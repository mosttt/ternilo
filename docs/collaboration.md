# 账号、机器与多人协作

使用同一个 Server 管理自己的机器，或在团队中分享工作区和会话。接入步骤见[远程访问](remote-access.md)，账号策略和管理员操作见[平台管理](platform-management.md)。

## Server 账号与多台电脑

本地网页和桌面直接使用当前电脑。远程使用统一 Server 时，先用用户名和密码登录；首次部署按终端显示的初始化链接创建实例所有者。开放注册的平台会显示“注册新账号”；需要审核时，提交申请后等待管理员通过，再用原来的账号登录。仅邀请的平台则使用管理员发来的账号邀请链接注册，无需重复审核。

在“用户设置 → 通用 → 账号”可以查看和复制自己的账号 ID。它与用户名分开显示，修改名称或切换空间不会改变这个 ID。

在“用户设置 → 我的机器”登记要连接的机器，再按页面给出的命令在那台机器上启动 `ternilo serve`。这个步骤也适用于自己的 VPS。连接后，已有工作区和会话会自动出现在工作台，本地原有记录仍可使用。同一账号可以管理多台机器；不同机器上的同名工作区和会话会分别显示。切换工作区后，插件、预设和非模型凭据的配置目标跟随当前执行位置；Server 的“我的模型”使用独立的来源选择，当前会话的模型在输入框下方选择。草稿按账号和会话保存。

撤销旧连接后，可以用新的电脑 ID 重新登记，并继续使用原来的本地数据目录。原有会话、历史和待执行任务仍可导入；当前连接无法核验的旧账号身份会显示为未知，正文、附件和任务内容保留，不会把旧消息归给新连接的所有者。原始本地记录不会因此改写。

实例所有者可在“平台管理 → 实例设置”切换访问模式：

| 模式 | 谁可以远程访问 |
|---|---|
| 单用户 | 仅实例所有者 |
| 多用户 | 已加入且具有相应资源权限的账号 |

保存模式前，页面会说明影响。切回单用户会暂停其他账号的访问；已有账号数据、私人电脑归属、历史和正在执行的任务保留。被暂停的页面会停止接收内容，不能继续提交任务；恢复多用户后，点击“重试访问”恢复访问。切换访问模式不会转移其他用户的电脑，也不改变数据库或启用托管执行。

每个账号默认拥有独立个人空间。多用户模式下，可以创建团队并邀请成员；平台注册邀请只创建账号，团队邀请才增加指定团队的成员身份。已有账号可以直接接受团队邀请。

团队邀请不会绕过账号注册要求。尚无账号时，先按平台当前方式注册并完成审核；登录后再接受团队邀请。管理员在“平台管理 → 账号”选择注册方式、筛选待审核申请并处理，详见[账号注册与团队邀请](platform-management.md#账号注册与团队邀请)。

“平台管理”负责全站账号、固定管理职责和 Worker；“空间管理”负责当前个人空间或团队的电脑、配额、用量和审计。平台职责不会自动获得他人的私人会话或电脑，团队管理员也不自动获得平台管理权。具体边界和操作见[账号、空间与平台管理](platform-management.md)。

部署者启用了 OIDC 时，登录页也提供组织账号登录。平台开放注册时，首次使用组织账号登录后需要填写平台用户名和联系邮箱；需要审核时先等待管理员通过。成员身份使用用户名和账号 ID，不另外设置昵称。用户名由本人注册时选择，组织账号的外部姓名变化不会改掉它。

注册时填写用户名、邮箱和密码，账号 ID 由系统自动生成。登录后可在“用户设置 → 通用 → 账号”查看自己的邮箱和账号 ID；邮箱不公开给共享会话的其他成员。邮箱目前作为联系信息保存，尚未进行验证码验证。

已有原生账号可以在“设置 → 通用 → 账号”点击“绑定 OIDC 登录”，完成身份提供方验证。绑定后两种登录方式使用同一个账号，原用户名、账号 ID、密码、机器和会话保留；不会按相同邮箱自动合并账号。已绑定到其他账号的身份不能再次绑定。

电脑凭据只在签发时显示，吊销后现有连接会断开；重新连接需要重新登记。退出登录会清除当前页面的登录状态和工作台选择，再次登录重新读取可访问资源。Server 的部署、数据库和可选 Worker 配置见[部署说明](deployment.md)，电脑连接步骤见[远程访问](remote-access.md)。

“用户设置 → 通用 → 账号”的登录会话区可逐项退出本站浏览器会话或退出其他会话；这不会撤销电脑、模型接入密钥或模型授权设备。通过组织账号登录时，外部组织的会话需要在其身份提供方管理，不能把撤销本站原生会话当作退出所有外部登录。

### 管理托管 Worker

在“平台管理 → Worker 与执行”查看托管执行状态。未启用时页面说明部署开启步骤；启用后，平台所有者、管理员或运维员可以登记专门运行托管任务的服务器。输入 Worker 名称，生成并保存页面给出的两条命令：首次配置只需 Server 地址和该 Worker 的独立凭据，以后执行启动命令即可。

列表区分待接入、在线、离线和已撤销，并显示最后联系时间。接入凭据只显示一次；撤销会阻止继续执行任务，运行中的结果需要检查，原磁盘文件保留。需要重新接入时登记一个新名称。

默认每台 Worker 使用独立存储。只有已经挂载同一个真实持久卷时，才展开高级选项并填写相同存储标识；这个标识不会自动复制文件。数据库和 Server 主密钥始终由 Server 保管，不需要填写到 Worker。详细部署与恢复要求见[托管执行说明](server-reference.md)。

## 与其他人共享工作

在多用户模式下，资源所有者打开团队内工作区或会话的“更多 → 共享…”，选择成员或权限组，搜索并保存权限。权限组由团队拥有者或管理员在“空间管理 → 权限组”管理。共享工作区包括其中的会话；只共享一个会话时，对方会在“未分组”中看到它，不会因此获得整个工作区或电脑的访问权。

个人空间的共享入口仅提供团队协作引导，不会直接给其他账号授权。当前没有把已有个人会话、工作区、项目或机器转入团队或转给另一所有者的操作。[项目共享继承](project-sharing.md)由工作区所有者主动开启，应用项目当前及后续规则。侧栏拖动改变显示顺序，分叉创建派生会话，均不等于转移归属或复制工作目录。

| 共享权限 | 可以做什么 |
|---|---|
| 查看内容 | 阅读共享会话、历史和其中的附件 |
| 发送任务 | 提交、编辑待处理消息，回答普通问题 |
| 停止任务 | 停止运行、删除排队任务，以及批准对应停止操作 |
| 调整会话设置 | 更换会话模型、调整会话配置和审阅计划 |

这些权限可以分别授予。只有发送权限时，计划批准按钮不可用；只有调整会话设置权限时，仍能审阅计划，但没有任务输入框。扩展的全局启停、撤销和其他电脑管理操作仍由所有者执行；共享不会开放机器的 Provider 配置、API Key 或全局插件安装权限。

多人查看同一会话时，各自保留输入草稿，看到的模型输出和工具结果来自同一份事件记录，重连后会补齐。有发送权限的人可以提交消息排队，同一会话每次只执行一轮；上一轮结束后，等待的普通消息作为多条独立用户消息进入下一轮。手动发送整个队列还需要停止权限；运行中会先等待旧执行停止，不会同时运行两轮。当前没有按人独占输入框的控制权锁。

消息和待处理项旁显示提交者：自己的消息显示“你”，其他人显示用户名。点击头像或用户名可以查看完整用户名、账号 ID，并复制 ID。别人编辑或代为发送已有排队消息时，仍保留最初提交者；新写的补充消息记录为这次发送的人。同批次也不合并消息或身份，不再用输入框上方的“当前任务”重复正文。分叉历史保留原作者，不会改成分叉发起者。没有作者记录，或当前电脑连接无法核验作者的旧消息，会显示“身份未记录”；正文和附件仍可查看。本机输入和自动任务也不会被标成某个平台账号。

本机 Ternilo、CLI 和 Server 接入电脑的目录协调按可信输入作者区分：同一用户的多个会话和普通历史分叉可以在同一目录并行；不同用户对同一目录或父子目录的任务仍会等待，不重叠的目录可以并行。电脑所有者的 Server 输入可与该电脑上的本地输入共用目录，但不同账号不会因此合并身份。等待时可以继续查看、编辑草稿或停止这次任务；子 Agent 和定时任务沿用原始任务作者。同一会话的队列仍串行执行。

后台任务、持久终端和 MCP/LSP 可能在回答完成后继续保留目录占用，使其他用户的重叠目录任务等待；可回到对应会话结束任务、关闭终端，或在“更多 → 后台服务”中停止服务。取消一个会话不会释放另一个仍在运行的会话或后台进程的占用。托管 Worker 仍按执行家族协调，不套用上述同用户并行规则；需要确认受控执行实际退出才可释放或恢复占用，不能仅凭断线或租约超时移交目录。外部程序不参与这一协调，共享也不会自动创建每人的独立工作副本。多人或父子 Agent 处理同一批文件时，仍应约定各自修改的范围。

接入电脑的共享会话支持现有的设备模型协作；具有“调整会话设置”权限的成员还可以明确选择自己的账号 Provider 或平台授权模型供该会话使用。新增账号模型必须由该 Provider 的持有人授权；其他成员只能沿用已授权的绑定，不能借此枚举或管理他人的 Provider。调用时继续核验原输入作者的发送权限、模型持有人的会话配置权限，以及所选模型授权。平台授权供其他协作者使用时，还必须允许资源共享。

托管 Worker 会话的模型仍归执行资源所有者：协作者可使用所有者已经绑定的账号模型，或允许资源共享的平台授权；具有配置权限也不能新增另一账号 Provider 绑定，只能在已有账号绑定范围内调整。把协作者自己的模型或额度委托给他人的托管会话尚未提供，不能把 Node 已有的授权方式直接视为 Cloud 已实现。两种执行位置都不会把模型 Key 交给协作者，选择共享会话模型也不会改写所有者的新会话默认值。

成员可以新上传附件，也可以读取共享会话中已有的附件；知道另一私有会话的附件摘要，不会获得其内容。有发送权限的成员可以编辑共享待处理消息或重新生成共享历史。待处理消息使用开始编辑时的版本提交；如果他人已修改，保存会提示冲突并保留你的草稿，不静默覆盖对方内容。可明确加载最新内容后重新编辑，或取消；消息已执行或删除时也不会把旧草稿写回队列。切换账号或会话会清理原编辑状态。这不是独占编辑锁，与 Agent Team 任务板的版本检测分别生效。

协作者可以从“更多 → 查看权限…”了解当前有效权限及其来源。单独授权、权限组、工作区共享和项目继承可以同时生效；撤销其中一个来源不会清除其他来源的权限。团队只读成员仍只能查看，组授权不能放宽这个限制。

所有者可以随时调整或撤销共享。失去全部查看权限后，对方的列表和实时内容会移除，后续请求会被拒绝。已经接受的任务不会因此自动取消；需要停止时，仍须通过停止操作处理。

真实工作目录侧栏与会话文件库的权限不同：会话查看权限允许读取对应历史与附件／产物，不自动开放整棵目录；侧栏的目录列表、文件内容和托管文件命令结果要求工作区查看权限。“在应用中打开”只在本机 Ternilo 界面提供，Server 对所有账号隐藏入口并拒绝启动请求，不随共享权限授予。文件侧栏只读且不取得目录执行占用，标签和展开状态为各浏览器账号私有；详见[文件指南](files.md)。

分叉共享会话时，新会话仍归原所有者，只有发起者获得派生权限，不会把原会话的整个共享名单复制过去。通过组获得的派生权限继续依赖原授权和组员身份：移出组或撤销原组共享后失效，减少原权限也会限制分叉；之后重新加入组不会恢复已经撤销的派生权限。原授权增加权限时，旧分叉也不会自动提权。若共享的是整个工作区，组员仍可按工作区授权查看其中的新分叉。

单独授予某位成员的权限按原有行为保留在分叉中。所有者也可以在子会话的共享列表中编辑派生成员并保存，将该子会话的派生权限改为明确的单独授权；页面会先说明这一变化。此后撤销原组共享不再撤销这份单独授权。

项目继承通过固定工作区动态生效，不复制成分叉的个人授权。关闭继承或撤销项目规则后，派生访问同时消失；重新加入项目权限组则按当前工作区规则重新获得访问，独立的直接授权仍保留。
