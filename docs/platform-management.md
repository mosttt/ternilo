# 账号、空间与平台管理

登录 Server 后，每个账号都有自己的个人空间。个人空间保存自己的项目、机器和配置；加入团队不会把这些资源自动搬过去。需要协作时，先创建或选择团队，再在该团队中登记机器、组织项目并共享工作区或会话。

账号使用用户名和自动生成的账号 ID 辨认身份，不另设昵称。注册时填写用户名、邮箱和密码；账号 ID 无需填写，可在“用户设置 → 通用 → 账号”查看、复制。邮箱作为联系信息，只对本人和有账号查看权限的管理者显示，不出现在共享会话的作者信息中。当前不提供邮箱验证码验证，也不支持邮箱登录或按邮箱自动合并账号。

## 找到正确入口

日常使用从普通工作台开始。Server 侧栏的“用户设置”用于个人偏好、账号以及当前目标的插件、预设和非模型凭据配置；“我的模型”统一管理账号自有、所选电脑和平台授权模型，以及模型接入 Key、授权设备和用量。自己的电脑或 VPS 从“我的机器”接入。本地直连网页和桌面仍使用“设置 → 模型”，不套用 Server 的页面导航。

具有平台职责的账号另外看到“平台管理”。它管理平台注册账号、平台模型与授权、托管 Worker、平台用量和实例配置，不包含个人设置或个人模型 Key。Worker 只是平台管理的一部分。个人自用时同一账号同时是使用者和管理者，入口仍然分开。

团队成员、团队权限组和当前空间的资源管理放在空间切换区域旁的“空间管理”。从这些页面都可以明确返回工作台；用户设置使用 `/settings` 和 `/settings/{section}`，平台管理使用 `/admin/*`。

## 个人空间与团队

工作台侧栏的“切换空间”用于选择个人空间或团队。个人空间只属于本人，不能添加成员或更换拥有者。多用户模式下，可以点击“创建团队”，填写名称和标识；创建人是团队拥有者。

空间切换区域内的管理按钮打开独立的“空间管理”页面，始终显示当前空间。具有相应管理权限时，个人空间提供项目、电脑、配额、用量和审计；团队另外提供成员、邀请和权限组管理。项目页支持创建、改名、删除空项目、查看当前可见工作区及返回工作台。这里的拥有者、管理员、成员和只读成员都是该空间内的角色，不是平台管理身份。

改名只改变项目显示名称，不移动文件或改变已有授权。删除需要确认，且项目必须没有工作区、电脑登记、执行器、凭据或模型请求历史等关联记录；列表中没有可见工作区并不代表可以删除。个人默认项目及空间最后一个项目不能删除。删除不递归清理资源，不删除磁盘文件，也不绕过不可见资源的保护。项目支持由工作区所有者主动启用的[共享继承](project-sharing.md)；迁移和交接仍未提供。

团队成员不会因为加入团队或管理项目而自动获得他人的工作区和会话。资源所有者可以在“共享…”中直接授权，也可以先查看项目规则，再主动开启工作区的项目继承。当前没有把已有个人资源转入团队、转给其他所有者或在项目间迁移工作区的一键操作；创建团队、共享和侧栏拖动排序都不会迁移资源或项目文件。共享权限和文件归属见[协作指南](collaboration.md#与其他人共享工作)。

## 用权限组管理团队协作

团队拥有者或管理员可以在“空间管理 → 权限组”创建组，填写名称和说明，再从团队成员中添加组员。例如，建立“代码审阅”组后，资源所有者可以在会话的“共享…”中选择这个组，统一授予查看或提交任务的权限。新建组默认没有资源权限；资源所有者向组共享后，现有和后来加入的组员都按组授权获得权限。

成员、权限组、组员与共享候选都由 Server 搜索和分页读取。一个组只能包含本团队的成员，不支持嵌套组。平台管理身份不会自动赋予团队组管理权，团队组管理权也不代替资源所有者的分享决定。

同一人可能同时通过单独授权、多个组、工作区共享或项目继承获得权限，实际可用操作取这些授权的合集，再受团队只读身份限制。“查看权限…”会显示有效权限和来源。删除一个来源后，如果还有其他授权，对方仍能继续访问。

移出组、移出团队、删除组或撤销组共享后，对应权限会失效，在线页面会更新列表并停止接收已失去访问权的内容。已经接受的任务继续遵循原队列和停止规则；需要停止时，由仍有停止权限的人操作。

这里的权限组用于团队内的工作区和会话协作。“平台管理 → 模型服务”中的平台模型组面向全平台账号，只授予模型与额度，不共享私人项目。不能用团队协作权限直接调用独立模型服务。

## 账号注册与团队邀请

OAuth 2.0／OIDC 登录和 Cloudflare Turnstile 由实例所有者在“平台管理 → 实例设置”配置，不放在个人设置或注册策略中。配置、密钥保留规则和故障恢复见[Server 登录与人机验证](server-authentication.md)。

在“平台管理 → 账号 → 注册设置”选择账号准入方式。默认仅邀请；开放注册时，登录页提供“注册新账号”，还可以选择新账号是否需要管理员审核。实例所有者和平台管理员可以修改这些设置，审计员只读。

| 注册方式 | 用户怎么进入 | 管理者需要做什么 |
|---|---|---|
| 开放注册，不审核 | 自行注册后直接登录 | 按需要另行授予模型或执行权限 |
| 开放注册，需要审核 | 提交申请，等待审核 | 在账号列表筛选“待审核”，通过或拒绝申请 |
| 仅邀请注册 | 使用管理员的邀请链接注册并登录 | 在账号页生成邀请；邀请已经代表批准，无需再次审核 |

开放注册时不提供账号邀请入口，后端也拒绝创建和兑换账号邀请。切换方式只改变后续准入，不会自动批准已有申请；已通过的账号仍可登录。仅邀请模式下不能直接注册。单用户模式下继续只有实例所有者可使用，保留的注册设置在多用户模式下生效。

待审核账号不能登录工作台、领取模型接入 Key 或使用执行服务。通过审核后用原来的用户名和密码登录，账号 ID 保持不变；拒绝申请后登录页会说明结果。管理员可以筛选“未通过”，重新选择“通过审核”，用户随后用原账号登录，无需重新注册。审核与设置修改保留审计记录；如果其他管理员已更新状态，页面会刷新后要求重新确认。

“平台管理 → 账号 → 邀请注册账号”只在仅邀请模式下出现。被邀请者注册后获得自己的个人空间，不会加入邀请者的个人空间。

“空间管理 → 成员 → 邀请加入团队”生成指定团队的邀请，并选择团队角色。已有账号的人登录后接受邀请，继续保留原有个人空间与其他团队成员身份。没有账号的人先按平台当前方式注册，需要审核时先等待通过，再接受团队邀请。团队邀请不能代替平台注册邀请或审核。

邀请链接只显示一次，有有效期且只能接受一次。链接创建者失去对应邀请权限后，尚未使用的邀请不能继续授予权限。

OIDC 登录也遵守账号准入规则：开放注册时，首次组织登录后填写一个未被占用的平台用户名和联系邮箱，确认后创建账号；需要审核时先进入待审核状态。仅邀请时新用户应先受邀创建账号，再绑定 OIDC。已有绑定账号可以继续组织登录，外部组织姓名或邮箱变化不会改掉平台用户名和账号 ID。模型、机器和会话的使用权限继续分别授权。

## 封禁和移除账号

在“平台管理 → 账号”按用户名、邮箱或账号 ID 搜索，从对应账号的操作菜单中处理：

- “封禁账号”暂停正常账号的访问；解除封禁后可以重新登录，原账号 ID 和历史记录保留。
- “注销账号”永久移除该账号的使用资格，不能恢复。历史会话、项目文件、用量和审计归属保留，不会自动删除项目文件。已注销账号仍可通过状态筛选查到；其联系邮箱可用于注册新的账号，新账号会获得新的 ID。

这些操作仅平台所有者和平台管理员可用，不能作用于实例所有者或自己。每次操作前页面会说明影响并要求确认。封禁或注销会吊销本站签发的登录凭据、模型接入 Key 和个人机器接入凭据；解封后需重新登录、生成 Key 或接入机器，旧凭据不会恢复。实际已经发生的用量仍计入原账号；账号状态操作不等于立即终止机器上所有已启动的进程。

## 平台管理职责

“平台管理”与日常工作台使用同一登录状态，拥有独立导航和页面地址：

- `/admin/accounts`：账号搜索、职责及状态筛选、分页查看、注册设置、审核、封禁、注销与平台注册邀请。
- `/admin/instance`：查看实例模式；由所有者切换单／多用户并配置 OAuth 2.0／OIDC、Turnstile。
- `/admin/workers`：登记和撤销 Worker、查看状态、暂停或恢复新任务领取。
- `/admin/models`：接入上游、发布模型、管理平台模型组、授权与用量。

当前职责与可用操作如下：

| 平台职责 | 可用操作 |
|---|---|
| 平台所有者 | 全部已实现的管理操作；任命其他账号的职责、切换访问模式 |
| 平台管理员 | 查看账号、设置注册方式、审核申请、邀请注册、封禁及注销账号、管理模型供应和授权、Worker 与执行维护；不能任命职责或切换模式 |
| 模型／执行运维员 | 维护上游和发布模型、查看模型用量，管理 Worker 与执行维护；不能授予模型权限或枚举全部账号 |
| 用量审计员 | 只读查看账号、模型服务用量、Worker 和实例状态 |
| 使用者 | 使用获授权的模型和工作台资源，管理自己的模型 Key 及自己负责的空间 |

这些是平台管理权限，不会授予私人项目、会话正文、机器文件或模型 Key 的读取权。团队拥有者也不会因此成为平台管理员。单用户模式下，其他账号仍不能通过管理 API 继续访问。

所有者修改账号职责时，需要确认具体账号和新职责。权限在下一次请求时按当前记录检查；两个页面同时修改时，过期页面必须重新读取并确认。账号列表每次从 Server 读取一页，不把所有用户加载到浏览器后再分页。

独立模型管理、平台模型组、授权额度和受限接入密钥已提供。普通用户从“我的模型”进入 `/models`，在自己的客户端中使用获授权模型，无需 Worker，具体步骤见[模型接入指南](model-service.md)。

托管任务使用独立模型授权和调用账本；账号封禁和注销会阻止后续模型及执行访问，通用执行环境授权尚未提供。当前空间的执行用量与审计仍通过该空间的管理权限访问；现有统计是 token 和任务预留，不是金额账单。

## Worker 接入与部署设置

“Worker 与执行”始终对具有查看权限的管理者开放。尚未开启托管执行时，页面显示部署开启步骤；开启后，具有管理权限的人可以生成 Worker 专属凭据和启动命令。普通使用者不领取 Worker 管理凭据。

数据库、监听地址、存储目录与托管执行开关属于部署配置；访问模式、账号职责、团队成员、邀请和 Worker 登记在软件中管理。数据库使用 SQLite 或 PostgreSQL，都提供上述功能。更多部署要求见[部署说明](deployment.md)和[Worker 部署](worker.md)。
