# Extension packages

External extensions use one versioned package contract and registry. Rhai and WASM Component are alternative runtimes under that contract, not separate inventories or trust systems. Each package version selects exactly one runtime and supplies its corresponding payload.

## Manifest and trust

The current manifest uses `schema_version: 1` and signing domain `TERNILO-EXTENSION-PACKAGE-V1\0`. The signature covers package/version, exact source, publisher key ID, payload digest, runtime, configuration schema, contributions, requested capabilities and resource limits. Rhai payloads are UTF-8 source; WASM uses the declared component world `ternilo:extension/runtime@1.0.0`.

Canonical manifest encoding sorts object keys recursively, preserves array order and Unicode spelling, and normalizes floating negative zero. This keeps signatures stable through supported database JSON storage without treating reordered arrays or changed text as equivalent.

All six contribution arrays must be present: `tools`, `prompt_sections`, `skills`, `hooks`, `commands` and `providers`. Individual arrays may be empty, but the package must contribute something. A static-only package still declares a runtime and passes payload/signature validation.

## Contributions

Tools declare input/output schemas, effects and presentation. Their raw runtime output is validated before canonical ToolOutput rendering. Static prompts and skills contribute signed content without executing the payload. Hooks enter the shared hook service, with physical execution metadata generated by the host. Commands map fixed/suffix arguments to a contributed tool and follow the same validation/approval chain. Provider templates copy signed provider settings into a user-chosen ID/credential reference; they do not execute the extension runtime.

Activation registers prompts, skills, hooks, tools and commands as one lifecycle; failure rolls back registrations in reverse order. Disable, revoke, uninstall, unmount and session teardown remove active contributions without rewriting historical events.

Requested host capabilities are requests, not grants. Current capability APIs include bounded logging and workspace-relative UTF-8 reads. The grant must also be allowed by host policy. Neither runtime directly acquires arbitrary network, environment, credentials or process execution through the package contract.

## Build, sign and install

Use the runnable [Rhai example](../../examples/rhai-echo-extension/README.md), and inspect the `examples/` directory for the matching WASM example and manifests. `ternilo-plugin --help` lists package build, signing and offline verification commands. Keep publisher private keys private; distribute the signed bundle and public trust information.

Installation, publisher trust, enabling and profile mounting are separate decisions. Version identity survives uninstall/reinstall; permanent revocation must not be bypassed by reinstalling the same identity. Runtime extension management follows the same registry authorization. See [plugins](extensions.md), [program roles](binaries.md) and [security](security.md).
