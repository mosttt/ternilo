# Ternilo v0.2.4

This release fixes the Rustls startup panic during WSS connections to Server and expands OAuth2/OIDC login and registration management.

- Configure multiple named OIDC providers with independent enable switches and encrypted credentials. Sign-in and native-account linking show provider names. Code exchange, PKCE, refresh and MFA bind to the selected provider.
- OAuth2-only registration applies to both open signup and password-based invitation registration. OAuth invitations survive redirects and are consumed atomically when creating an account. Existing password sign-in remains available.
- Account statuses appear beside names with text, color and bordered badges, including active, pending and banned states, in light/dark themes and mobile layouts.
- Client, Server, Worker and Desktop explicitly select the Rustls crypto provider at startup. Multiple compiled backends no longer cause a panic; certificate and hostname validation remain enabled.
- GHCR `latest` points to the exact AMD64/ARM64 index of the latest published stable release. Prereleases never replace it. Deployment still pins versions by default, with both choices documented.

Authentication management and public login metadata use the `oidc_providers` array. Code exchange, refresh and MFA requests include `provider_id`. The previous single-provider API is not retained. OAuth2 providers still need the supported OIDC identity contract or a dedicated integration.

Client and Server artifacts cover Linux x86_64/ARM64, Windows x86_64/ARM64 and macOS Intel/Apple Silicon. The Server image is `ghcr.io/mosttt/ternilo-server:0.2.4`. Desktop publisher signing, notarization and automatic updates remain disabled.
