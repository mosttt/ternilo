# Ternilo v0.2.27

This patch improves model transport, tool failure handling and read-only verification, with Chinese, English and Korean UI guidance.

- Send model gateway keepalives every 15 seconds during silent reasoning. Correlate executor disconnects, Server shutdown and authorization changes across requests and attempts, with direct navigation from error details to usage records. Unknown usage is not zero; uncertain requests are not replayed automatically.
- Preserve optional OpenAI Responses tool arguments instead of allowing automatic strict normalization.
- Create missing workspace parent directories for `write_file`; retain zero-byte file versions for preview, download and recovery.
- Supplement history search with Chinese, Korean and mixed-language substrings while retaining full-text relevance, authorization scope and filters.
- Configure named checks in `shell-tool` so read-only reviewers can verify results through `run_check`. Commands are fixed by settings, the workspace stays read-only, and ordinary Shell, terminal, job and file-write access remains denied.
- Give restricted processes private writable temporary/cache directories held until process-tree cleanup. Canonical macOS paths prevent accidental Python/xcrun cache-write denials.
- Add Rhai `try_tool` with `ok / result / error`, preserving exit status, stdout, stderr and timeout state, including output captured before timeout. Existing calls still throw, with concise Git failure messages instead of serialized JSON exceptions.
- Default code maps to symbols, imports and candidate calls within selected files; use `detail: "full"` for all call locations. Rhai parse errors add bounded source excerpts and backtick guidance.

After accepted submission, closing the Server browser does not stop computer-side execution. Reopen it to view the result; the computer, background service and selected model connection must remain available.

## Upgrade

Update clients normally, then pull `ghcr.io/mosttt/ternilo-server:0.2.27` and recreate Server. Executor protocol 49, data epoch 1 and update-signature policy remain unchanged. Windows clients require the matching `ternilo-sandbox-windows.exe`, included in official complete packages. See [named verification checks](https://github.com/mosttt/ternilo/blob/v0.2.27/docs/en/agents.md#run-checks-from-a-read-only-review).
