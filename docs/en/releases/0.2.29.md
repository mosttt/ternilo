# Ternilo v0.2.29

Web search and page reading now share the Provider editor. Save one account configuration and let the task computer use the selected Provider's web settings. Chinese, English and Korean interfaces are updated together.

- Open “My models → Account-owned → Edit → Custom settings → Web access.” For standalone Ternilo, use “Settings → Models.” New sessions follow the existing default model; no separate search default is required.
- Choose DeepSeek, Brave, Tavily or SearXNG for computer-side search, and direct access or DeepSeek Markdown for page reading. Enter a separate web API key in the same editor. DeepSeek search and reading can share that web credential; the model key is never reused automatically.
- When the model comes from an account or another computer, standalone web tools still run on the task computer. Web credentials are delivered on demand only to the owner's authorized computers, without entering their credential stores or session histories.
- Enable provider-hosted search for DeepSeek Responses `deepseek-v4-pro`, or hosted search and reading for Claude. These tools run upstream and are selected separately from computer-side services.
- Keep “Use session plugins” or disable either capability. Explicit capability restrictions and host policy remain effective; an inactive alternative does not disable an already-enabled implementation. Both plugin settings views show Provider-managed effective values.
- New dialogue tasks read changed settings, and switching Providers switches web tools. Configuration changes, missing credentials and insufficient balance have distinct guidance. Offline model sources do not block local non-web commands.
- Update the Markdown parser to address RUSTSEC-2026-0414.

See [web access](https://github.com/mosttt/ternilo/blob/v0.2.29/docs/en/web-access.md) for configuration and supported paths. Platform Providers do not export computer web credentials; managed Worker sessions continue using standalone plugins or provider-hosted tools.

## Upgrade

**Executor protocol changes from 49 to 50. Upgrade Server and connected computers together.** Wait for active tasks to finish, stop the relevant services, keep the existing instance data, update the complete client packages, then pull `ghcr.io/mosttt/ternilo-server:0.2.29` and recreate Server. Restart using the existing service configuration. A new Server cannot remotely update a computer still using protocol 49.

The signed update manifest requires client 0.2.29 or later and Server `>=0.2.29, <0.3.0`. After this initial coordinated upgrade, subsequent releases within the same protocol and data epoch can use remote updates again. Data epoch remains 1. Windows requires the matching `ternilo-sandbox-windows.exe` from the complete package.

Existing Worker deployments must update Server/Worker together and set `catalog_revision` to `ternilo-cloud-v5` in their private Worker policy. Deployments without Worker need no policy change. Desktop installers remain unsigned/unnotarized, with automatic desktop updates disabled.
