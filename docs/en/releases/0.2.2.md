# Ternilo v0.2.2

Server binaries and Docker can now start directly with `serve`. Use the Initialization Key from startup logs to choose a database and create the administrator in the browser. Setup saves private configuration; restarts preserve the existing account and database.

- Setup, login and the workbench follow the browser’s preferred Chinese/English language; saved manual choices override it.
- Web setup supports default SQLite and PostgreSQL runtime plus optional schema-owner connections. The Key is checked before database access and expires after setup. Uninitialized restarts log a fresh Key.
- Terminal setup uses `ternilo-server setup`, with hidden prompts or one-time automation options. Daily `serve` does not accept administrator credentials or recreate/reset accounts on restart.
- Chinese and English deployment guides cover native binaries, external and included PostgreSQL, HTTPS gateways and temporary SSH access. Release includes `compose.server.postgres.yml` and `postgres-init.sql`.
- Precedence is CLI > environment > saved configuration > defaults. Database settings saved in web setup do not require duplicate environment variables. The public URL can be configured in the browser.
- Older session-history reads seek to byte boundaries rather than scanning the complete event file for every page.

Client and Server artifacts cover Linux x86_64/ARM64, Windows x86_64/ARM64 and macOS Intel/Apple Silicon. Windows uses ZIP; other CLI archives use tar.gz, alongside Desktop installers. `ghcr.io/mosttt/ternilo-server:0.2.2` provides AMD64/ARM64 images. Desktop publisher signing, notarization and automatic updates remain disabled.
