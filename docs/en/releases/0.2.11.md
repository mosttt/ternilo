# Ternilo v0.2.11

Workspaces can now move to another management project within the same space. The current manager chooses “Move to project…” from the workspace menu, selects a destination and confirms. Desktop and mobile share the workflow in Chinese, English and Korean.

- Retain workspace and session identifiers, history, files, computer bindings, managers, the original execution project and usage attribution. File and execution identity migration and moving personal resources into teams remain separate future stages.
- End access inherited from the previous project and disable target project sharing by default. Target rules apply only after explicit opt-in. Direct workspace and session grants remain.
- Check current management permission, space boundaries, destination name conflicts and a monotonic move revision. Stale confirmations cannot overwrite a later move, including round trips.
- Servers refresh permissions, resource lists and session subscriptions after commit. Instances sharing a database must use the same version before using project moves.

The release includes six platform targets, desktop installers and the AMD64/ARM64 Server image. Desktop signing, notarization and production updates still await publisher materials.
