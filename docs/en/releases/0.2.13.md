# Ternilo v0.2.13

This release adds role models, Independent/Assisted/Parallel collaboration, context optimizations and project delivery tools. It also fixes conversation jumps while loading older history.

- Configure separate models and reasoning effort for Investigator, Implementer and Reviewer. Assisted defaults to four concurrent children and Parallel to eight, with configurable limits of 1–32. Workflows batch tasks using the same limit. Host permissions, model authorization, quotas and cancellation remain authoritative.
- Load tool definitions on demand, preserve structured context handoffs, budget tool output, optionally cache file reads with change detection, and inspect AST code maps for supported source languages.
- Team Usage groups coordinator and child tokens by the actual model and optionally estimates costs using prices stored in the browser. Cache/reasoning categories are not double-counted; missing usage and prices remain unknown.
- Optional Anthropic prompt prefix caching and reasoning effort observation are available. Observation does not change model parameters.
- Keep project memory separate from history search. Commit explicit Git paths and use GitHub tools for PR review, draft creation and merging at a reviewed head SHA. Current isolated Workers are offline; use a local or connected computer for GitHub operations.
- Render Markdown/static HTML in an actual browser and persist screenshots for review. Source changes require a new render; detected layout/resource problems prevent passing a review. Provide Chrome/Chromium inside the execution environment and use an image-capable model.
- Skill frontmatter uses a maintained YAML parser while preserving multiline text, field aliases and existing boolean forms.
- History backfill and delayed usage statistics preserve the bottom or the current reading paragraph. Large conversation windows retain their latest turns. Brief metadata reads no longer make idle configuration saves report a running task.

The interface supports Chinese, English, Korean and narrow mobile screens. Update CLI/Desktop, Server and the existing Worker together. `ternilo-work` remains a framework reservation; separate resource migration work is not included. Desktop signing, notarization and production auto-update remain dependent on publisher information.
