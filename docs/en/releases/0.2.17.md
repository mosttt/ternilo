# Ternilo v0.2.17

This patch fixes runtime feedback, session controls and file presentation.

- Discard file-backed SQLite connections with stale transaction depth after an engine rollback, preventing repeated transaction, readiness and request-recovery failures.
- Reject permission changes promptly while a turn is active instead of blocking history reads. Permissions remain editable when idle; full access still requires confirmation.
- Fix child-session navigation for Server-connected computers and show subagent startup, activity and direct navigation in the parent conversation.
- Show unconfirmed run status while the computer or live connection is offline, without continuing stale thinking timers. Reconnection restores current state.
- Preview and enlarge workspace images in chat through the existing authorized file interface, including Node-redacted paths.
- Remove completed todo lists from the composer dock while retaining history, and clarify progress-update expectations in the tool description.
- Group generated file records by workspace path, with separate previews and downloads for older versions.
- Show the actual folder path and provide parent-folder navigation in the directory picker.
- Explain command approvals through action, purpose and impact, with the full command in an expandable disclosure. Pending cards and history use the same presentation; older requests identify missing explanations.

The affected interfaces support Chinese, English, Korean and narrow mobile screens.

## Upgrade

Update both Server and connected computers' `ternilo`. Pull `ghcr.io/mosttt/ternilo-server:0.2.17` and recreate the Server container; restarting an old container does not change its image. Stop local Ternilo, replace the program or update through the original installation method, keep the existing data directory and configuration, then restart.

This patch does not require a resource-migration activation command. Resource migration and recovery remain on a separate development branch; Work is excluded. Desktop installers remain unsigned and unnotarized, and production automatic updates are not enabled.
