# Ternilo v0.2.20 (unpublished candidate)

Short-screen sidebar acceptance blocked this candidate before public release. The fix ships in [v0.2.21](0.2.21.md); the original tag is retained.

This release adds Server-initiated client updates and a sidebar computer dropdown for one or all computers. Related UI is available in Chinese, English and Korean.

- Update individual or multiple connected computers from **User Settings → My machines**. Server downloads and caches official release packages; each computer independently verifies the signature before installation. The production signing private key is used only for releases, never deployed to Server or clients.
- The computer owner explicitly enables updates locally. Installation waits for conversations, subtasks, queued work and background jobs to finish. Idle persistent MCP/LSP services do not block updates.
- Restart directly launched clients, persistent systemd services or Supervisor programs. Roll back if the new program fails to start, or recover an interrupted installation locally. Configuration, conversations, computer identity and credentials are retained. Windows currently supports direct restart.
- In the sidebar's computer view, select one computer or all computers. Selection is retained per account and space, with in-page scroll positions preserved. Search still covers the visible scope, and changing the filter does not switch the active conversation.
- Update certificate-verification and frontend build dependencies to address known security issues.

## Upgrade Server and connected clients together the first time

This release uses Executor protocol 49 and does not accept older protocol connections. Back up the Server database, configuration and client data, then stop the old services and upgrade Server and connected clients to 0.2.20 within the same maintenance window.

Pull `ghcr.io/mosttt/ternilo-server:0.2.20` and recreate the Server container. Update clients using their original installation method or replace the complete client package. Keep the existing data directories and configuration; on Windows, retain the sandbox helper beside the main executable. Older clients cannot perform this first upgrade remotely.

After upgrading, the computer owner runs `ternilo updates enable --help` locally, selects the actual restart method and restarts the client once. Later compatible releases within the same protocol and data epoch can be installed from Server. See the [client update guide](https://github.com/mosttt/ternilo/blob/v0.2.20/docs/en/client-updates.md) for enablement, status and recovery commands.

Remote updates apply to official browser/CLI packages, not containers or desktop installers. Desktop installers remain unsigned/not notarized, and desktop automatic updates remain disabled. Resource migration and Work are excluded from this release.
