# Ternilo v0.2.25

This patch fixes remote client update readiness and status messages, with Chinese, English and Korean UI support.

- Replace the roughly 30-second local startup check with a 120-second elapsed-time window, allowing slower computers to become ready before rollback. Version verification and timeout recovery remain enforced.
- Report execution records whose completion cannot be confirmed after a restart instead of continuing to wait for those tasks to finish. Records are not deleted automatically, and tasks are not forcibly interrupted.
- Verify that the configured service manager owns the current process before the client downloads the package, and check again before installation. Use Supervisor's full process name, such as `ternilo:ternilo_00`.
- When the new version is already running but the previous automatic update could not confirm completion, state that no further update is needed and retain diagnostics. Improve startup, reconnection and rollback messages.

## Upgrade

Pull `ghcr.io/mosttt/ternilo-server:0.2.25` and recreate Server using your existing deployment method. Executor protocol 49 and data epoch 1 remain unchanged; v0.2.23 and v0.2.24 clients can remain connected.

**Manually install v0.2.25 on computers that have encountered slow-start rollback or an unresolved execution-record blocker, keeping their data directories and configuration.** The currently installed client performs the update. Updating Server alone cannot replace the old client's 30-second readiness logic. Subsequent remote updates use the new waiting and diagnostic behavior after this patch is installed.

Supervisor's `--service` must exactly match the full name shown by `supervisorctl status`. The computer administrator must check actual processes before resolving unknown execution records. Do not delete all runtime records or lock files to force an update. See the [client update guide](https://github.com/mosttt/ternilo/blob/v0.2.25/docs/en/client-updates.md).

For Desktop, install the new package for your platform. Desktop installers remain unsigned/unnotarized, and desktop automatic updates remain disabled.
