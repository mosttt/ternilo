# Ternilo v0.2.31

## Subagents and session interactions

Fixes new Server subagent sessions reusing snapshots taken before their creation, which could reject web-access authorization. Duplicate answers to the same approval are coalesced. Stale activity no longer shows failed or finished subagents as running; a later restart still appears normally.

Clicking an Agent preset card now opens its details without changing the default. After a session starts, its preset is locked consistently in settings and the session toolbar. Viewing, editing and setting the default for new sessions remain available.

## Replies, errors and settings feedback

Streaming and final replies share the same Markdown layout, reducing reading-position jumps at completion while preserving question history and trajectory layout. Subagent approvals explain the task, permission limits and model usage in Chinese, English and Korean. Brief post-task cleanup no longer immediately rejects plugin saves; active tasks remain protected.

Responses image-complexity rejections display an actionable reason and are not retried with the same invalid parameters, even when wrapped in HTTP 502. Ternilo does not add image `complexity`; these rejections require correcting upstream or proxy image configuration, not conversation reasoning settings.

## Update recovery and dependency fixes

Failures saving installation markers, configuration or progress now enter safe recovery. After the original program is restored and verified, progress-write failures cannot prevent its restart. Rollback and local recovery follow the same rule. Failed restoration or version checks retain the protective marker rather than starting an incomplete installation.

Updates Wasmtime to 48.0.8 and pulldown-cmark to 0.13.6 to address dependency security advisories.

## Upgrade

Update Server to `ghcr.io/mosttt/ternilo-server:0.2.31` and update complete client bundles. Version 0.2.30 clients with remote updates enabled can upgrade through Server; earlier versions still require manual installation. Keep instance data, computer registrations and service configuration. The maintenance baseline remains v0.2.30; maintenance protocol, execution protocol and data epoch are unchanged.

See [client updates](https://github.com/mosttt/ternilo/blob/v0.2.31/docs/en/client-updates.md) and [release workflow](https://github.com/mosttt/ternilo/blob/v0.2.31/docs/en/ci-release.md). Desktop installers remain unsigned and automatic updates remain disabled.
