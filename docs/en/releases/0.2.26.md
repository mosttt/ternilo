# Ternilo v0.2.26

This patch adds remote client updates for macOS user LaunchAgents, with Chinese, English and Korean guidance.

- Configure `--restart launch-agent` using the actual plist Label, file location and login domain. Defaults use the current user's LaunchAgents directory and GUI domain.
- Check the plist and running service PID before downloading and again before installation. Unload the agent during file replacement so KeepAlive cannot restart the old program, then reload and start it from the original plist after installation or rollback.
- Retain signature verification, idle checks, data and configuration, the 120-second readiness window and local recovery. Existing direct, systemd and Supervisor usage is unchanged.

## Upgrade

Before first enabling updates for a LaunchAgent, manually install the v0.2.26 client containing this adapter. Then run as the account that runs the agent:

```sh
ternilo updates enable --restart launch-agent --service com.ternilo.client
```

Replace `com.ternilo.client` with the actual plist `Label`. Specify the same `--data-dir` for a custom instance directory. See the [client update guide](https://github.com/mosttt/ternilo/blob/v0.2.26/docs/en/client-updates.md) for another plist location or a non-GUI domain. Launch the service through the stable `bin/ternilo` entry point, restart once using its normal manager, then refresh in Server. Stay logged in during installation in a GUI domain. This adapter does not update system LaunchDaemons or Desktop installers.

Pull `ghcr.io/mosttt/ternilo-server:0.2.26` and recreate Server using your existing deployment method. Executor protocol 49 and data epoch 1 remain unchanged; a fleet-wide coordinated shutdown is not required. Other compatible clients with remote updates enabled can continue using their existing update flow.
