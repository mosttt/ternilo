# Ternilo v0.2.33

## Archive and delete

Archiving a parent also archives its delegated subagent descendants, stops their work and pauses their queues. Ordinary conversation forks remain independent. Restoring shows the delegated branch again without automatically restarting tasks or queues.

Owners can permanently delete individual archived records, with Chinese, English and Korean confirmation and retry feedback. Other conversations and workspace files remain. Deleting a cloud parent detaches its direct children without changing execution-directory isolation.

## Memory and execution paths

Startup streams history into the search index. Inbox recovery retains submission receipts and schedule facts instead of accumulating all transcript bodies.

Runtime now indexes committed session facts and per-run event boundaries. Run checks, input-author resolution, directory admission, result extraction and inbox settlement read only the required information instead of copying the full transcript. Synchronous event persistence, durable inputs, permission checks and schedule-origin validation are unchanged.

Reading session configuration no longer depends on model authorization or a network connection. Revoking a platform model grant leaves existing history readable, and users can switch to an available model and continue. New tasks still require current authorization.

## Downloads and retention

Workspace ZIP files, unsupported previews and large files can be downloaded in full, independently of the 2 MiB preview limit. File links in replies open workspace tabs. Original and historical files transfer in chunks; historical downloads retain integrity verification.

The session-log plugin adds **Retained generated-file limit (MiB)**, defaulting to 64, synchronized between aggregate and detailed settings. Lowering it preserves downloads and restoration of existing objects. Upload limits remain independent.

## Subagent follow-ups

Repeated messages to the same child within one parent turn now use distinct run IDs, fixing `already exists in this session`, and failures invalidate activity state. Child invocations retain the original task authority through verified origin proofs. Agent Team’s Shared tasks empty state distinguishes conversation plans; plans are not automatically converted into shared tasks.

## Plugin configuration saves

Aggregate settings, plugin details and coordination settings share pending-write state. A late completion from a previous entry point no longer overwrites a newer draft. Restoring inheritance clears only the unchanged draft belonging to that operation.

## Core plugin interface change

Custom core plugins using the Sessions service must adapt to `ternilo/sessions@2` and rebuild. Executor protocol 52 replaces 51; Server, Node and Worker require matching upgrades, while the independent maintenance channel remains available to update older executors. New subagent inputs record `source.kind=subagent` and the parent run. Older binaries cannot safely read histories containing these records; retain a pre-upgrade backup for rollback. The new version reads existing history, with no database migration.

## Upgrade

Update Server to `ghcr.io/mosttt/ternilo-server:0.2.33` and update complete client bundles. Clients on v0.2.30 or later with remote updates enabled can upgrade through Server; earlier versions require manual installation. Keep instance data, computer registrations and service configuration. No database migration is required.

See [client updates](https://github.com/mosttt/ternilo/blob/v0.2.33/docs/en/client-updates.md) and [core architecture](https://github.com/mosttt/ternilo/blob/v0.2.33/docs/en/architecture.md). Desktop installers remain unsigned and automatic updates remain disabled.
