# Ternilo v0.2.7

This release completes first-time OAuth2/OIDC registration and fixes mobile layout and Turnstile callback conflicts after widget recreation.

- A usable provider `preferred_username`/`username` and email register the account automatically. Conflicting or unusable usernames require a choice; contact email is requested only when the provider omitted it.
- Provider email is used directly without an editable field. The backend ignores registration parameters attempting to replace it. Equal emails never merge identities automatically; existing addresses require signing in to the original account and explicitly linking the identity.
- Automatic registration preserves invitation, approval and human-verification checks. Required Turnstile verification comes first; missing invitations cannot create accounts, and pending approval does not grant access.
- Mobile computer cards display one full-width action per row for details, suspension/resumption, revocation and removal.
- Turnstile callbacks from retired size/theme variants cannot overwrite a newer widget token. Retry and expiry refresh use a single explicit flow, and provider error codes are displayed.
- Recovery documentation describes the exact login-settings reset scope and Docker command, avoiding accidental instance master-key regeneration.

Server still verifies OIDC signatures, PKCE, nonce, UserInfo identity and Turnstile Siteverify. Saved login settings keep their current format. Widget lifecycle fixes do not guarantee that Cloudflare will accept a production challenge; persistent failures need investigation using the displayed code, browser, network and provider configuration.

Six platform targets and desktop installers are included, together with the AMD64/ARM64 Server image `ghcr.io/mosttt/ternilo-server:0.2.7`. The stable release updates `latest` after publication. Desktop signing, notarization and automatic updates remain disabled.
