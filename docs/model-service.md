# 通过 Server 使用模型

Server 可以集中接入模型服务商，再把模型使用权限分配给账号。使用者在自己的 Ternilo 中发起模型设备授权，在 Server 网页验证账号并确认；也可填写平台地址和受限模型 Key。客户端无需账号登录，文件、命令和工具仍在自己的电脑上运行。这项能力不需要 Worker，也不需要先把电脑登记到 Server。

单用户和多用户模式都可以使用模型服务，SQLite 和 PostgreSQL 提供相同功能。单用户模式只有实例所有者能调用；多用户模式按每个账号的当前授权判断。

## 三个入口怎么配合

“平台管理 → 模型服务”由平台管理员接入模型、发布模型并分配使用权限和额度；“我的模型”让每个用户查看和使用自己获得的授权；“空间管理 → 权限组”让团队管理者把工作区／会话的协作权限授予一批成员。

模型使用的路径是：**平台接入上游 → 发布平台模型 → 授权账号或用户组 → 用户的“我的模型”显示获准的模型与额度来源**。用户可以在自己的 Ternilo 中使用，不需要先加入团队。模型服务中的“用户组”包含账号，不是模型集合；一份组授权的额度由成员共同使用。

项目协作的路径是：**团队成员 → 团队权限组 → 共享工作区／会话 → 获得查看、提交、停止或配置等具体权限**。团队权限组与模型服务用户组分别维护成员，当前没有自动同步或继承。加入团队权限组不会直接增加“我的模型”中的授权，加入模型服务用户组也不会获得项目文件访问权限。

例如，管理员给小王个人分配一份模型额度，小王便能在“我的模型”看到它。小王再把一个已配置该平台模型的托管会话分享给团队协作组：组员有提交权限，且小王使用的模型授权允许协作者使用时，组员便能在这个会话里提交任务，消耗该会话选定的额度。组员不必另外领取一份独立模型授权，但也不能因此创建用于自己电脑的模型 Key。若只授予查看权限，就只能查看结果。

“我的模型 → 模型 → 平台授权”是个人所获授权的视图，不是需要再次配置或发布一遍模型的管理后台。管理员给自己使用时，也通过这个入口查看自己的授权；自己的使用权限与管理平台模型的职责分开。“账号自有”和“设备本地”管理各自的 Provider，与平台发布、授权分别维护，见[三类来源](models.md#server-的三类来源)。

## 管理员：接入并发布模型

进入“平台管理 → 模型服务”：

1. 在“上游接入”添加模型服务商或兼容网关，填写地址、协议和 API Key。点击“获取可用模型”，确认模型目录、上下文和最大输出设置后保存。
2. 在“平台模型”发布模型，选择上游连接及其模型，填写对外模型 ID 和显示名称。对外 ID 是使用者在客户端中填写的名字，与服务商的内部模型名可以不同。发布本身不会让所有用户获得使用权限。
3. 在“授权与额度”按“给谁使用 → 可以使用哪些模型 → 设置额度与有效期”填写授权。单人直接选账号，不必先建组；多人共用额度时选择用户组。

授权表单可以就地新建用户组、添加成员并选中，也可以发布缺少的模型；发布过程中若缺少上游连接，同样可以就地添加。返回后保留原授权和发布草稿，并选中新建项。上游连接、平台模型、用户组各自独立保存；取消最后的授权，不会撤销之前已创建的配置，也不会自动授予模型访问权限。

平台所有者和管理员可以分配模型权限；模型／执行运维员可以维护上游和发布模型；审计员只读查看。平台职责不授予其他用户私人项目的读取权。

上游 Key 保存后不会回显。再次编辑时，Key 留空保留原值，填写新值会替换；只有明确选择清除时才删除。公开模型 API 的每次请求只调用上游一次；托管任务按上游配置重试，每次尝试分别记录用量。请求超时可以在上游配置中调整。

## 模型服务用户组与团队协作组

用户组位于“模型服务 → 授权与额度”，可从全平台账号中添加组员。每个人继续拥有自己的个人空间，不需要加入公共团队。

给模型组分配的额度由整组共享，不是每人各得一份。例如，给组分配每月 100 万 token，组内所有成员共同使用这 100 万。需要分别控制个人预算时，可以直接向各账号分配授权。成员、组和授权目录均支持搜索、分页。

模型服务用户组只用于分配模型调用权限。团队“空间管理 → 权限组”管理的是工作区和会话共享，两者不会互相扩大权限。共享会话的提交权限也不能拿来生成独立模型 Key。

## 使用者：给客户端授权账号模型

在本机 Ternilo 的“设置 → 模型 → Server 模型连接”点击“连接 Server”，填写 Server 地址与连接名称。页面显示验证码和授权链接；在 Server 网页登录账号，核对设备名称和验证码后确认；需要使用另一个账号时点击“切换账号”。长期设备凭据保存在本机，网页不接收该凭据。

账号验证发生在 Server 的授权网页，可在手机或另一台电脑上完成。客户端不需要账号系统或普通网页登录态，不保存账号密码；它只持有此次授权产生的模型设备凭据。能够连接 Server 不等于已经获准调用，后续每次请求仍须校验该凭据及账号当前的模型授权。退出授权网页的登录不会自动撤销设备模型访问，要停止授权应使用设备撤销或本机断开操作。

默认允许账号当前及以后获授的平台模型；账号自有 Provider 必须另外明确勾选，已有设备不会自动获得私有模型权限。也可以限制到指定的平台授权与私有 Provider 的具体模型，支持仅授权私有模型。勾选全部私有模型包含以后新增的配置；指定模型的授权不会自动扩大。账号自有模型的费用由相应上游结算，Server 按 `user_provider` 记录用量，不扣平台额度。私有上游地址、密钥及密钥引用不下发设备。

批准连接时可以给该设备设置月度 token 上限、并发请求上限和访问截止时间。留空表示不增加这一项设备限制，不代表平台预算无限。设备额度按 UTC 自然月计算，账号自有模型与所有获准的平台预算共同使用这一份设备额度；切换模型、Provider 或平台预算不会获得另一份。平台来源还必须同时满足原授权的额度、并发和有效期。设备限制只约束通过该授权调用的模型，不限制该电脑上直接连接其他服务商的 Provider。

也可设置“每分钟请求上限”（1–10000，留空不额外限频）。它是滚动的最近 60 秒窗口，不在整分钟或跨月时清零；账号自有和平台来源共用。只统计 Server 已接受的逻辑请求，限额拒绝不会写入新请求；同一幂等标识的重复提交和 Server 内部上游重试不多占次数，重新提交为新请求则计数。即使后来取消或上游失败，已占次数也要等窗口到期。达到上限返回 HTTP 429，不自动换来源；移除限制立即允许新请求，不清空已有用量。此项不限制其他设备，也不是全平台的速率策略。

在“我的模型 → 授权与接入 → 模型授权设备”可查看和调整自己设备的限制，并查看本月已结算 token、仍保留的预留与当前活动请求。预留包括无法确认的消耗，不会当作零；可信用量到达后按实际结果结算。调低 token 或并发上限只限制新请求，不强行中断已接受调用；设备到期或被撤销则使后续访问失效，活动模型流也会复核并停止。

已到期或撤销的设备需要重新授权，不能靠编辑限制恢复旧凭据。授权网页上的验证码有效期与设备长期访问截止时间是两回事；若批准后尚未完成连接就已超过设备截止时间，也不会签发可用访问凭据。Server 的设备管理只允许授权账号本人使用，平台管理员不能替他人修改设备限制。

连接不授予平台远程操作电脑、访问文件或管理账号的权限，也不要求登记电脑或 Worker。设备凭据只用于模型 API，不能作为普通账号登录凭据。

回到 Ternilo 后，在模型选择器中按“账号自有 · 已连接 Server”或“平台授权 · 已连接 Server”选择来源。分组显示连接名、用户名、Provider／额度来源和 Server 地址；同名模型保持独立，不会因密钥删除、撤销或额度不足而自动换用另一份。每台设备可以连接多个 Server 或不同账号，同一账号的多份来源可以在一次浏览器确认中授权。

授权变更后点击连接旁的刷新按钮即可重新读取模型。删除私有 Provider 或其密钥会使该来源不可用；运行中的模型请求也会复核授权。撤销一份平台模型授权只影响这份来源；撤销设备则使该设备的所有模型请求失效。“我的模型 → 授权与接入 → 模型授权设备”提供设备目录和撤销入口，它与工作区内的电脑登记不同。本机断开连接保留会话历史；Server 暂不可达时可以选择仅从本机断开，并在 Server 恢复后撤销设备。

本机设置的 Server 连接卡也显示取得的设备月额度、并发、请求频率和截止时间。它是上次读取的元信息，不代替 Server 的实时判定；点击刷新可更新，调整限制仍在 Server 网页完成。缓存时间已到期时，本机会提示刷新确认，不擅自撤销或修改 Server 凭据。刷新遇到模型授权失效时会明确报告访问被拒绝，保留原连接、历史和模型选择，不自动换来源，也不把它当作本机网页的访问令牌失效。

这条独立设备连接用于本人在本机发起的任务，不接受通过 Server 远程提交的账号输入作为设备模型的可信操作者。它与 Server 直接授权 Node 会话使用账号／平台模型的路径不同；手动 Provider、受限 API Key 和托管任务路径也分别保留。

对于已作为 Node 接入、由 Server 网页远程操控的电脑，可在会话模型选择器中选择“账号自有”，或从“平台授权”选择账号获授的预算。这条路径使用受信任的机器连接和 Server 接受的任务身份，不借用电脑上另存的设备模型凭据。配置者需要会话配置权限；新的私有模型绑定须由模型持有人明确授权，协作者实际调用还要有提交权限，平台授权还须允许共享。模型和上游密钥留在 Server，文件工具仍在电脑执行；撤销后保留原选择并显示不可用，不自动切换其他预算或同名本地模型。

## 使用者：手动接入自己的 Ternilo

打开 Server 的“我的模型 → 模型 → 平台授权”查看模型及其额度来源，或直接进入“授权与接入 → 接入密钥”。创建接入密钥时，为它起一个容易辨认的名字，例如“我的笔记本”，选择一份授权和允许使用的模型，再按需缩小月额度、并发和有效期。

接入密钥只显示一次。复制创建结果中的平台 API 地址、Key 和模型 ID，然后在本机 Ternilo 的“设置 → 模型”中添加 Provider：

- API 地址填写平台地址，例如 `https://ai.example.com/v1`。
- API Key 填写刚创建的接入密钥。
- 协议选择该模型显示的 OpenAI Chat Completions、OpenAI Responses、DeepSeek Responses、Google Gemini 或 Claude · Anthropic Messages；两种 Responses 共用 `/v1/responses` 入口，但保留各自的思考格式。Gemini 和 Claude 使用原生接口，同样以 Server 的 `/v1` 为基础地址。
- 获取模型并保存，随后在会话中选择它。

创建结果中的“管理接入密钥”进入“我的模型 → 授权与接入 → 接入密钥”。这里可查看前缀、模型范围、状态和撤销，但不能再次读取完整密钥；遗失后应创建新密钥并撤销旧密钥。

不同协议需要分别创建 Provider，可以共用同一平台地址与接入密钥。获取模型时，Ternilo 只导入与当前 Provider 协议匹配的模型。其他兼容客户端按相同地址、Key、协议和模型 ID 配置。

每份 Key 固定使用创建时选择的授权预算。它自己的额度只是这份预算的进一步限制，不会增加新的余额，也不会在额度不足时换用另一份授权。Key 不能用于登录管理网页、读取文件、登记电脑或接入 Worker。

## 用量与撤销

“我的模型 → 用量”显示自己的调用记录；管理员在模型服务的“用量”查看平台记录。输入、输出、缓存读取、缓存写入和上游提供的推理 token 分别显示。缓存和推理中的子项不会再次算成一笔 token 消耗；这些记录不是金额账单。

原生 Gemini 的输出用量包含候选回答与思考 token，缓存读取另列为输入明细；Claude 的输入用量包含普通输入、缓存读取和缓存写入，输出按上游报告记录，未报告的独立推理用量保持未知。这些归一化后的用量复用同一账本和额度结算，不需要另建原生协议计费系统。

个人用量支持账号自有、平台授权和全部来源筛选，统计与分页记录使用相同来源条件。设备直接调用本地 Provider 的用量尚未汇入 Server，需要在对应会话查看，不表示调用量为零。个人请求接口 `/api/v1/model-access/requests` 与汇总接口 `/api/v1/model-access/usage` 均接受可选 `source=user_provider` 或 `source=platform_grant`；省略时返回当前账号有权查看的全部来源。

接受请求前，Server 会预留额度和并发。返回完整用量后再结算；如果连接中断或上游未提供完整用量，记录显示“用量待核对”，并保留必要预留，不记成零消耗。月度按 UTC 的自然月统计，用量归入接受请求时的月份，跨月执行不会把同一次调用改扣到另一月。

撤销 Key、撤销授权、移出模型组或停用模型后，新调用会被拒绝，活动模型流也会重新检查授权并终止。已经发生的调用仍需结算，用量记录不会跟着授权删除。Server 异常退出留下的过期请求会释放并发占用；无法确认的消耗继续保留。

Key 列表中的“未撤销”仅说明这份 Key 没有被主动撤销。实际能否调用，还取决于当前账号模式、组员身份、授权、模型状态和有效期。

平台上游 Key 加密保存在 Server 数据库中，数据库备份和现有主密钥轮换同时覆盖这些凭据。轮换仍按[部署说明](deployment.md)执行，不需要把 Key 分发到 Worker。

## 兼容接口与当前范围

公开接口为：

| 接口 | 用途 |
|---|---|
| `GET /v1/models` | 返回这个 Key 当前可使用的模型与协议信息 |
| `POST /v1/chat/completions` | 调用发布为 Chat Completions 协议的模型 |
| `POST /v1/responses` | 调用发布为 Responses 协议的模型 |
| `POST /v1/messages` | 调用 Claude／Anthropic Messages 模型，使用 `x-api-key` 请求头 |
| `POST /v1/models/{model}:generateContent` | Gemini 原生 JSON 调用，使用 `x-goog-api-key` 请求头 |
| `POST /v1/models/{model}:streamGenerateContent?alt=sse` | Gemini 原生 SSE 调用，使用 `x-goog-api-key` 请求头 |

官方设备连接在 `/v1/device/{grant_id}` 或 `/v1/device-account/{provider_id}` 下使用同样的 `models`、`chat/completions`、`responses`、`messages` 和 `models/{model}:generateContent`／`:streamGenerateContent` 路径，分别固定平台授权和账号私有 Provider。两者只接受已批准的模型设备凭据；私有模型范围不能通过普通平台接入密钥调用，也不接受网页会话代替设备凭据。客户端自动生成这些来源配置，无需手动填写私有上游地址。

上述协议分别支持流式和非流式调用，保留文本、图片输入、客户端函数工具及结果和已配置的推理能力；结构化输出须按各协议与模型实际支持的参数提供。服务不自动跨协议转换，请按模型声明的协议调用。`GET /v1/models` 使用 Gemini 或 Claude 的原生鉴权请求头时返回对应协议的目录形状，并只列该协议模型；密钥放在请求头中，不放进 URL。

当前 Responses 调用不保存跨请求状态，使用 `store: false`；不支持引用上游已有的 response、conversation、prompt、file 或后台请求。需要继续对话时，由客户端携带本轮所需历史。供应商托管搜索、音频和其他托管工具仍需单独适配，不能把它们当作已开放功能。

原生网关同样不提供上游托管状态：拒绝 `cachedContent`、`container`、`context_management`、`mcp_servers`，工具仅允许客户端函数，Gemini 每次请求只允许一个候选。Vertex AI/OAuth、Bedrock、Files 上传、实时语音、图像生成和服务商内置搜索不在当前接入范围；完整原生配置见[模型说明](models.md#gemini-与-claude-原生协议)。

客户端可传入 `Idempotency-Key` 防止同一请求被重复接受。同一 Key 重复提交已经接受的请求会收到 HTTP 409，不会再次调用上游；该接口不缓存并重放先前答案。额度或并发不足返回 HTTP 429，协议或参数错误返回 HTTP 400，凭据或授权问题返回 HTTP 401／403。

这些公开 API 不自动重试上游调用。客户端若决定发起另一次尝试，应使用新的请求身份，并按新的调用记录处理用量。


## 在托管会话中使用

托管会话直接选择“模型＋授权”，无需给 Worker 创建或复制模型 Key。相同模型可能来自不同授权，选择时会显示授权名称，后续不会悄悄切换预算来源。也可以选择会话所有者在“我的模型”保存的账号 Provider，即使会话在另一个团队空间执行，也无需复制配置或密钥。未配置模型时可以先创建空白会话，填写配置后再提交任务。

共享会话沿用资源所有者的模型配置；协作者需要资源提交权限。会话直接选择平台模型授权时，该授权还必须允许共享资源使用。共享会话不会向协作者发放独立模型 Key。自己的请求历史包含本人发起或本人模型授权承担的调用，并区分操作者与资源所有者。

资源所有者需亲自选定要共享使用的账号 Provider。协作者仅能查看当前选定的模型，不能凭会话查看或配置权限遍历、改选所有者的其他私有模型。个人凭据空间与团队执行空间独立，任务额度仍归实际执行空间；移除所需凭据后，新的提交和调用检查失败，不自动沿用执行空间中的同名 Provider。

“允许共享资源使用”约束直接绑定平台授权的托管调用，以及 Server 向接入 Node 会话明确配置的平台授权调用。自己的电脑或私人 Provider 通过普通模型 Key 接入时，模型服务按 Key 持有人计量，不能仅凭这份 Key 识别远端协作者。

托管调用支持上游配置的重试次数，每次尝试分别计量。连接中断或任务结束不会抹去已知用量；未得到可信用量的部分保留预留。平台模型授权与托管任务使用同一份模型账本，空间预留只负责约束执行任务的总额度。

每个托管会话还可在“更多会话操作 → 任务用量上限”调整后续每次任务的预留上限。它约束整项任务的多次模型调用，不是单次回答的最大输出长度，也不增加授权余额。已有排队和运行任务保留提交时的上限；图片等输入预留不足时，先按提示提高上限，再提交保留的草稿。

模型服务管理中的 Provider 也使用“单次请求总时限”：`0` 表示 Server 不设置该上游请求的总时限，正数包含上游的等待、思考和输出。客户端与上游各自的限制仍独立；客户端断开或用户取消会继续停止执行。
