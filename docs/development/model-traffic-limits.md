# Server 模型请求分层限流

状态：下一实施项，尚未交付。设备级每分钟请求、并发和月度 Token 限制已有实现；此处扩展全站与账号层，不增加授权，不替代已有模型／空间预算。

第一条完整流程覆盖 Server 实际接受的逻辑模型请求：平台模型、账号 Provider 及通过 Server 转发的电脑 Provider。账号层以实际提交者身份计算，服务账号使用自身身份；不把资源原所有者或借出模型的账号当作提交者。本机直接访问上游且不经过 Server 的调用不在 Server 可强制控制的范围。

全站与账号层先支持滚动一分钟请求数、同时进行的逻辑请求数。现有 `control_model_requests` 和 `control_computer_model_requests` 作为接受／完成／租约事实来源；幂等重复和内部重试不重复计数，失败或取消不能清除一分钟内已接受的事实。所有来源共同检查同一层限制，多 Server 使用数据库事务和一致锁顺序竞争额度；编辑限制不能清空当前窗口。既有 Token 预算继续按原来的模型提供者与空间归属结算，不把设备报告转成 Server 计费事实。

管理界面提供实例策略、默认账号策略和账号覆盖值；未设置的维度不增加额外限制。仅具备对应实例管理权限的账号可以修改策略，普通账号只能查看自己的有效限制及使用状态。拒绝应返回可识别的 429 和合理的重试提示，不能落成笼统的 500。

验收必须覆盖双库并发竞争、不同账号／凭据、不同模型来源、跨 Server、幂等／重试、到期／完成释放、窗口边界、策略修改与撤权，以及真实网页配置和受限请求。策略配置、准入与观测验证全部完成前，不在正式文档宣称已支持分层治理。
