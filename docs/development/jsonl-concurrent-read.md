## 代码与复现

`JsonlEventStore` 的写锁属于单个实例，而全量／增量／分页／单事件读取没有与写入共享保护。同一日志经常由不同实例读取。写入一条 JSONL 记录时，读者可能在换行和完整字符串落盘前到达 EOF；读取器会把尚未完成的尾部当作损坏记录。分页读取只固定文件长度，也可能固定到写入中间的长度。

Tokio `sync_data` 已等待正在进行的写入。需要保证其他读者等待写入完成，而不是跳过末尾数据、扩大浏览器等待时间或修改真实会话历史。静态损坏日志仍应报错，并继续使用既有离线检查／备份／修复流程。

新增可控回归：两份独立 store 指向同一日志，写入者在记录的 JSON 字符串中间暂停，四种读取并发开始。读者必须等待记录完整落盘，之后返回相同的完整事件；正常关闭后的损坏日志保持严格拒绝。修复前失败，修复后的日志／分页／损坏修复 14 项全部通过，0.69 秒。

实现使用按日志路径共享的 `RwLock`，保护完整写入、分叉种子、删除和四种读取；不同日志互不阻塞，同一日志的读者可以并发。共享注册表保留弱引用，创建新锁时清理已释放项，避免把结束会话的访问锁永久保留。没有忽略未完成尾部、放宽 JSON 校验、自动改写日志或修改用户实例。
