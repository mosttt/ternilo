# 2026-11 项目审查

## 结论

本轮审查与发现问题的修复已完成，随 v0.2.31 公开发行。审查覆盖本地服务、Server Node、共享授权、模型转发、子会话、设置、历史、文件页面和更新恢复；Work 不在范围内。

## 审查发现与修正

### P1：依赖安全更新

审查时锁定 `wasmtime 48.0.7` 与 `pulldown-cmark 0.13.5`。候选 Checks 的依赖作业命中 `RUSTSEC-2026-0422`、`0423`、`0424` 和 `0433`，安全门禁失败，许可证与来源检查通过。

Wasmtime 的组件借用资源内存记账问题可能造成宿主内存耗尽；项目确实启用了 Component Model，不能只依赖现有 fuel 与内存限制忽略该公告。官方同分支修复为 **48.0.8**，见[组件资源公告](https://github.com/bytecodealliance/wasmtime/security/advisories/GHSA-6fr9-xmw9-5352)。另两项公告涉及核心 Wasm 的 I31/NoneRef 或跨 Engine 的宿主结构类型，当前扩展路径没有使用对应接口，见[类型参数公告](https://github.com/bytecodealliance/wasmtime/security/advisories/GHSA-3982-jqvv-277m)和[跨 Engine 公告](https://github.com/bytecodealliance/wasmtime/security/advisories/GHSA-qw58-7h65-crq2)。

pulldown-cmark 的问题要求启用 `ENABLE_WIKILINKS`；当前 `document_tools.rs` 未开启该选项，因此没有命中这条解析条件。现已更新到同系列补丁 **0.13.6**，未增加安全忽略项，见[RustSec 公告](https://rustsec.org/advisories/RUSTSEC-2026-0433.html)。

已升级 Wasmtime 至 **48.0.8**，同步 Cranelift 等配套锁文件。WASM 扩展、文档生成与安全门禁按新锁文件验证。

### P1：升级进度写入失败可能使客户端保持停机

位置：`apps/ternilo/src/updates/apply.rs` 的 `activate`。

原流程先停止旧服务，再执行安装标记、程序替换、配置和进度保存。`progress(AwaitingReconnect)?` 位于安装回滚分支之外；失败会直接返回，既不清除安装标记，也不进入 `start_service`。已有安装失败／启动回滚分支也把进度写入放在启动服务之前。

隔离故障注入使用临时程序和目录，将进度目录设为只读。实际返回 `Permission denied`，并确认残留 `.ternilo-installing.json`，复现安装未恢复的状态。该验证不连接真实服务。

安装标记、替换、配置、进度与标记清理现已纳入同一失败恢复分支；未替换程序时不执行多余回滚。恢复保留安装锁和原版本校验，确认恢复安全后启动服务，进度保存失败不再阻断启动。回滚及显式本地恢复先保留报告结果，再启动并核验健康，最后返回报告错误。原配置未改变时不重复写入，使配置目录写入失败后的安全恢复仍可启动。当前配置缺失或损坏时，仍从保存的恢复计划还原，保留原有恢复能力。

### P2：旧活动快照会让失败的子 Agent 继续显示“正在协作”

位置：`web/src/components/workbench/subagent-activity.tsx` 的 `active` 计算。

原实现只要活动快照存在，就优先使用其 `running`，不比较它与已保存子 Agent 状态的时间。组件复现使用时间 20 的失败记录和时间 5 的旧运行快照，仍显示“1 个子 Agent 正在协作”。这可以同时解释失败卡片和运行提示不一致的表现。

现按同一子会话的更新时间合并；时间相同时优先已保存状态，后续更新的运行快照仍能表示真正重新启动。组件回归覆盖失败、完成、取消、空闲、同时间冲突与随后重新运行。

### P3：预设设置页仍允许尝试修改已开始的会话

位置：`web/src/components/settings/presets-settings.tsx` 的“用于当前会话”按钮。

后端与会话工具栏已禁止首次接受任务后切换预设，但设置页原先只检查是否已经使用同一预设，仍提供会被后端拒绝的操作。设置页现复用空白会话条件，并显示中英韩锁定原因；仅禁用当前会话的更换入口，新会话默认值、查看和编辑保持可用。组件回归验证开始后锁定、空白会话可切换及其他入口不受影响。

## 本轮已修复并验证

- 新子会话的资源同步不再复用创建前取得的在途快照，保留原有模型与凭据授权检查。
- 授权回答避免同一问题并发重复提交，成功后立即移除等待项；错误会话回答仍被拒绝。
- 预设卡片查看不再暗中修改默认值；旧异步读取不能覆盖后来选择的预设。
- Responses 的图像复杂度拒绝保留安全原因，不再因 HTTP 502 包装而重复发送相同无效参数；对话推理设置不变。
- 已结束任务的短暂收尾不再立即误报为运行中任务，运行中的插件修改仍及时拒绝。
- 无代码块回答结束时从第 20 段跳到第 25 段的问题已复现并修复：流式与最终内容共用安全 Markdown 布局。
- 子 Agent 授权显示委派任务和影响，支持中英韩；具体策略原因不被通用说明覆盖。

实现和前期证据见[运行交互修复](agent-runtime-reliability.md)。
