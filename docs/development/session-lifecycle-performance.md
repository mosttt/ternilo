# 会话生命周期、启动内存与执行路径

## 归档按委派关系联动，删除仍针对单条记录

Local 和 Cloud 的归档／恢复只遍历带 `subagent` 元数据的委派后代，普通历史分叉不联动。Local 在取消父任务后发现子会话，持有生命周期锁直至整棵树的归档状态写入完成；Cloud 在事务中锁定父子记录、暂停队列，再取消 queued／leased／running 任务。创建子 Agent 时检查父记录的归档状态，避免归档后继续派生。

Server Node 保留现有单会话响应，并刷新电脑资源快照以同步子会话元数据。远程操作已经成功时，后续资源刷新失败只记录同步错误，下一次发现重试，不把已执行的归档报告成操作失败。

归档页新增所有者可用的永久删除确认，中英韩一致。确认明确名称、不可恢复、只删除此条记录、不删除其他会话或工作目录文件；重复点击只发一个请求，失败保留确认和重试入口。恢复后刷新列表，避免已恢复子会话残留。

`DELETE /sessions/{id}` 仍是单记录操作。Cloud 删除先确认委派分支没有活动任务，再解除直接子会话的父子关联；保留子会话及其日志、分享和独立执行目录族记录，不因删除历史改变隔离边界。Local 子会话的原父 ID 可作为历史来源保留。

## 启动改为流式处理历史

原搜索索引重建先累计所有会话的索引文本及文件列表，再提交 SQLite；队列恢复随后再次整份载入各会话日志。启动阶段因而产生与历史体积相关的临时内存峰值。

索引重建现在复用 JSONL 的序号校验读取器，在 SQLite 事务内逐条读取、索引；队列恢复只保留已消费的输入 ID 和调度事件，不保留消息正文或工具输出。读取器持有日志读锁，SQLite 工作线程执行同步读取，沿用日志→索引锁顺序，避免阻塞异步执行线程。索引替换仍为一个事务，损坏日志会回滚，不发布半份搜索结果。

启动优化不改协议、配置、数据格式或历史内容，不要求停机迁移。索引仍在启动时扫描全部历史，调度器仍按原规则重放；增量索引及常驻运行时淘汰不在本阶段实现范围。

## 启动测量：内存下降，耗时基本不变

Linux x86_64、相同未优化构建且关闭调试信息／增量编译，使用 10 个隔离会话，其中 5 个已归档，每个 100 轮，共 9000 条事件、27,424,800 字节（26.15 MiB）。未连接浏览器或 Server，没有模型费用。前后顺序执行，测量期间不编译或运行其他压测。第一次启动重建索引，第二次已有索引缓存；当前实现两次都扫描历史。

| 指标 | 修改前，第一次／第二次 | 修改后，第一次／第二次 |
|---|---|---|
| 采样峰值 RSS | 101.3／101.9 MiB | 73.3／73.3 MiB |
| 就绪一秒后私有脏页 | 40.7／40.7 MiB | 11.6／11.8 MiB |
| HTTP 就绪耗时 | 3.54／4.31 秒 | 3.58／4.27 秒 |

该负载中 RSS 降约 28%，主要收益来自不再累计历史正文。耗时变化约 1%，没有启动提速结论。数据是开发构建与合成历史，不代表正式包在任意配置下的占用。原始数值见[启动测量](benchmarks/2026-11-08/startup-memory.json)。

## 执行路径：只读取需要的事实和轮次

会话存储在历史恢复后建立轮次索引、主输入来源、终态和消费凭据，仅在持久化成功后与规范事件一起发布。Agent 的重复轮次检查、结果提取、取消和推理观测按轮次读取；Local 目录准入、模型作者溯源和队列收尾读取事实。未加载运行时的作者查询流式扫描日志，不为读取记录启动运行时。首条输入的作者不会被后续 steering 输入覆盖。

内部接口升级为 `ternilo/sessions@2`，提供 `summary`、`run_facts`、`run_events` 和 `event_at`。直接实现或声明依赖旧 Sessions 服务的自定义核心插件需要适配并重新编译；内置插件同步升级。该接口重构本身不改变持久化格式；本版本新增子轮次来源和文件传输的升级边界见下文。

成功轮次与正常队列收尾不再执行结果未被使用的撤权查询；只有取消或失败时才查询是否需要暂停或丢弃撤权任务。准入、工具、模型调用的权限检查及调度来源校验保留，事件同步落盘和输入队列持久化策略没有降低。

## 配置查询与执行授权分离

浏览器回归发现：平台模型授权撤销后，Live 元数据读取中的配置查询仍请求模型网页授权；该错误被当成历史访问失败，清空页面并阻止继续发送，即使用户随后已切换到有效模型。

配置读取及投影配置集中到 `application/session_profiles.rs`，与历史操作和执行准备分离。查询只组合已接受的会话配置及当前运行时快照，不访问 Server 模型授权、不创建运行时。普通任务提交和真正执行时仍刷新网页配置并验证授权，网页凭据调用仍验证本轮来源。既有 `effective_session_profile` 入口保留。

## 执行测量：长历史收益更明显

短／长会话交替执行 `/code "execution-probe"`。长会话为 100 轮、900 条事件、10,654,000 字节；每种会话首次任务单列，再统计 20 次后续任务和 5 次前台 in-process 委派。使用相同开发构建设置，无付费模型调用，串行测量且不同时编译。计时包含本机 HTTP 往返、工具处理及持久化；子任务还包含授权轮询。

| 指标 | 执行优化前 | 最终候选 |
|---|---:|---:|
| 短历史后续任务 p50 | 42.48 ms | 37.32 ms |
| 长历史后续任务 p50 | 89.82 ms | 61.38 ms |
| 长历史后续任务 p95 | 128.74 ms | 68.16 ms |
| 长历史首次运行 | 1503.57 ms | 1036.07 ms |
| 短历史委派总耗时中位数 | 228.30 ms | 216.09 ms |
| 长历史委派总耗时中位数 | 291.78 ms | 232.77 ms |

本负载中，长历史后续任务 p50 降约 32%，委派总耗时中位数降约 20%。模型推理和外网等待不在该收益内。首次运行仍有加载规范历史和构建运行时的成本。

最初仅加事实索引的候选缩短了长历史任务，但短任务 p50 反而增加约 2–6 ms，委派没有稳定收益；随后移除成功路径的冗余撤权读取，得到上表结果。原始系列与早期反证保留在[执行对比](benchmarks/2026-11-08/execution-comparison.json)，初始调查基线见[执行基线](benchmarks/2026-11-08/execution-baseline.json)。这些数据用于解释本次改动，不作为所有机器或正式包的性能承诺。

## 子轮次来源与文件传输

自动子任务和连续追问分配独立运行 ID；显式接受的人类输入保留授权运行 ID，以继续拒绝重复提交。`source.kind=subagent` 指向父轮次，配置查询不推测作者。Node 向 Server 提交按遍历顺序排列的子输入／调度来源证明，Server 按事件序号核对规范输入、登记父子关系和调度事实，再验证原账号输入、当前模型与资源权限。失败同样发布活动失效通知，避免侧栏保留运行标记。

工作目录下载与预览分离，按 1 MiB 分块验证路径、大小和修改时间；Server 每块重新检查工作区访问。历史文件使用规范附件对象，按块校验摘要，Cloud 使用 SQL `substr` 读取。HTTP 消费驱动下一块，取消后不再拉取。浏览器下载为 Blob，由浏览器管理存储，不承诺恒定内存。

会话日志插件的 `max_retained_file_mib` 默认 64，Local 主任务、子任务和 Worker 使用同一个类型化解析器。只限制新留存写入，不改变上传策略或已有文件读取／恢复。Worker 新增按有效租约和运行配置限额接收的原始附件上传，避免 base64 扩张触及旧 JSON RPC 上限；启动子执行进程前恢复规范对象，不再把大附件内嵌进执行信封。全局 JSON 请求限制没有放大。

执行协议升级为 52，Server／Node／Worker 配套更新；维护通道独立。包含新子输入来源的日志不能交给旧版读取，降级需要升级前备份；既有历史可继续读取，数据库无需迁移。
