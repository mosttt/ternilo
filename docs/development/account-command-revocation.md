# 账号停用与 Node 持久命令

状态：持久命令的授权接收、投递及禁止重放已通过 SQLite、受限 PostgreSQL、真实 WebSocket 重连与 Server 回归。托管运行的处理见[账号任务清理](account-task-cleanup.md)，Node 队列、运行及离线收尾见[Node 账号清理](node-account-cleanup.md)。

每个新接收的账号输入保存当时的账号状态版本。接收事务与账号状态操作使用同一账号锁；命令去重不能刷新版本。每次首次投递和补发都核对当前状态及版本，不符合时永久禁止该命令继续发送。解封后新提交取得新版本，先前授权失效的输入不恢复。

pending 命令返回投递拒绝回执，但缺少投递证据不能证明此前未执行。inflight 命令保留已发送事实，干净断开只结束本次投递租约，不改写成从未发送。禁止再次发送后，当前有效连接仍可提交真实迟到回执；失效投递代次的回执被拒绝。缺少接收证据的持久输入不重放，历史事件和完成回执保留。

`gateway_input_authorization` schema 1 保存按租户隔离的接收证据。运行中清理另外通过当前执行器协议和 `node_account_cleanup` 组件追踪可信作者、持久撤销及完成回执，不能把禁止补发、断线或租约过期当成外部进程已经结束。

验证覆盖封禁期间原子拒绝接收、快速解封不复活原输入、去重不刷新版本、失效命令不阻塞其他批次、干净断开与换租约、迟到真实回执、journal 重开、无证据输入拒绝和真实认证 WebSocket 重连。
