# Cloud 会话统计检查点

2026-10-10。普通 `/sessions/{id}/stats` 与只请求统计的 Live 元数据读取现在使用数据库检查点，减少不变历史的重复解析与回放。实现复用 `ternilo_builtins::stats_unit()`，不另外维护计算公式；事件日志仍为事实来源。

独立最终 schema 组件 `cloud_session_stats`、版本 1 保存每个 tenant／session 的统计状态、日志游标、投影版本和重新生成后被丢弃的 run。SQLite 与 PostgreSQL 使用相同表结构；PostgreSQL 添加 tenant RLS 与受限 runtime 权限。没有更改原 Cloud 核心 schema 版本。首次读取或检查点缺失／失效时全量重建，追加事件只读取 tail，游标未变化时不重写检查点。重新生成历史会按现有 conversation 语义完整回放，并过滤后续迟到的旧 run 事件。缓存命中仍在事务内重新检查查看权限。

完整插件投影仍回放历史；Live 同时请求完整投影和统计时共用一次历史读取，以相同切面生成两者。不能把本阶段称为全部 Cloud 投影增量化。

SQLite 和受限 PostgreSQL 共用合同，覆盖空历史、模型计时跨检查点／重启、tail、幂等、并发、真正历史分叉、重新生成、迟到旧 run、坏 JSON／状态／游标／版本失效重建、共享查看／撤权及跨 tenant 拒绝，结果与原全日志统计 oracle 对比。PostgreSQL 另验证 runtime 无 scope 不能读取、不能更改 schema。合同加入标准 PostgreSQL CI 门禁。

匹配 v0.2.9 新源码程序的独立 SQLite HTTP／实际浏览器验证通过：先用公开 v0.2.8 创建配置与 30005 条合成历史，再用新程序读取原数据并自动建立独立检查点。连续三组冷读和各 30 次热读结果完全一致，重复读取不改写检查点；8／32 并发读取正确；追加 3 条事件后统计与完整 projection 相同，只请求统计的 Live 返回同一结果且不附带完整 projection。桌面／手机浏览器显示历史及两轮统计，无控制台、页面或 HTTP 错误。

同一开发构建下，三次无检查点全量统计为 1985.5、1980.1、1973.1 ms；热读 p50 为 4.79、5.01、4.62 ms，p95 为 6.75、6.75、5.15 ms，tail 为 6.59 ms。完整报告见[原始数据](benchmarks/2026-10-10/cloud-stats-http.json)，包含程序 SHA、版本、dirty 状态与相关源码摘要。这是无并行编译／其他负载的本机回环、合成历史和开发构建测量，不是跨版本发行构建比较、生产最大容量、上游请求负载或 SLA。临时测量驱动留在仓库外，不纳入正式测试命令。
