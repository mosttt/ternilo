# 文件写入与历史检索合同

## 空文件写入与历史一致

`write_file` 原本先写磁盘，再保留产物；产物存储拒绝空内容，使零字节文件已经落盘而工具报告失败。保留对象现在区分“现有引用”和“新对象的空字节”，空文件可存储、读取和恢复，文件清单及下载仍使用原事件与引用。普通上传附件保持非空要求，现有大文件保留上限不变。

写新文件时，先解析并校验已有的父级目录，再准备缺少的普通目录组件。创建父目录和写文件在同一拥有执行租约的阻塞任务中完成，调用方取消不会提前释放写入准入。工作区外路径、外部符号链接和只读权限不放宽；替换已有文件不隐式创建缺失目录。

新增端到端 Local 回归在修复前确认两个失败：文件已经写成零字节但嵌套工具返回附件错误；嵌套文件因父目录不存在未创建。修复后覆盖空写、替换为空、原历史版本、重启读取、父目录创建、越界路径、外部符号链接和只读会话。保留对象测试另验证零字节恢复与普通上传边界。

## 全文检索同时补充连续片段

SQLite `unicode61` 会把没有空格的中英混合片段作为一个词，短关键词因此可能漏掉。查询保留原 FTS 命中与相关性，并通过已持久索引的事件正文补充连续子串；两路在同一 SQL 查询中合并，每个事件最多出现一次。子串补充不以“全文结果为零”为前提。

会话、工作区、运行、类别、时间与结果上限使用同一组参数化筛选；FTS 结果优先，子串结果按事件时间排列。`instr` 不把 `%` 或 `_` 当作 SQL 通配符。片段从命中位置附近截取，避免只显示长正文的开头。没有新增索引文件、迁移或历史 JSON 回放；大范围短词检索仍需扫描符合条件的索引正文。

混合语言回归在旧实现只返回独立英文词，漏掉中文内的相同片段。修复后验证中文短词、中英混合、英文大小写、韩文片段、完整片段、整词优先、数量限制、运行／时间／工作区筛选、参数化查询及重启读取。Cloud 原有连续子串实现保持不变。

## 阶段验证

混合语言回归、文件相关测试、附件对象与既有会话归档检索共 26 项不同测试通过。Builtins、Local、Server 与 CLI 的 all-targets 严格 Clippy 及匹配程序构建通过。

`web/tests/model-gateway-browser-e2e.test.mjs` 经实际 Server 向 Node 提交 Rhai `write_file`，验证嵌套空文件的磁盘内容、文件页预览与下载均为零字节。实际历史查询接口同时返回中文内的英文片段和独立英文词，并命中韩文子串；手机文件页面截图验收通过，未发现非预期页面、控制台或 HTTP 错误。
