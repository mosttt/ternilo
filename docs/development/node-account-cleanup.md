# Node 账号撤销与执行端收尾

状态：功能实现及定向回归完成，Node／Server／浏览器验收已通过，正在进行平台 CI 和发布前检查。候选版本为 v0.1.3，尚未发布。OIDC 浏览器来源修复已独立合入本地 main，见 [OIDC 浏览器来源与公网地址](oidc-browser-origin.md)。

## 持久授权与清理通道

Server 在账号状态事务内保存清理请求，按账号状态版本、Node 和凭据实例定位。Gateway 保存输入的真实账号、接收版本及凭据证据；本人电脑和接收过该账号输入的共享电脑都能被定位。独立 `node_account_cleanup` schema 1 包含请求、输入授权和本机数据实例绑定，PostgreSQL 使用受限 runtime 授权。

Node 通过 `/api/v1/executors/cleanup/sync` 同步授权状态，以 `/api/v1/executors/cleanup` 提交回执。撤销凭据只能访问属于自身实例的清理通道，不能恢复普通连接、文件、模型或 Application 权限。每个凭据固定绑定本机数据实例；不同数据目录、其他凭据或错误撤销版本不能提交完成回执。

Server 绑定、接收证据、撤销水位和回执持久保存在本机。启动授权屏障在恢复会话之前安装，Account 及其自动派生任务等待同步；省略 gateway 参数不会改变来源。解封不会恢复旧授权输入；独立 Local 输入保持可用。

## 选择性收尾

清理根据可信输入来源进行，保留其他账号和 Local 的队列、目标、提醒及执行资源。输入接纳与授权同步互斥，避免旧授权消息在清理后才写入队列。撤销取消不会把其他作者的队列误标记为暂停。刚启动而尚未写入首条事件的任务，可以用持久队列中的作者证据识别。

归档会话直接写清理事件，不重新启动运行时。活动会话使用事件序号条件写入，避免重复删除提醒或覆盖其他作者的新目标；提醒目录和调度器从持久事件刷新状态。自动任务沿创建事件和子会话来源追溯，人工跟进保留独立输入身份。

Shell、后台 job、terminal 和外部 ACP 子任务在启动前登记执行归属，由独立监督任务执行取消、等待进程退出并释放目录占用。Unix 检查受管进程组中是否还有可执行进程；Windows 在恢复子进程之前绑定 Job Object，并独立查询进程列表确认退出。ACP 保留协议取消和宽限期，随后清理其外部进程树。正常关闭等待当前监督器完成；重启后缺少旧进程完成证据时保留 pending。

确认范围是 Ternilo 登记并监督的执行资源，不回滚任务已经造成的外部效果。普通 `CancelRun`、WebSocket 断开、Rust task 结束或进程信号已发送，都不能单独作为完成证据。

## 界面与验证

平台账号页按需展开“电脑任务清理”，显示 Node、空间、撤销版本、请求时间、确认时间和未完成原因。用户展开或主动刷新时加载，不在页面循环轮询。离线及未完成显示 pending；完成回执持久写入后才显示 confirmed。重复完成回执幂等，确认状态不能被迟到的 pending 降级。

已通过：

- Local 十项定向回归：混合作者队列、重新启动与解封、延迟接纳、归档会话、提醒目录、新目标保护、真实后台写入进程、未知旧进程，外部 ACP 子进程的选择性终止和目录释放，以及人工对子会话跟进的独立归属。
- SQLite 与受限 PostgreSQL 的相同账号／凭据／数据实例／回执隔离合同，包括重复提交和管理员读取权限。
- Builtins 155 项单元测试；Local 完整回归 214 项通过、1 项条件跳过；Server 125 项通过、5 项条件跳过。
- 实际 Node 保存提醒、离线封禁、原目录重启并持久删除提醒后提交确认，管理员网页从 pending 转为 confirmed；桌面／390px 手机布局、控制台和网络请求均通过。
