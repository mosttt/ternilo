# 角色模型与协作模式

2026-10-12。已实现会话插件中的独行、协行、并进，以及调查、实现、复核三个角色。协行默认 4 个并发子代理，并进默认 8 个，均可设置 1–32 的上限；统筹不占名额。Workflow 读取相同上限并分批执行，子代理总数、宿主准入和模型额度继续生效。

角色可继承主模型，或使用已保存的 Provider、平台授权和账号模型连接，并选择其支持的推理强度。修改角色不会修改主模型或账号默认值。调查和复核默认只读，实现继承父权限；子代理角色默认独行。已有子会话保持创建时的模型、说明和权限配置，续发仍收紧到当前父会话的权限与 Plan 模式。

Local 持久化角色配置并由宿主检查工具权限。Server 重建角色模型快照，忽略客户端与 Node 自报的授权；Node 子会话从 Server 父记录取得角色绑定。Worker 从已接受的父 RunSpec 创建子会话，入队校验规范子会话的模型、插件和权限，每次模型调用继续检查当前授权。

Cloud 核心 schema 保持 15，新增独立 `cloud_agent_roles` 组件版本 1 保存角色，不更改既有子代理 JSON 的严格格式。旧会话和旧子代理可在新增组件初始化后继续读取。运行账号的 PostgreSQL RLS 与无 DDL 权限保持有效。内部 Subagents 服务升级为 `ternilo/subagents@3`，所有内置消费者同步更新。

配置界面、角色展示、说明和错误提示提供中英韩文。模型选择器支持独立角色草稿及 Server 授权预览。手机可实际触摸滚动并访问保存按钮。另修复关闭通知时设置窗口跟随关闭的问题，通知被移除后迟到的外部点击事件也保持设置窗口打开。

验收结果：

- 37 项定向 Rust 合同通过，包括角色模型实际请求、只读写入拒绝、重启保留、SQLite／受限 PostgreSQL 的模型授权、旧会话存储保留、子代理续发／取消、Workflow 分批与结果顺序，以及真实 HTTP Worker 租约与撤权。
- Protocol、Kernel、Builtins、Local、Cloud、Control、Server、Worker 的全目标 Clippy 通过；三个执行程序构建通过。
- 前端类型检查、三语扫描、49 项配置／模型／Team 单元测试和 5 项设置窗口测试通过。
- 最终构建的两项实际浏览器合同通过：本机中英韩、320×560 手机原生触摸滚动与保存；Server＋Node、Server＋Worker 的角色模型和独立推理强度。页面、控制台和 HTTP 错误均为空。

测试使用临时目录、随机端口、合成账号及独立 PostgreSQL 容器。角色功能位于独立功能分支，不属于 v0.2.12。现有 Worker 继续兼容，Work 保持设计预留；资源迁移工作树未纳入本次修改。使用方式见[Agent 指南](../zh-CN/agents.md)。

续发兼容补查：Worker 按既有插件覆盖规则补齐子会话的执行配置，并固定采用子会话保存的模型。仅保存部分插件覆盖的旧子会话或显式覆盖配置可继续执行，不会在父会话换模型后误用新模型。SQLite／受限 PostgreSQL 的稀疏配置续发合同和 HTTP Worker 租约／撤权合同通过；实际 Node／Worker 浏览器执行也通过。
