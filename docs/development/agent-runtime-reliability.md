# 子会话同步与运行交互修复

## 修复范围

本轮处理 Server Node 子会话的网页配置同步、授权回答重复提交、Agent 预设查看与默认值的交互，以及 Responses 图像参数错误。当前为开发候选，尚未发行。

### 新子会话不能复用创建前的快照

Server 原先用资源同步的**完成时间**合并重叠读取。如果一个 Node 快照已经取得，但仍在写入 Server，刚创建的子会话请求会等待该次同步，随后误以为它已经覆盖自己。网页配置读取因此可能得到 `web access session is not registered on this Server`。

改为记录快照请求的**开始时间**：只有开始晚于当前读取请求的快照可以复用。较早的快照即使较晚提交，也不能代替新读取。认证、会话映射、父子来源、角色模型及凭据归属校验保持原规则。

新增真实 Node 传输回归，固定“旧快照在途 → 新子会话读取 → 旧快照提交”的顺序，要求再读取新快照并登记子会话。浏览器合同覆盖 Server 账号 Provider、手机授权、in-process 子会话、外部搜索执行、父子记录与凭据不落盘。

### 授权回答与预设查看

同一会话问题的并发回答合并为一次提交，提交使用操作开始时的会话；成功后立即移除已回答问题，再刷新元数据。Server 对问题所属会话的验证不放宽。

预设卡片主体原来直接设为默认。现在主体只查看，默认值由独立的“设为默认”按钮修改；“用于当前会话”和编辑入口仍单独保留。异步预设读取只应用最后一次请求，切换执行目标后不应用旧响应。

### Responses 图像复杂度错误

请求适配器只发送对话推理设置与已登记工具，不自动添加图像 `complexity`。官方[图像说明](https://developers.openai.com/api/docs/guides/image-generation)将图像复杂度与图像渲染质量区分；它不是对话推理强度。

对于 `image_generation_user_error`、`invalid_value`、`param=complexity` 的结构化组合，HTTP 错误与 SSE 错误均保留固定、安全的原因，提醒检查上游或中转的图像模型和复杂度设置。HTTP 502 包装不再导致同参数自动重试。任意上游正文仍不能穿过 Server 的错误脱敏边界；界面提供中英韩说明。

## 任务结束后的插件保存

main 的浏览器门禁在任务结束后遇到 409。代码审查确认，活动标识清除后，标题生成和状态收尾仍可能持有执行锁。配置更新现在区分运行中的任务和已经结束的收尾：前者立即拒绝，后者最多等待一秒，超时提示配置操作仍忙，不取消任务或跳过锁。

固定时序回归分别验证运行中拒绝、空闲元数据读取与已结束任务收尾。八项交互测试通过；真实本地／Server Node 浏览器分别通过 5.43 秒／9.08 秒，保留草稿、停止任务、手机保存及零非预期错误断言。

## 页面审查发现的完成重排

新增无代码块回答的阅读位置回归，复现流式结束时从第 20 段变为第 25 段，`scrollTop` 同为 12520。原因是先渲染整篇纯文本，再于完成时切换为 Markdown。现改为流式和完成共用安全 Markdown 结构，保留增长中的代码块处理；真实浏览器复验通过：无代码块和带代码块的回答均保持同一阅读段落，完成前后偏移小于 2 px。

子 Agent 的通用授权说明改为展示委派任务、会话权限限制及模型额度影响，不再只显示英文工具风险分类。具体策略拒绝原因仍保留原文。
