## PostgreSQL 请求取消修复

v0.2.21 正式 Release 的 Node 浏览器用例停在电脑离线列表，Server 日志包含 `cannot execute INSERT in a read-only transaction` 及后续事务已中止错误。SQLx 0.9.0 在收到 PostgreSQL 的 BEGIN 响应之后才增加事务深度；在发送 BEGIN 后取消调用，会使数据库已开启事务、驱动却仍认为深度为零。该连接随后回到共享连接池，污染下一次请求。

独立 PostgreSQL 最小复现等待服务端进入只读事务，再取消启动调用；原实现稳定得到与 CI 相同的写入错误。修复仅把 PostgreSQL 的事务启动交换放在独立 Tokio 任务内完成：调用方取消后，完成的事务自动丢弃并回滚，用户的后续 SQL 不会继续执行。正常读写事务仍由调用方管理，SQLite 保持原有行为，不增加数据库权限或改变租户作用域。

新增真实 PostgreSQL 回归验证取消发生后，下一个请求仍能写入并独立提交；与共享事务、受限账号初始化及 SQLite 合约共 8 项通过。该回归以数据库锁精确控制取消时点，已接入既有 PostgreSQL CI；存储模块 all-targets Clippy、发行元数据与签名脚本 4 项及 231 份 Markdown 检查通过。
