# 电脑间模型转发

状态：2026-10-03，源码与本阶段验收完成，待阶段发行。仅支持 Server 管理的远程电脑会话；不增加独立客户端的本地跨电脑模型入口，也不将可选 Worker 等同于 Work。

## 执行与授权

用户在 Server 中选择执行电脑 A 的会话，在模型目录中按需展开自己在同一空间登记的来源电脑 B。A 执行 Agent、文件和工具；模型请求从 A 经 Server 到 B，B 使用自己的 Provider 与 Key 调用上游，流式结果返回 A。绑定保存 B 的固定系统 ID，界面展示可修改名称。合成的已连接 Server 模型不能再次作为电脑转发来源。

首次指定来源要求拥有 B 和会话配置权限。协作者及服务账号使用已有绑定时，持续核验原始输入的实际提交者、资源权限和来源所有者的配置权限；每次上游重试必须取得新的 Server 许可。来源端还检查本机 Provider、模型配置和凭据变化。来源离线、撤权或改变配置时停止调用，不改用同名模型，不复制 Key，也不重放不确定是否执行过的请求。

## 传输与记录

执行器协议 47 包含独立请求、取消、流式结果、逐次报告和重试许可。每次调用固定到来源连接，陈旧连接不能注入结果。有界队列在超载或接收方断开时取消来源调用，任务完成后单独回收，不引发电脑连接重连。

不同 Server 实例使用 `/api/v1/internal/node/model` WebSocket，复用共享数据库的可信租约目录和集群密钥。HMAC 用途域与普通 RPC 分离，绑定正文、目标实例、租约、时效及随机请求 ID；校验来源所有者和当前连接，不进入可重放命令队列。输出、报告、取消及重试许可走同一通道。

独立 `computer_models` schema 1 保存模型快照、执行／来源电脑、实际提交者、模型所有者、资源原所有者和各次尝试。记录不保存提示词、上游地址或 Key。计数标为来源设备报告，与 Server 平台预算分开；未知计数不伪造为零，取消后的最终报告可继续结算。来源端不创建 Agent 会话，避免与普通会话直连报告重复。

“我的模型 → 用量 → 设备本地 → 跨电脑模型调用”按需读取当前空间内与本人有关的分页记录，可搜索并展开各次尝试。整机报告的电脑和月份筛选不作用于此独立记录。

## 验收结果

- 来源端 7 项测试覆盖真实 HTTP／WebSocket、Key 留在来源、工具原样返回、思考／正文流式输出、取消／断线、错误脱敏、重试等待及许可拒绝。前一基础阶段 Node 命令恢复、事件和附件回归通过。
- SQLite 与受限 PostgreSQL 共享合同通过：请求去重、逐次重试、实际作者／模型所有者可见范围、跨空间隔离、原生本地输入拒绝、来源撤权及迟到报告。
- Server 集群 8 项定向测试通过，包含原 RPC 合同与新增模型签名用途隔离、时效／重放、真实双 Server WebSocket、陈旧来源输出拒绝、重试许可、取消和断线不重放。PostgreSQL 旧集群合同本轮未重复执行；受限真实双实例流程另行通过。
- 真实 Chromium + 两台 Node：SQLite 单 Server、受限 PostgreSQL 单 Server及双 Server均通过。双实例中浏览器连接 A 实例、执行电脑连接 B 实例、模型来源连接 A 实例，真实模型工具循环、服务账号、工作区撤权、来源 Key 删除、离线及原身份重连均成功；无意外控制台或网络错误。
- 1440px、390px、320px 用量页面及展开明细已检查，无横向溢出。前端 39 项定向测试、TypeScript、259 文件 i18n、90 篇正式文档检查和相关 all-targets 严格 Clippy 通过。

浏览器验收同时修复模型菜单两个来源组件使用相同 React key 导致的重复渲染，以及受限 PostgreSQL 电脑名称批量查询生成 `?` 占位符导致的 500。后者已有多个 ID 与跨空间过滤的双库回归。测试数据库、浏览器路径及构建目录均为本机验证参数，不写入项目标准配置。

更完整的托管模型委托继续独立推进；电脑凭据轮换仍按用户要求后移。GitHub CI 和发行在功能达到阶段交付条件后集中处理。
