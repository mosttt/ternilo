# 电脑间模型转发实施记录

2026-10-02，优先级 1。用户确认仅支持 Server 管理的远程电脑会话，不增加独立客户端本地界面的跨电脑模型入口。

## 确定的执行方式

用户在 Server 中选择执行电脑及工作区，并选择另一台电脑提供的模型。任务的 Agent、文件和工具均运行于执行电脑 A；模型请求从 A 发往 Server，经 Server 转至来源电脑 B。B 从自己的 Provider 配置与凭据读取端点及 Key，实际调用模型上游，流式结果经 Server 回到 A。模型返回的工具调用继续在 A 执行。

来源电脑需要在线。Server 不复制 B 的 Key 到 A，不将模型请求改成在 Server 发出，也不在 B 离线时回退到同名来源。现有本机模型及已连接 Server 的账号／平台模型入口保持原有行为。

## 当前实施范围

来源电脑的调用端与执行器协议已实现。协议 46 增加独立的模型请求、取消及流式输出帧；模型调用不进入可重放的持久命令队列。来源端只解析本机 Provider，拒绝再转发合成的 Server 模型连接；线上请求不接受调用方提供的端点或 Key。调用前核对 Provider 协议、当前允许的推理值和当前输出上限。

来源端每条连接限制并发调用数量，完成任务单独回收，不触发连接维护任务的重连。取消向实际上游传播，连接结束时终止来源端在途请求。思考、正文、重试状态和完整结果沿模型帧传回；上游报错与重试文案清除私有端点和凭据内容。

已通过 Node 模块 28 项测试，其中 6 项新增来源模型验证覆盖：真实 HTTP 调用使用来源端凭据；思考与正文在完成前流式传回；工具调用原样返回且来源端不创建任务会话；取消与断线关闭上游；重试等待可取消；错误账号范围、协议变化、缺失凭据及调用方注入端点被拒绝；错误输出不泄露凭据。真实 WebSocket 验证同一连接先完成一次调用，再接受下一次并取消上游，电脑连接保持正常。原有命令持久恢复、事件及附件同步回归通过。

真实连接测试环境已补齐服务启动时创建的 `config.json`，没有改变产品对配置入口的要求。该基础实现不等于功能交付；目前 Server 尚未发起已授权的来源电脑调用，也没有开放界面入口。Server 拒绝无对应请求的模型输出帧。

传输协议 21 项测试及 Ternilo／Server／Transport all-targets 严格 Clippy 通过。90 篇正式文档检查通过，并同步当前协议号；不提供旧协议兼容。浏览器回归发现的相邻行悬浮卡遮挡菜单问题另在[工作台记录](workbench-performance-and-layout.md)跟踪，不能用来源端测试代替整体界面及双电脑验收。

## 后续闭环

1. Server 保存包含来源电脑系统 ID 的模型绑定，检查执行资源、实际提交者与来源模型授权。模型目录仅显示获准使用的来源与电脑名称。
2. 请求与来源连接绑定，支持有界流式传输、停止／断线取消和陈旧连接隔离；接入不同 Server 的电脑需要沿现有可信集群路由转发。
3. 完成持久调用记录、各次尝试及取消时用量归属；电脑上报的用量与 Server 直接观测的上游计量区分。撤权停止后续调用和重试，不复制 Key。
4. Server 模型选择器加入来源电脑；验证两台真实 Node 的工具循环、来源电脑离线、取消、撤权、同名模型隔离和浏览器交互。没有通过这组验收前，不将整个功能标为完成或可发行。

更完整的托管模型委托另行推进；本功能不扩展为独立客户端的本地跨电脑入口，也不等同 Worker 已支持电脑模型。
