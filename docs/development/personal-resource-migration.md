# 个人资源转入团队

2026-10-11。继续 v0.2.11 后的已确认资源迁移阶段；排除 `ternilo-work`，电脑凭据轮换、签名／公证与生产更新继续暂缓。当前为实现边界核对，尚未交付迁移功能。

个人空间不能添加其他成员。现有同团队管理权交接和同空间管理项目迁移均保留原空间，不能作为个人转团队的替代实现。`control_workspaces`、Edge／Cloud 会话、电脑凭据、上传游标和用量记录都使用空间身份；跨空间操作需要同时处理管理授权与执行绑定，不能仅更新项目字段。

用户已明确选择：选定工作区及其会话，转入已有团队，保留其余个人资源。原先考虑的整体个人空间转为新团队方案不推进。实现需要处理独立的团队管理权限与原电脑连接范围，不能通过改变整个个人空间的类型代替选择性迁移。独立项目和整台电脑的迁移保留为后续范围，不因迁移工作区而隐式搬走其他资源。

共同验收要求：只有原资源所有者发起，目标团队角色允许接收；迁移前显示范围与共享影响，提交时复核原状态；同名冲突和过期请求完整回滚；原有文件、会话历史和作者保留；旧入口、团队列表、权限组与 Live 刷新一致；电脑重连后继续工作；拒绝越权、只读成员和其他个人空间资源。历史计量及当前执行身份不能因管理归属变化而被静默改写。

使用独立临时实例和合成数据验证 SQLite、受限 PostgreSQL、真实桌面／手机浏览器及旧版数据升级。发行前先同步源码到 main，再从已同步提交打标签；公开产物验收记录随后补充，避免默认分支落后于 Release。

本轮已完成 schema、资源授权、Node 连接身份及用量边界核对，尚未修改产品代码。按用户追加要求，先整理[全部剩余任务](remaining-task-audit.md)，该选择性迁移仍是下一项实施目标。
