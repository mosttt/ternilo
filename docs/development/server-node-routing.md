# 跨 Server Node 路由与实时同步

状态：源码已接入连接持有者转发、合并变化提示和原 Node 凭据复核，已合并本地 main，尚未发布。定向 HTTP／SQLite、实际双 Server TCP 和受限 PostgreSQL 合同已通过；真实受限 PostgreSQL 双 Server 浏览器联调已通过，尚未发行。

## 实现范围

每台 Server 显式配置自身 `cluster_url`，共享同一数据库和 `secret_master_key`。租约目录绑定启动实例 ID、Node 租约 fencing token、原登记凭据身份及实例地址。只匹配未过期的当前租约；旧地址不会跟随新租约自动复用。原凭据、电脑或账号撤销后，转发和在线判断重新核验原身份。

其他实例通过在线 HTTP 通道向持有 Node 连接的实例调用。请求使用带用途域的 HMAC-SHA256，绑定完整原始正文、目标实例、租约版本、随机请求 ID、签发时间及期限。接收端只在自己持有的当前连接上执行，不再转发到第三台实例。签名、期限、重复投递和执行器能力检查在命令发送前完成。

HTTP 客户端关闭代理、重定向和自动重试。跨主机地址必须使用验证证书的 HTTPS；HTTP 仅接受字面量回环地址。转发丢失结果时返回未确认状态，不自动生成另一条命令。入口实例保存实际输入账号及其授权版本，连接持有者复核后沿用这份版本，不能把经过停用／恢复的旧输入刷新成新授权。Node 原有持久命令、账号启动授权、输入作者和回执语义保留；秘密、目录、文件内容及其他既有临时调用继续仅在线传递。

`gateway_cluster` schema 1 保存租约目录及每台 Node 一行的变化版本、原实例 ID 和到期时间。事件／上传与变化版本在同一事务提交；本地瞬时失效在当前租约下更新提示。心跳延长到期时间而不增加变化版本。提示没有事件正文、秘密、路径或 RPC 结果。

启用转发的 Server 每 250 ms 补读合并提示，复用现有 Edge Rescan 和权限复核，读取当前历史、状态及在线活动。补读基于每行单调版本，不使用 PostgreSQL 序号分配顺序当作事务提交顺序；突发更新合并为当前状态，历史仍从规范事件补齐。该机制不要求网页周期刷新工作台。租约过期、释放以及数据库恢复后触发重新读取。

## 验收要求

- 对端认证拒绝浏览器凭据、正文篡改、旧实例和旧租约；重复请求不能再发一条 Node 命令。
- 秘密请求和回复不进入持久命令或变化表，输入保留实际提交者和账号授权。
- 两个独立连接池之间读到提交后的变化、连续历史及撤销后的离线状态；回滚不提示。
- 真实双 Server HTTP 经连接持有者抵达 Node，响应丢失时没有自动重试。
- 受限 PostgreSQL 保持租户路由隔离，只对变化提示开放全局标识读取，运行账号没有 DDL。
- 浏览器连接非 Node 所在实例时能够工作，并在共享撤权后停止内容发送。

这不实现文件或执行身份搬迁、Work 容器调度、托管存储的跨主机接管，也不构成平台容量或完整故障转移结论。本机的受限验证环境不写入项目标准测试配置。
