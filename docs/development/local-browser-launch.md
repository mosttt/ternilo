# 本地服务自动打开浏览器

2026-10-02：按用户要求为 `ternilo serve` 增加本次启动的 `--open-browser`。默认不自动打开，开关不写入总配置，也不改变 Desktop 自行创建窗口的行为。

浏览器启动等待认证后的服务接口就绪，使用实际回环监听地址和端口，不向 URL 添加令牌。Linux 使用 `xdg-open`、macOS 使用 `open`、Windows 使用无控制台窗口的 `rundll32.exe url.dll,FileProtocolHandler` 调用系统默认浏览器。不添加新的平台依赖。

启动选项或已保存配置禁用了本地网页时，明确提示使用 `--no-local-web=false`，不打开不存在的网页。浏览器启动失败仅打印包含手动访问地址的诊断，服务继续运行；服务退出时取消尚未完成的自动打开任务。

验证覆盖有效动态端口、`--open-browser` 参数、URL 不携带凭据、配置不保存开关、普通重启不再次自动打开、浏览器打开失败仍可访问服务，以及已保存的禁用网页配置拒绝自动打开。本机 Linux 验证不能替代 Windows／macOS 实机发行验收。

自动打开功能首次验收时，本地客户端、Server 与 Desktop 构建通过。使用隔离实例捕获浏览器启动调用的地址并在真实 Chromium 中打开，动态端口、页面渲染、控制台和请求检查、无令牌 URL、启动开关不写入配置以及认证后的正常停止均通过。

首次验收的 `service_lifecycle` 4 项实际进程回归通过：服务认证与正常重启、禁用网页的管理服务、动态端口及启动开关不持久保存、浏览器打开失败不关闭服务。同次电脑管理 SQLite 5 项回归通过，PostgreSQL 专项采用此前独立的受限运行账号验证结果。

客户端与 Desktop 的 all-targets 严格 Clippy 及格式检查通过。中英文快速开始已补充用法，当前正式文档检查通过（88 篇）。

当前参数统一为 `--open-browser`。新编译程序的 `serve --open-browser --help` 成功且只列出正确拼写，错误拼写在参数解析阶段返回未知参数（退出码 2）。2026-10-02 运行权限恢复后，最新参数修正的实际进程回归 2 项重新执行通过：捕获真实动态服务地址、不含凭据、配置不保存开关、普通重启不再次打开，以及启动浏览器失败时服务继续运行。此前受限环境的未运行结果不作为此次通过依据。
