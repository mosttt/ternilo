# 会话交互反馈修复

本轮处理 Ask 选项滚动、个人默认模型、授权说明及切换会话缓存。资源迁移停留在 `baf93da`，不改动 `ternilo-work`。

## Ask 面板内滚动，操作区保持可见

390×844 复现中，旧面板高 1284px、顶部位于 y=-468；底部 sticky 容器将题目推到视口外，外层聊天滚动无法找回。现在限制面板高度，题目、选项和补充输入在内部滚动，翻页、跳过和提交留在固定底部。切题归顶，草稿不清空。

实际 CLI Chromium 验证已通过（20.04 秒）：中文手机、英文横屏、韩文窄屏的双向触摸滑动、最后选项、草稿保留、缩小输入视口和实际提交。截图已检查，包括 390×360 输入视口中完整可见的补充输入和提交。

## 个人默认模型同时用于接入电脑和托管会话

原入口只对托管新会话生效，而且 Server 拒绝保存 `profile_default`，界面没有清除入口。用户已确认：统一用于从 Server 在个人空间新建的会话；已有会话、团队空间及电脑本地默认值不变。

新增“每次新会话时选择”，以既有 `profile_default` 保存清除状态。保留未配置与明确清除的区别：旧账号未配置时继续继承电脑默认值；明确清除后，Server 创建的新会话回到预设模型状态。账号 Provider 在电脑会话中使用明确的 `account_provider` 身份与 Server 授权快照，不把同名账号 Provider 当作电脑本地 Provider。

创建前验证默认模型，创建后完成既有会话模型配置流程才返回；配置失败清理本次新建会话。普通新会话的空白复用读取同一有效默认值，避免重新打开模型不同的旧空白会话。原有电脑默认读写入口保持原含义。已有可用模型时，未选择状态提示选择模型并直接打开选择器，不再要求重复配置。

## 授权说明改成简短自然段

Shell 工具要求用用户语言给出一句话或短段，说明要做什么、为什么需要，以及重要影响；新调用以字符串提供 `approval`。旧版三字段对象仍可执行，并作为一段显示。历史和底部授权卡共用组件，完整命令保持默认折叠，权限和单次批准语义不变。

## 切换会话保留已加载的历史

原缓存只接收完整结束的初始化读取；较早历史页较慢时，切走会丢弃已显示的部分。现在逐页保存游标，允许缓存已接受的部分历史；切回立即显示，并从已有游标续读。不重复读取最新页，旧的已取消请求不能覆盖当前状态。账号／空间隔离、撤权清理、8 个会话与 24 MiB 内存上限保持原逻辑。
