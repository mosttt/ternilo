# 插件集中配置与团队协作设置

2026-10-13：将插件配置集中展示，并在 Agent Team 面板直接提供当前会话的协作设置。资源迁移与恢复仍保留在独立工作树，本项不改变相关数据模型。

## 实现

插件默认页改为集中配置，只展示有 schema 字段或已有 JSON 配置的插件，支持本地化参数搜索和快速定位。集中页与折叠配置页复用同一组卡片，搜索仅隐藏卡片，避免丢失编辑状态；插件列表与扩展包入口保留。

团队面板通过现有会话插件配置组件展示内置子代理参数，复用角色模型选择、会话覆盖、启停、恢复继承及运行中保存保护。入口仅提供给具有配置权限的用户。共享草稿位于工作台生命周期内，按账号／空间、执行目标及插件 ID 隔离，切换设置入口和弹窗生命周期保留草稿，重新载入网页丢弃草稿。持久配置变化会更新草稿基线，防止恢复继承后旧草稿复现；插件写入在同一会话的多个入口之间共享保存锁，禁止并发提交，避免覆盖列表互相覆盖。

核对运行时后明确：`coordination.max_parallel` 的名额在任务完成后释放；`max_children` 的名额跟随保留的 Child 实例，关闭实例后释放，并不是历史会话配额。界面提供三语名称、说明和两者较小值的有效并发提示，不修改运行时限制语义。

团队刷新与关闭按钮统一为 40×40 并对齐，弹窗打开聚焦标题，避免默认聚焦刷新按钮造成外框常显；保留键盘焦点反馈与刷新中动画。

## 2026-10-14：跨 Server 撤权合同

## 2026-10-14：无工作台页面时的 Node 角色任务

独立验证确认，普通 Node 会话也会在离开工作台后丢失新子会话的模型同步：0.2.14 候选程序创建了调查子会话，但未调用其配置的角色模型。此前有页面持续刷新时会顺带登记新会话，掩盖了这条执行依赖。

账号 Provider 与电脑转发模型的入口现通过已认证的 Node 连接主动补齐缺失会话，登记使用真实电脑拥有者，继续校验原有绑定、父子来源、输入作者与当前模型／资源授权。同步沿用现有有界等待；合并并发快照后仍未登记的会话会在等待循环内重新核对。正式平台协作合同增加离开工作台后执行子任务，并检查角色模型、推理强度和实际子任务回答。此修复属于普通协作执行，不包含资源迁移入口；匹配的 0.2.14 程序已通过完整 Node／Worker 浏览器合同（27.51 秒）和受限 PostgreSQL 双 Server 无页面执行（16.89 秒），检查实际子任务回答，错误列表为空。电脑身份保护测试、41 项工作台回归及 Control／Server 全目标 Clippy 通过；完整 CI 继续作为发布门禁。
