## 公开程序的浏览器验收

使用实际下载的客户端与 Server，在隔离实例和受控模型端点上执行九项浏览器用例，覆盖：

- 本机／Server、桌面／手机的归档恢复、委派后代联动、单条删除、共享只读权限和工作目录保留。
- 账号与设备 Provider 隔离、原作者授权、后台子任务、Workflow、取消与撤权，以及消息批次。
- 同一父轮次对同一子 Agent 连续追问三次、独立运行 ID、来源链和活动状态；手机网页授权及错误会话回答拒绝。
- ZIP、完整截断文本和 65 MiB 工作区原文件下载，规范历史版本、离线反馈、权限与撤权边界。
- 中英韩插件集中配置、详情、协作设置的共享草稿与写入锁，延迟保存、迟到配置投影、恢复继承和手机布局。

首轮七项通过，两项失败。Provider 用例在共享协作者点击授权时报告 Chromium `Target crashed`；子 Agent 网页用例完成父子任务及搜索后，因控制台记录一次 Live WebSocket 连接错误而失败。单次定向诊断复验保持相同公开程序、浏览器、断言和等待上限，只增加浏览器事件与握手记录；两项分别在 78.73 秒和 4.43 秒通过，没有页面崩溃、页面异常或控制台错误。

这两次首轮异常的根因尚未确定，分别保留为[调查项 45–46](remaining-task-audit.md)。诊断复验中，Provider 场景记录到切换期间建立前关闭的连接及后续成功握手；手机子 Agent 场景记录到一次成功握手，未重现原连接错误。后续若再出现，继续采集进程退出原因与连接关闭时序，不放宽产品断言。

九项功能均取得通过证据。已检查公开程序的文件下载、主子会话、共享任务空状态、三语插件设置和手机归档删除截图。插件配置、本机／Server 归档及子任务跟进的页面、控制台和相关 HTTP 错误记录为空。

## 正式跨版升级

使用公开 v0.2.31 客户端和 v0.2.33 Server，在隔离 Supervisor 实例中完成真实更新接口驱动的 0.2.31 → 0.2.33 升级。旧客户端的执行协议 51 与 Server 不匹配、任务连接不可用时，独立维护通道保持在线并接受更新。

更新使用正式签名清单和客户端包，新版启动人为延迟 45 秒。最终状态为 `completed`、版本 0.2.33、执行连接恢复；本机健康查询一致。辅助进程释放操作锁后，重新启用原 Supervisor 更新配置成功；随后通过 Server 创建工作区和会话，实际写入文件成功。

## 升级边界

执行协议从 51 升为 52，Server、Node 和 Worker 需要配套升级。独立维护通道仍支持旧执行端更新；已启用维护的 v0.2.30 及更新客户端可从 Server 升级，更早版本需手动安装。

使用 Sessions 服务的自定义核心插件需适配 `ternilo/sessions@2` 并重新编译。新版可读取既有历史，数据库无需迁移；旧程序不能安全读取新增的 `source.kind=subagent` 日志，降级需要升级前备份。Desktop 安装器仍未签名，自动更新保持关闭。

本轮性能测量的负载、开发构建条件及完整数值见[会话生命周期与执行路径](session-lifecycle-performance.md)。更大规模压测、常驻运行时淘汰和完整 Cloud 插件投影增量化继续保留；历史调查项不因本版门禁通过而关闭。
