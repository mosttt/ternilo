# 运行中会话的插件保存提示

2026-10-11：用户反馈 `web-fetch` 配置长时间停留在“正在保存…”，要求确认与正在运行的对话是否相关，并提供明确交互。

## 原因与实施

本机和 Server Node 的插件覆盖保存调用 `LocalApplication::update_session`。重组运行环境时，`stop_live_session` 会等待任务持有的 turn gate；原逻辑取消待回答交互，但普通模型／工具任务仍可能持有该锁很久。它还会在等待前把运行环境移出实时索引，导致等待期间的运行状态暂时消失。前端一直等待 PATCH 及后续刷新，于是只能显示“正在保存…”。

插件变更现在尝试获取生命周期锁和空闲 turn gate，繁忙时及时返回 Conflict；不自动取消当前任务，也不进入等待运行环境销毁的路径。空闲检查与真正保存之间仍持有生命周期锁，避免新任务趁检查间隙启动。其余执行权限、计划模式及显式生命周期操作沿用既有规则。

插件页使用当前会话 Live 活动提示等待原因，暂时禁用保存、插件启停和移除覆盖；配置字段可继续编辑。具备停止权限的用户可以在同一页面点击“停止当前任务”，保存前等待实际任务结束，避免离开表单丢失编辑。停止请求复用现有队列读取和运行取消接口，后台仍检查权限。收尾阶段或实时状态变化引起的后端 Conflict 会转成当前界面语言的提示，并恢复可操作状态、保留编辑值。托管 Cloud 任务沿用配置快照机制，不因本机运行环境锁而增加这一限制。

直接打开 Server 插件设置页时，会复用共享 Live 客户端接收工作台活动，不要求先打开聊天历史；已有工作台继续负责自己的连接和订阅。取消／失败的结束事件可能早于 active run 清除，导致一次状态读取仍为运行中；现在在运行返回并完成队列结算后，再发送活动失效通知，保证停止后提示解除。

## 验证进度

运行交互 Rust 合同 6 项通过，包括忙碌时及时拒绝插件变更、待回答交互和运行继续可访问、用户主动停止后保存成功及运行环境再次打开。插件表单、插件设置和设置容器相关前端单元合同 28 项、类型检查、i18n、前端构建和 Local 全目标 Clippy 通过。

新的真实浏览器合同已进入 CI，使用独立 Local 和 Server＋Node 及受控长模型任务，覆盖等待提示、继续编辑、后端及时拒绝、运行和原配置保留、任务自然完成后保存，以及 320×560 手机在表单内停止后保存。匹配开发构建两项均通过，分别为 10.96 秒和 20.02 秒；忙碌保存拒绝响应分别为 5 ms 和 148 ms。直接打开 Server 设置页也通过，没有先载入会话历史的运行时。页面、控制台和 HTTP 错误均为空，桌面和手机截图已检查。

所有运行验证使用隔离目录、随机端口和合成账号，不操作用户的日常实例或真实数据。结果见[浏览器记录](benchmarks/2026-10-11/plugin-save-busy.json)。本项与未完成的资源迁移改动独立提交，将与空白会话管理一同进入 0.2.12 补丁版本；公开发行状态另行记录。
