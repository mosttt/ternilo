# 账号停用后的任务清理

状态：已实现，SQLite／受限 PostgreSQL、并发、真实浏览器和配套构建验收通过，已纳入持续回归。

## 当前行为

Server 管理接口将账号封禁／注销、凭据撤销与托管运行取消放在同一事务。使用 Server 保存的当前执行授权 `actor_user_id` 查找全部租户中未终结运行，包括派生运行，不用资源所有者或显示用户名代替执行身份。排队消息由其他成员编辑后，执行授权转给编辑者，历史 `input_provenance` 仍保留最初作者；取消按当前执行授权处理。同会话其他账号的独立授权任务保留。

排队和尚未开始执行的运行使用既有取消路径，删除对应待处理项并释放预留；运行中的任务保持 `cancel_requested`，持久停止命令按执行代次去重，等待 Worker 报告真实结束。不能把断线、租约丢失或账号移除当成外部进程已停止。解除封禁不恢复已取消任务。历史事件、用量归属和文件效果保留。

新输入、编辑与启动前复检账号 active 状态。PostgreSQL 在事务中尝试取得与账号状态操作同键的共享锁；调用者可能已持有会话或预算锁，因此不等待账号锁。账号清理先非阻塞预锁全部目标会话和当前运行行，再预锁排队／未启动任务仍 active 的预留，全部成功后取消；不等待已被其他事务占有的运行或预留。避免与父子会话调度、其他账号的预算过期回收及共享队列操作形成锁环。队列编辑、删除和恢复先锁 canonical session，防止反向锁序和取消时丢失下一条任务的唤醒。争用时整事务回滚，最多 8 次、间隔 25 ms，耗尽后返回 409，账号仍保持原状态，需重试管理动作。SQLite 写事务在读取之前已取得写锁。独立 `cloud_account_cleanup` schema 1 组件安装按账号状态和管理职责限定的作用域发现函数及索引；受限 runtime 仍使用租户和资源所有者 scope 完成取消。

Local 和 Cloud 的普通 FIFO 批次只合并同一可信作者的连续消息。账号按稳定 `user_id` 判断，本机输入单独合并；Cloud 同时要求执行授权账号相同，不能把编辑后转给 Bob 的授权任务合进 Alice 的运行。自动任务类别和缺少作者不能证明共同创建者，因此单条处理。不能越过 Bob 的消息去合并后面的 Alice。消息、附件、引用和作者仍独立记录。
