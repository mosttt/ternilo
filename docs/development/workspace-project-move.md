# 工作区管理项目迁移

2026-10-11，继续已确认的资源迁移阶段，先实现同一空间内的工作区跨项目管理。功能及本机验收完成，准备随 v0.2.11 执行完整发行门禁；公开产物验收另记。

现有 `control_workspaces.project_id` 同时被 Cloud 会话、运行记录和电脑执行授权引用；历史运行与执行项目不可因整理工作区而改写。本阶段新增独立的管理项目登记，未迁移的工作区沿用原项目。工作台显示与项目共享继承使用管理项目，已有会话、文件、电脑绑定、执行项目和用量归属保留；文件／执行身份迁移仍属于之后的独立阶段。

只有当前可写管理者可以迁移。目标必须属于同一空间，目标项目内不能出现该管理者的同名工作区。请求携带原项目和单调版本，拒绝过期操作，包括迁移往返后的旧确认。迁移默认关闭项目共享继承；用户可明确选择采用目标项目规则，直接工作区／会话授权保留。事务同时写入管理项目、共享选择与审计，并通知各 Server 刷新权限和工作台。

按后端／HTTP、前端确认流程、SQLite／受限 PostgreSQL、实际桌面／手机浏览器的顺序完成。验证覆盖原项目授权失效、目标项目显式授权、历史和真实文件保留、Node 重新发现／重启、Cloud 原执行身份，以及权限拒绝、版本冲突和同名回滚。测试仅使用隔离临时实例、数据和合成上游。

## 实现与验证

`workspace_projects` 是独立初始化组件，不改写历史 Cloud 会话／运行的项目外键。工作台新增 `management_project_id`；原 `project_id` 继续表示执行归属，`GET/PUT /workspaces/{id}/project` 返回迁移版本及明确的执行项目。名称检查、共享继承、工作区／会话／搜索发现均按当前管理项目解析；旧的存储项目唯一名称索引由当前管理者／项目的事务命名锁代替。Node 重新发现保留已有迁移，重新登记和管理权交接也检查当前管理项目的名称。

SQLite 与受限 PostgreSQL 使用同一合同：当前管理者和只读角色、同空间目标、重名拒绝与审计回滚、默认关闭继承、显式目标授权、工作区／会话列表可见性、独立会话管理者、原 Cloud 执行身份与历史内容、往返后的过期版本拒绝、目标项目删除保护、并发同名创建，以及个人空间迁移和禁止个人共享的原子回滚均通过。最终 SQLite 0.81 秒、受限 PostgreSQL 2.49 秒；两库的既有管理权交接合同也通过。补充 PostgreSQL 首次运行在夹具连接前遇到临时容器启动切换的 TCP reset，改为等待 TCP 就绪后通过；此本机等待调整没有加入项目标准脚本。

相关前端 28 项测试通过；移除多余成功提示后，确认流程 3 项再验通过。类型、三语言、生产构建通过。Control／Cloud／Server 全 target／feature 严格 Clippy 通过；新增个人空间和并发用例的定向 Clippy 也通过。Node 发现 1 项、项目共享 2 项和服务账号只读／执行边界 1 项回归通过；一次 `workspace` 名称过滤未匹配测试，不计为已运行验收。

匹配 v0.2.11 CLI／Server 的实际 Chromium 验收通过，11.65 秒：从桌面迁移并关闭继承，原项目读者移除且不再收到后续任务事件，真实文件和历史保留，Server 继续向原 Node 写入，Node 重启后项目登记保留；再在 320×560 触摸窗口滚动并移回原项目，显式启用项目共享后原读者恢复访问。取消与提交按钮完整可见且没有覆盖物，桌面／手机截图已检查。测试主动重启 Node 时的 503 仅接受重启阶段、当前会话接口且响应明确为 `unavailable / selected Ternilo node is offline`；其余 HTTP／控制台错误拒绝，页面异常为空。

另用公开 v0.2.10 Server 创建真实测试项目、共享、Node 文件及会话历史，再在同一临时地址与配置目录启动新程序，完整迁移与重连流程通过，14.67 秒。临时升级脚本已删除，没有固化本机路径或版本下载方式。记录见[本机验收证据](benchmarks/2026-10-11/workspace-project-move.json)。正式浏览器合同和受限 PostgreSQL 合同接入既有 CI；178 篇文档、2 项版本元数据、23 项部署工具、5 项发行门禁检查通过。

本阶段没有实施个人资源转团队、文件／执行身份迁移、跨主机存储接管或故障转移。共享同一数据库的 Server 必须统一版本后使用管理项目迁移。
