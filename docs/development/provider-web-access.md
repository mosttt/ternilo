# Provider 网页访问

Provider 编辑页统一选择网页搜索和读取：会话插件、关闭、执行电脑服务或协议支持的模型内置工具。账号配置保存一次，执行电脑随当前 Provider 使用；模型内置工具仍由供应商执行。正式用法见[网页访问](../zh-CN/web-access.md#让网页工具跟随-provider)。

## 配置与执行

`ProviderProfile.web_access` 分别保存 `search` 和 `fetch` 的模式、服务参数及独立凭据引用。不存在此字段时保留既有插件与 `hosted_tools` 合同。新模式下，`web_access` 决定是否使用内置工具，`hosted_tools` 保留 Claude 的次数、正文及域名选项。DeepSeek 显式内置搜索只接受 `deepseek-v4-pro`，不自动降级。

配置应用在插件组合阶段，不增加另一套搜索实现。Provider 选择替换同名搜索／读取工具；能力被明确禁用时不重新启用。若已有同类实现启用，另一个停用的替代插件不表示禁用整个能力。仅抑制权限的 `blocked_web_tools` 随内部模型请求传递，避免由远端模型注入已禁用的内置工具；宿主工具权限同样约束供应商内置工具。文件与其他工具不受网页来源选择影响。

账号和跨电脑来源通过 `/internal/node/v1/model/web-access` 提供配置。实际搜索／抓取由任务电脑现有插件发起。执行电脑不保存网页 Key；每次调用按原输入、子任务及定时来源验证权限。新的 `NodeRunContext` 复用模型调用的身份与来源校验，不为网页调用伪造模型请求或预留模型 Token。

## 凭据边界

网页凭据与模型 Key 分开。接口核验登记电脑、会话绑定、输入提交权限和 Provider 所有者的配置权限；导出网页 Key 还要求执行电脑归该所有者。共享模型调用权不授权将 Key 交给他人的电脑。跨电脑来源只返回选定配置引用的网页凭据，不提供通用密钥读取接口。此 RPC 走既有临时投递通道，不进入 Server／Node 的命令日志，完成后也不保留内存回复；重连不能重放旧 Key。

插件请求的地址、服务种类和限制必须与选定配置一致，避免修改插件地址后带走原凭据。配置变化、凭据缺失或撤销明确失败，不改用模型 Key、其他来源或旧缓存。Provider 搜索与 DeepSeek 抓取可以明确共享网页凭据；改换搜索供应商使用不同的托管凭据名称，避免覆盖仍被读取功能引用的 Key。

平台 Provider 不向执行电脑导出凭据。托管 Worker 的电脑执行模式明确拒绝；继续使用已有独立插件或内置工具。仅授权模型的独立客户端连接不增加网页凭据导出权限。

## 界面与协议

中英韩共用 Provider 编辑器。集中与单插件配置显示 Provider 管理的生效值，编辑回到 Provider。高级选项保留独立网页地址、超时、结果条数与读取大小，不将模型中转地址视作搜索接口。

执行器协议为 50，Server、Node 与 Worker 需要同步升级；目录修订为 Builtins v22、Local v22、Cloud v5，当前 Worker policy 示例已更新。数据代次没有改变。

## 验证

协议与工具组合合同通过。6 项 Provider 网页合同覆盖替代插件、明确禁用、地址篡改拒绝和宿主权限传递到模型网关；5 项模型可用性合同包含模型来源离线时本机命令仍可运行、对话任务明确失败。SQLite 授权合同覆盖同所有者导出、他人电脑拒绝、无运行来源／伪造绑定／地址变更拒绝，以及网页凭据轮换和删除。Node 私有回复测试与 Server SQLite 日志合同确认网页凭据不进入内存完成缓存或持久命令日志。

最终真实浏览器 4 项共 107.41 秒通过：Provider 本机 26.50 秒、Server Node 28.52 秒；DeepSeek 内置搜索四条模型路径 28.77 秒、Claude 四路径 22.34 秒。Provider 流程覆盖三语配置、后续对话更新配置、已有替代插件、账号／跨电脑来源、切换 Provider、网页与模型 Key 分离、凭据删除、搜索／读取、402 和取消。跨电脑模型来源没有任务会话，执行电脑凭据库没有委托 Key。两个插件配置入口显示相同生效值；缺失凭据提示及手机／桌面截图已检查，页面、控制台与非预期 HTTP 错误为空。

既有独立 DeepSeek 本机／Server Node 及个人默认模型两类会话浏览器回归通过。相关 Rust crate 全目标严格 Clippy、Web 类型与三语检查、46 项相关 Web 单元测试通过；UI 凭据状态修订后的 9 项定向单元测试也通过。最终文档门禁覆盖 245 份 Markdown；部署工具 23 项、发行门禁 5 项和发行元数据 4 项通过。上游采用受控 HTTP 协议服务，不使用真实收费凭据。

PR 首轮 CI 的旧默认模型浏览器用例依赖加载期间短暂显示的“默认模型”。等待目录完成后，页面稳定显示“选择模型”，原定位器可确定性复现 30 秒超时。用例改为等待该稳定状态后操作；默认值保存、刷新和新会话继承断言及原等待上限保持不变，定向复验 3.09 秒通过。

第二轮 CI 的文件面板用例在打开 Server 空白会话后等待 `src` 超时。隔离诊断保留真实历史响应，在按钮按下后释放：空白历史完成将按钮从页头移到欢迎区，松开时原控件已卸载，没有触发 click，确定性复现相同超时。文件面板用例改为等待空白会话的目标布局后点击；预览、下载、原生应用、共享与撤权断言及原上限保留。正常流程 12.80 秒通过，延迟历史响应另作诊断，不进入项目标准测试。

并发 Rust 检查中，只读检查的超时用例返回了 `timed_out: true` 和空 stdout。原场景只有 200 ms，无法保证隔离登录 Shell 已执行首条输出；用例目标是保留已产生的输出，不是约束启动速度。场景改为 2 秒命令预算与 30 秒阻塞，保留 stdout／stderr、超时、只读权限和重启全部断言；生产超时行为不变。Local 库默认并发复验 240 项通过、1 项按原条件忽略，共 31.07 秒。

服务账号 SDK 回归发现已撤销的模型授权在网页配置准备阶段失败，任务已入队却尚未产生运行事件，SDK 因而等待至超时。实际复现确认队列带有 `model grant was revoked or expired` 且仍保留该输入。远端网页来源校验现置于接收任务前，已失效的来源直接返回错误；开始执行时仍刷新配置，离线非网页命令继续使用本机配置。5 项模型可用性测试覆盖离线对话不入队及离线 `/code` 入队执行，严格 Clippy 通过。

匹配 v0.2.29 程序的最终三项浏览器复验共 65.74 秒：Provider 本机 23.84 秒、Server Node 28.51 秒、真实 TypeScript／Python SDK 与服务账号撤权流程 12.27 秒。原 SDK 与授权断言未修改，页面、控制台及非预期 HTTP 错误为空。

模型断线验收的故障注入代理原先只识别 TCP 连接上的第一个请求。网页配置读取复用该连接后，后续真实模型请求未被标记，断线注入因找不到连接而失败。新增同一 keep-alive 连接先读元数据再请求模型的用例，在旧代理上确定性失败；代理现使用 HTTP 请求解析并即时转发响应头，WebSocket 控制连接独立转发。新用例与原关闭浏览器／模型断线验收均通过，共 13.63 秒；产品传输和原有断言未改。

v0.2.29 发行候选同步更新 Cargo／Tauri／镜像示例与签名兼容范围。Executor 50 的首次升级需要 Server 与接入端统一更新，不能跨旧协议远程升级。GitHub CI 与公开成品验收由发行流程继续完成。
