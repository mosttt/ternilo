# 工具定义按需加载

2026-10-12。`ternilo.tools.registry` 增加可选 `schema_loading` 配置。启用后，常用工具直接可用，其他工具通过 `search_tools` 按名称或关键词发现并加载当前 Schema；缓存满后移出较早加载的附加定义。默认保留 32 个附加定义，可设置 1–128；单次搜索最多返回 16 个。

工具目录与定义都来自当前注册表。工具卸载后不可继续查找，相同名称重新注册时使用新 Schema。查找只改变会话中的定义缓存，不执行目标工具，不授予权限，也不改变审批和宿主校验。未启用目标模式的 `update_goal` 不参与发现。显式用户命令仍可调用已登记但未加载定义的工具；Code-only 模式的直接调用限制保持有效。Code Mode 的 SDK 描述与当前加载集合同步。

界面在“设置 → 插件 → tool-registry”中提供中英韩开关和保留数量。默认不开启，已有配置继续原行为。父子会话及 Local、Server＋Node、Server＋Worker 使用同一注册表实现。

两项 Rust 合同通过，覆盖 32 工具合成目录的首次定义体积降低超过一半、加载和淘汰、Schema 更新、未知工具拒绝、权限撤销以及显式命令／Code-only 限制。Builtins 与 Code Runtime 全目标 Clippy 通过，前端类型／i18n／7 项配置卡合同及构建通过。

完整执行程序的两项浏览器合同通过：中英韩设置保存及本机实际“查找定义 → 调用工具”；Server＋Node 和 Server＋Worker 也完成相同模型调用流程。首次请求不包含 `list_agents` 定义，调用 `search_tools` 后的请求包含该定义并成功执行，页面、控制台与 HTTP 错误均为空。合成目录的体积结果不作为每个实际模型请求的固定节省比例。
