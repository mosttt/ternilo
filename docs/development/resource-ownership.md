# 资源管理权交接

状态：已实现同团队工作区／会话交接及前端确认流程，已合并本地 main，尚未发布。SQLite、Server HTTP、前端回归、受限 PostgreSQL 和真实浏览器联调已通过。

## 当前实现

`resource_ownership` 组件保存独立管理者和单调版本。现有工作区、Edge 会话、Cloud 会话的存储和执行字段保持原值；`ResourceAccess` 分别返回管理者、存储身份、管理版本和执行配置身份。资源发现、改名、共享、删除、分叉及工作台读取使用当前管理权限，电脑登记与 Provider／插件配置继续使用原执行身份。

交接限同团队的有效可写成员，当前管理者与版本必须匹配，数据和审计在同一事务提交。同名接收工作区、只读成员、过期版本和已取消登记的工作区拒绝交接。会话交接同时锁定父工作区，保证继承版本检查与工作区交接串行；Node 发现、创建、改名和交接共同使用工作区命名锁。界面需选定接收者并确认，默认显式保留原管理者为编辑协作者，也可取消此授权；已有独立共享不清除。改变这项选择后必须重新确认。

工作区归属影响同存储绑定下没有独立管理记录的会话。单独会话交接优先，后续工作区交接不会覆盖；当前管理者主动分叉时保留新分叉管理权，历史事件和原执行用户不改写。删除 Edge／Cloud 会话清理单独归属。`resource_ownership_live` 在事务内记录失效提示，复用跨 Server 权限通知，不写会话正文。

全局凭据、Provider／预设配置及插件启用审批不能把管理身份当成执行身份；新增 `ManageExecution` 明确区分。模型与执行的既有来源和授权继续生效，交接不隐式迁移执行账号或配额。

## 验证与交付

- SQLite 合同覆盖接收者筛选、重名与只读拒绝、回滚、管理往返后的过期版本、共享保留、继承与独立会话、分叉、存储身份、权限通知和删除清理。
- 原有 Edge 工作台、Cloud 共享、Control 共享／项目继承和 Node 发现回归通过，保持已有错误响应和绑定行为。
- Server HTTP 回归覆盖真实登录凭据、交接与版本冲突、当前管理者读取和改名、原 Node 凭据及绑定保留、拒绝新管理者写原电脑凭据、撤销协作访问和 Edge 归属清理。
- 前端类型、国际化、生产构建和定向交互回归通过，覆盖显式确认、版本字段、保留协作者选择、失败刷新和只读角色；相关 Rust 模块 Clippy 通过。构建产物写入独立临时目录，没有覆盖在线页面。
- 真实浏览器完成团队工作区管理权交接、原执行身份保留、保留原管理者的编辑访问及确认流程；页面、控制台和 HTTP 检查通过。受限 PostgreSQL 管理权交接合同通过。
- 已合并本地 main，可从当前源码直接编译；GitHub 推送和新版本发行尚未完成。

本机验收产物保存在忽略的 `target/workbench-validation/`。临时验证环境不作为项目标准测试流程。
