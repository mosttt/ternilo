# 独立客户端维护通道

任务执行协议变更不应切断电脑更新能力。维护接口 `POST /api/v1/executors/maintenance/v1` 使用独立协议 1，沿用电脑登记凭据、所有者权限和 HTTPS；不新增常驻进程，不承载任务、文件或模型 RPC。Executor 仍严格匹配自身协议版本。

客户端先完成既有数据目录身份同步，再通过 Hello 报告安装信息和执行协议，并通过 Poll 取得状态、开始或取消更新命令。默认每 3 秒轮询，状态变化立即上报；Server 以 30 秒租约判断维护在线。任务连接仅在执行协议匹配时建立。独立 Relay 入口保持原来的执行连接方式，不要求 Server 维护接口。

`client_maintenance` 数据组件保存维护身份及命令信箱，SQLite 与 PostgreSQL 共用合同；PostgreSQL 启用租户 RLS。命令只保存操作引用，不保存下载凭据。每次投递重新验证登记凭据；暂停、撤销、移除或账号停用不能凭尚未到期的在线租约继续接收命令。命令具有有效期，回复与实例身份绑定，重连不会重建已确认命令。安装仍沿用签名清单、缓存、空闲检测、独立安装辅助进程及服务管理器恢复路径。

更新状态区分维护连接与任务连接。任务协议不匹配但维护正常时显示“维护在线”和可更新原因；相同版本字符串但协议不同不能显示配套勾号。没有维护通道的旧客户端提示手动升级。进度完成要求新版的本机服务健康且实际恢复执行连接。

首次需要手动升级到 v0.2.30。发行策略以 0.2.30 为维护基线，后续只因任务协议改变不会提高最低客户端；跨数据代次或维护协议自身不兼容仍要求人工维护。Worker、桌面安装器、容器更新不纳入本通道。

## 验证

SQLite 与 PostgreSQL 的同一存储合同通过（1.12 秒、4.27 秒），覆盖所有者隔离、暂停拒绝、身份替换、状态／取消回复、回复身份不符拒绝、签名任务引用、下载授权、确认重放和离线租约。相关 Rust 全目标严格 Clippy、6 项 Node 连接测试、20 项 Web 单元测试、类型检查、三语检查和 Web 构建通过。

实际 Server 与受控维护端的三语浏览器验收通过（14.77 秒）：任务协议不匹配、没有执行 WebSocket 时仍可更新；在命令入库但尚未投递时重启 Server，新进程仍能投递同一命令。390 px 中英韩弹窗截图已检查，页面、控制台及非预期 HTTP 错误为空。

首次真实 Node 接入验收发现维护握手先更新凭据使用时间，导致后续首次存储身份绑定被拒绝。客户端已调整为维护握手前完成原有身份同步，保持“使用过但未绑定数据目录的凭据不可重新绑定”的校验。真实电脑管理浏览器回归通过（14.90 秒），覆盖首次接入、暂停／恢复、撤销／重新登记、持久凭据恢复及保留会话历史；该修正的 Node 严格 Clippy 通过。隔离签名升级闭环通过：以当前代码构建维护基线 0.2.30／执行协议 51，再仅在隔离源码中模拟后续 0.2.31／协议 52，并使用临时 Ed25519 签名。真实客户端在任务连接不可用时，经 Server 更新 API 完成签名包下载、版本目录切换和 Supervisor 重启；25.49 秒后 Server 确认完成及任务连接恢复，随后通过 Server 新建会话并实际写入文件成功。这里的 0.2.31 是协议变化测试构建，不是公开发行版。

v0.2.30 已公开，正式发行与公开成品验证见[发行验收](release-0.2.30-acceptance.md)。部署工具 23 项、发行门禁 5 项和发行元数据 4 项通过；全量文档链接检查覆盖 249 份 Markdown。

候选 CI 的原离线浏览器合同暴露了缓存状态问题：任务 WebSocket 已断开时，维护租约仍可有效 30 秒；列表和空闲更新弹窗没有继续读取状态，过期后仍保留旧勾号。两个新增单元回归在旧实现上确定性失败。界面现每 3 秒只读 Server 缓存状态，避免等待电脑 RPC；列表与弹窗共用最新任务／维护状态；后台读取成功不会抹掉更新操作的失败提示。23 项相关 Web 单元测试、类型及三语检查通过；实际租约失效的浏览器断言按 30 秒租约加刷新周期设置 40 秒上限，其他场景与测试总上限保持不变。

实际浏览器复验 3 项通过：真实电脑管理 18.84 秒、协议不匹配与 Server 重启投递 13.19 秒、Server 独立加载和真实离线租约变化 63.72 秒。已检查桌面维护在线及离线叉号截图，原任务、目录、三语布局和历史保留断言均保留。

后续 CI 已通过全部平台、Rust、SDK、PostgreSQL 及综合浏览器场景，随后发现 TLS 测试服务只接收旧的 HTTPS 身份同步路径，没有响应新增维护握手。测试服务已补齐协议 1 的 Hello／Poll 响应；原有真实 WSS 拒绝不可信证书、服务不崩溃、无 CryptoProvider panic 和 30 秒等待上限全部保留。定向测试 0.33 秒通过，生产证书验证未改变。
