# 模型转发保活与请求诊断

## 传输与运行生命周期分离

账号／平台模型的 Node、既有 Worker 及跨电脑模型转发共用 NDJSON 响应发送入口。响应首次发送空行，随后每 15 秒保活；已有消费者忽略空白行。保活不生成模型事件、不改变计量，不在断线后重放结果未知的请求。`x-accel-buffering: no` 与 `no-store` 保留，已接受请求通过 `x-request-id` 关联记录。

后台执行由已持久接受的提交驱动，浏览器订阅关闭只结束订阅。关闭 Server 浏览器与关闭电脑端模型请求是两件不同的事；电脑后台停止、模型连接失效及等待用户输入分别遵循原生命周期。

## 原因贯穿尝试和请求记录

取消前记录 `client_disconnected`、`server_stopping` 或 `request_authority_changed`，上游尝试与外层请求结算保留同一原因，公开接口使用固定枚举展示，不公开原始上游正文。输出通道关闭与监控任务竞争时，先记录原因再取消；已有确定用量仍结算，缺失用量不记成零。

`client_disconnected` 表示执行端 HTTP 模型连接关闭，可能来自主动停止或网络中断；没有额外意图信号时，不把它标为用户主动取消。历史通用取消记录不追溯猜测原因。

消费者从响应头保留有界、规范的 `mrq_` 请求 ID，通过现有错误文本合同附在失败原因之后。中英韩错误详情展示相应说明；Server 界面可打开已按 ID 搜索的“我的模型 → 用量”，本机界面仅保留 ID，不链接到不存在的 Server 页面。查询仍由原账号范围与分页接口授权。

## Responses 参数保持原工具合同

标准 OpenAI Responses 适配器显式发送 `strict: false`，避免上游规范化改变原 ToolSpec 的可选字段。原 Schema 不重写，Rhai／直接工具共用的必填与缺省语义不变；DeepSeek Responses 及其他协议不附加该设置。

## 验证

模型适配 41 项、网关消费者 2 项、Server 模型网关 9 项通过。35 秒静默上游跨过 20 秒传输空闲窗口后完成，只有真实模型内容被输出；断开、停机、撤权和计量合同通过。静默夹具的 Provider 总时限为 60 秒，产品时限不变。

前端定向 27 项、TypeScript、i18n 与生产构建通过。Builtins、Local、Server 与 CLI 的 all-targets 严格 Clippy 及匹配程序构建通过。

`web/tests/model-gateway-browser-e2e.test.mjs` 使用真实 Server、Node、浏览器及合成 Responses 上游，验证关闭整个浏览器进程后任务继续完成，重开可见结果；单独切断电脑端模型连接时，控制连接仍在线，请求与尝试保留同一原因及请求 ID，未知用量不记作零，也不自动重发。中英韩错误详情到请求记录的导航、手机／桌面布局和截图验收通过，未发现非预期页面、控制台或 HTTP 错误。该回归已接入现有浏览器验收入口和 Checks 工作流。
