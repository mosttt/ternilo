# v0.2.32 候选门禁与插件草稿竞态

v0.2.32 标签固定在 `5d58bdeed1b1de2a0e05f369f3cc728f670b9f3c`，没有公开发行。合并前六项 Checks 通过，但正式 [Release 门禁](https://github.com/mosttt/ternilo/actions/runs/42471864617) 的 Server 插件配置浏览器用例失败：从集中配置保存 128 MiB 后，详情中输入 96 MiB，输入被改回 128，保存按钮不可用。该发行已停止，原标签保留。

## 保存回调和配置投影需要分别处理

受控组件回归复现了三个完成顺序：

- 旧保存回调在另一入口已编辑新草稿之后完成，携带旧基线覆盖新输入。
- 配置基线的被动同步在另一入口提交新编辑后执行，覆盖该编辑。
- 保存已成功，但规范配置稍后才投影到页面；期间产生的新编辑被当成旧基线草稿清除。

只约束保存回调不足以覆盖后两种顺序。首个修复候选 `d16dee3` 的 [Checks](https://github.com/mosttt/ternilo/actions/runs/42478570539) 仍在英文 Server 用例中丢失输入；截图中的值回到 128。后两项受控回归也在该实现上失败。

共享草稿现在区分已接受配置与等待更新的来源基线。保存和恢复继承返回已接受的规范配置；确认写入后，“放弃修改”使用该配置。迟到的投影只确认基线，不清除后续编辑。配置键顺序规范化，避免序列化顺序不同被误判为配置改变。保存回调和被动同步都核对其观察到的草稿，不能覆盖期间产生的新草稿。

不同入口共享待写入状态，在保存期间禁止修改同一份配置；运行任务仅阻止保存时，仍保留可编辑草稿。集中配置发起的保存完成后，不折叠用户刚打开的插件详情。

## 验证与发行

36 项组件／设置测试通过，包括上述负向复现、接受后的放弃修改，以及延迟投影下的恢复继承。本机和 Server 实际浏览器均通过中英韩集中配置、详情、协作设置、继承恢复及手机布局；Server 用例延迟保存后的配置读取，再切换入口检查共享写入锁。页面、控制台和相关 HTTP 请求无非预期错误，截图已检查。

网络延迟夹具先释放并等待已拦截请求转发完成，再移除拦截器，避免移除活动拦截器造成测试自身的重复处理错误。未增加等待上限或跳过保存、继承及跨入口同步断言。

会话生命周期、执行优化、文件下载、子 Agent 轮次修复与此项修复一起随 [v0.2.33](../zh-CN/releases/0.2.33.md) 公开发行。最终候选的六项 Checks 和正式 Release 的 20 个作业全部通过；公开成品的 Local／Server 三语插件保存、延迟投影、跨入口同步及恢复继承验证通过，见[发行验收](release-0.2.33-acceptance.md)。
