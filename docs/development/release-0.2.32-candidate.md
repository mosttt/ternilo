# v0.2.32 候选门禁与插件草稿竞态

v0.2.32 标签固定在 `5d58bdeed1b1de2a0e05f369f3cc728f670b9f3c`，没有公开发行。合并前六项 Checks 通过，但正式 [Release 门禁](https://github.com/mosttt/ternilo/actions/runs/42471864617) 的 Server 插件配置浏览器用例失败：从集中配置保存 128 MiB 后，详情中输入 96 MiB，保存按钮持续不可用。其他语言和本机用例曾通过，失败与异步完成顺序有关。

受控组件回归复现了同一问题：先保存旧草稿，再切换入口并接收已提交配置，输入新值，最后完成旧保存回调。旧回调仍携带原基线，写入共享草稿后触发当前入口的基线重置，覆盖新输入。延长等待或重复运行不能修复这种数据丢失。

修复让写入完成只清理其启动时未变化的草稿；不同入口共享待写入状态，在保存期间禁止修改同一份配置。恢复继承使用相同的条件清理，不影响运行任务期间仍可编辑、稍后保存的既有行为。新增回归在原实现上失败；修复后的组件与设置集成测试通过。实际浏览器进一步延迟保存后的配置刷新，验证切换入口时共享写入锁；集中配置发起的保存完成后不再折叠用户刚打开的插件详情。

本次发行已停止，原标签保留。会话生命周期、执行优化、文件下载、子 Agent 轮次修复与此项修复一起进入 [v0.2.33](../zh-CN/releases/0.2.33.md) 候选，重新完成门禁后才发行。

修复后 33 项组件／设置测试通过。本机和 Server 的实际浏览器用例分别通过中英韩集中配置、详情、协作设置、继承恢复及手机布局；Server 用例明确延迟保存后的配置刷新再切换编辑入口，写入锁与后续编辑通过。页面、控制台和相关 HTTP 请求无非预期错误，截图已检查。
