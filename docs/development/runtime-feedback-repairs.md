# 运行状态与会话操作修复

2026-10-17：根据实际使用截图，优先处理 SQLite Server 连续事务错误，再完成运行中权限设置、子会话入口、子 Agent 启动反馈及离线状态展示。资源迁移阶段保留当前检查点，待本轮修复完成后继续。

## 问题与处理方向

- SQLite 日志持续出现 `attempted to call begin_with at non-zero transaction depth`，就绪检查和模型恢复同时失败。已通过 SQLite 整体回滚后的同错误复现；文件型 SQLite 池在复用前移除仍有异常事务层数的连接。后续写入、已提交数据保留和失败事务回滚已验证；线上首次触发回滚的原因仍需首次错误之前的日志。
- 运行中修改权限会占用会话生命周期锁并等待当前执行结束，历史读取也被阻塞。改为及时拒绝运行中的权限变更，提示完成或停止当前轮次后重试；空闲后仍可修改。
- Node 的子会话拥有本机 ID 和 Server 公开 ID。父会话事件中的绑定尚未转换，导致 Team 显示无法打开，而侧栏已有会话。统一通过当前访问权限内的映射转换，不按名称猜测会话。
- 主会话需要在子 Agent 启动及运行时显示明确反馈和入口，不要求用户注意侧栏变化。
- 电脑离线后，历史中的未结束轮次不能继续展示实时“深入思考”及增长计时。保留历史，显示运行状态待确认，重连后同步。
- 目录选择器增加上级目录按钮和实际路径，主目录不再成为视觉上的导航终点。
- 已完成的待办不再占据输入框上方；保留历史与投影。工具说明要求按实际完成情况更新，交付前核对，不能由界面自动把未完成任务改成完成。
- Markdown 本地图片引用接通既有工作区预览，限制在当前工作区并沿用权限、媒体类型和大小限制；未读取成功时显示提示和重试。Node 的 `<local-workspace>` 路径占位符也按图片目的地址解析，不破坏代码示例。历史版本附件保留原有读取语义。
- 文件页按工作区和路径归并生成记录，最新已加载版本作为入口，历史版本独立预览／下载；跨页合并不丢记录。

- 命令授权增加模型提供的操作、用途与影响说明，调用参数保留完整命令；输入区和历史共用展示，中英韩标签一致。说明不改变宿主权限判定，旧调用仍可执行；旧授权未提供用途时明确提示，不解析 shell 命令来猜测意图。

## 2026-10-18：历史初始化中断后的保留与重连

v0.2.17 公开程序验收发现：历史正文已到达、Live 初始元数据尚未完成时 Node 断开，元数据错误被作为历史加载错误展示，整个正文随之隐藏。控制器已保留事件，但界面的错误分支替换了正文；Node 恢复也没有主动重试首次失败的读取。

现在错误提示与已加载正文同时显示，重试期间保留可读内容，首次新历史页到达后再替换旧基线。浏览器连接或当前 Node 恢复时只重试已有失败；更早页失败沿原游标续读，不重复加载整段。授权撤销、会话不可访问和账号／空间切换仍清理内容；新增 REST 重试返回 403 的合同，避免保留策略暴露已撤权记录。无法确认运行状态时停止实时运行反馈。真实浏览器回归又定位到 Gateway 租约失效被错误分类为 PolicyDenied，会触发清理历史；现改为 Unavailable，旧连接的领取／提交仍被拒绝，真正凭据撤销保持原权限错误。移除迁移回执中已不再需要的错误转换。

34 项控制器测试通过，另 26 项聊天视图回归、类型和三语门禁已通过。浏览器使用真实 Server／Node，并在历史到达后的初始元数据帧注入与线上一致的 unavailable 错误、实际断开 Node；验证三语正文保留、无手动点击的重连恢复和新基线不重复，最终通过（104.59 秒），非预期页面、控制台及 HTTP 错误为空。已检查中文／韩文错误提示及英文完整对话截图，韩文 390px 窄屏仍可阅读和操作。Gateway 旧执行者提交拒绝合同和双网关租约／撤权合同通过（0.05 秒／1.28 秒）。该追加改进已随 v0.2.18 发行，v0.2.17 标签保持不变。

浏览器构建核对发现 Node 二进制仍含上一轮前端；首次长 Buffer 差异输出造成测试进程内存耗尽。核对改为直接逐字节相等判断并输出简短错误，重新构建匹配程序后通过；没有以测试跳过或放宽内容断言处理。最终证据见[初始化断线恢复验收](benchmarks/2026-10-18/history-initialization-recovery.json)。

## 2026-10-18：Provider 的余额、额度与限流提示

用户确认截图中的 DeepSeek 调用失败是上游余额不足，但界面只显示“请查看 Server 模型请求日志”。原因是模型适配器将 HTTP 错误包装为 Execution，Server 又将所有 Execution 文案统一替换；仅改网页不能恢复被抹掉的原因。

按 [DeepSeek 官方说明](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)为 400／401／402／422／429／500／503 建立固定、安全的处理建议，本机调用和 Server 代理共用。依据显式 DeepSeek 协议或准确的官方主机识别，不根据模型名字猜测服务商。402 明确要求为 Key 所属账号充值或换模型，共享来源联系模型提供者；不重试余额不足。

后续用户要求同时查询 OpenAI 官网。已核对 [OpenAI 错误码](https://developers.openai.com/api/docs/guides/error-codes)，补充 Chat Completions／Responses 的余额、组织支出、项目支出、组织批准使用额度、兼容 `insufficient_quota`、普通限速和突增限流。优先读取具体 `error.code`，再用宽泛的 `error.type`；不从原始消息猜测余额。账单／支出／额度失败不自动重试，明确限流和服务端故障保留既有重试策略。兼容服务使用中性“模型 API”文案。已有上下文超限提示保留，另区分 `service_tier` 参数限制。

Server 仅放行完整匹配固定白名单的说明，仍隐藏其他执行异常及任意上游正文；附加密钥或内部地址的拼接文本不能穿过该边界。公开模型 API 同步返回具体安全错误码，保持上游失败 HTTP 502 的既有语义。聊天错误卡、历史、轨迹和详情共用中英韩解释，不修改已存历史。

后端分类 2 项、真实 HTTP 尝试／取消／流式回归 13 项（1.84 秒）及 Server 白名单脱敏合同通过；前端 9 项定向测试、类型检查、三语门禁及生产构建通过。真实 Server／Node 浏览器合同通过（25.67 秒）：覆盖 DeepSeek 七种 HTTP 状态、OpenAI 七种余额／额度／限流原因、正确的重试次数、三语历史刷新和详情、390px 手机，以及公开模型 API 的流式／非流式拒绝。页面、控制台和浏览器 HTTP 错误为空；已检查实际桌面错误卡和手机详情截图。Builtins／Server 全目标严格 Clippy（5 分 09 秒）、格式、差异和 212 份文档门禁通过。证据见 [Provider 错误验收](benchmarks/2026-10-18/provider-error-diagnostics.json)。
