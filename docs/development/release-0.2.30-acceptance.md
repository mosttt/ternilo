## 首轮测试夹具竞态与收尾

正式发行首轮在 MCP 重连测试的 `StdioFixture::assert_stopped` 读取到空 PID，出现 `ParseIntError { kind: Empty }`。同一提交的 main 检查已通过。受控复现确认：重连保留上一代的写入标记，测试服务可以在后台子进程写完新 PID 前完成握手和工具回复；进程组停止后，空 PID 文件仍可能留下。全部打包完成后，仅对失败的检查作业进行一次完整重跑，其余已验证包与镜像保留，原断言和超时未放宽。

发布后的主分支修正了这个仅测试使用的夹具：父进程取得 `$!` 后，先通过临时文件与重命名发布完整 PID，再进入协议循环。即使复用旧写入标记并延迟子进程，受控验证仍能读取属于当前进程组的完整 PID。Builtins 的 204 项测试及测试目标严格 Clippy 通过；正式 v0.2.30 标签和发布产物保持不变。

## 升级条件

首次需手动将 Server 和接入电脑升级到 v0.2.30，保留原实例数据和电脑登记。手动升级若改变实际程序目录，按原服务管理方式重新执行启用命令并重启一次，以更新安装位置登记。旧客户端没有维护通道，不能仅更新 Server 就让它获得此能力。

维护协议 1、执行协议 51、数据代次 1；签名清单以客户端 0.2.30 为维护基线，Server 范围为 `>=0.2.30, <0.3.0`。后续任务协议变化可通过维护通道升级；跨数据代次、维护协议自身不兼容或客户端未运行仍需人工处理。操作步骤见[发行说明](../zh-CN/releases/0.2.30.md)与[客户端更新](../zh-CN/client-updates.md)。
