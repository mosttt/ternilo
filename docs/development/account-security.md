# 原生账号安全

2026-10-03：本阶段按用户优先级 3 推进邮箱验证、密码找回与 MFA。自助修改密码先形成完整流程；这些能力与现有服务账号、本站 OIDC 会话统一管理分别记录。

## 自助修改密码

已登录的原生账号在用户设置验证当前密码后修改密码，不接受目标账号 ID。密码计算在数据库事务外完成，提交时比较原密码哈希并检查账号仍处于活动状态，避免并发改密覆盖。更新密码与撤销本站原生／OIDC 浏览器会话为同一事务，提交后通知 Live 重新认证；保留账号、角色、空间、电脑凭据和资源。审计只记录操作者及撤销数量，不记录密码或哈希。

SQLite 与受限 PostgreSQL 合同覆盖错误密码、伪造目标身份、禁用账号、旧登录凭据／刷新凭据、重置前已经验证但尚未签发的登录请求、其他账号及原资源保留。两种数据库均通过真实 Chromium 的界面提交、错误提示、手机布局、退出与重新登录验收；前端账号设置 6 项测试、TypeScript、i18n 和文档检查通过。

## 邮箱验证与找回

已完成并通过验收：部署者配置 SMTP 和固定公网地址；仅向已验证的当前账号邮箱签发找回凭据。凭据采用随机、短时、一次性设计，数据库不保存明文。公开请求不泄露账号是否存在；找回后撤销本站浏览器会话。邮件链路使用 TLS，本地邮件投递代理可显式使用回环地址。开发验证只向临时 SMTP 接收器投递，不使用生产邮箱。

验证器与一次性恢复码已完成，覆盖原生登录与已绑定的 OIDC 登录；密码找回保留第二因素。双库、真实浏览器及运维恢复记录见[多因素认证](native-mfa.md)。


实现采用 lettre 0.11.23 的原生 SMTP／Rustls 传输，核对其官方 [TLS／STARTTLS 文档](https://docs.rs/lettre/0.11.23/lettre/transport/smtp/struct.AsyncSmtpTransport.html) 及 [OWASP 密码找回原则](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。公开找回响应在账号查询和投递前返回相同结果，避免同步 SMTP 时长泄露账号是否存在；队列容量不足返回统一服务不可用提示。验证、恢复及按来源／全站邮件请求限流使用双库持久状态，不依赖某一 Server 内存。


验收结果：SQLite／受限 PostgreSQL 均通过实际 SMTP 认证、验证邮件、一次性确认、找回邮件、改密、旧登录撤销、重放拒绝及限流；确认 SMTP 密码不回显、远程明文 SMTP 与非 HTTPS 公网链接被拒绝，TLS／STARTTLS 配置可构建。追加真实 OIDC 授权跳转后返回原邮箱验证页面、同一标签页更换找回链接的流程通过。测试没有调用实际邮件服务商，不代表某个生产 SMTP 账号的投递效果。

152 个前端测试文件／989 项通过，账号设置与会话回归 16 项通过；新增双库存储合同、原改密／运维恢复合同、相关 Clippy、TypeScript、i18n、依赖安全／许可证／来源与正式文档检查通过。同步维护 CI 的 PostgreSQL 和浏览器入口。新增邮件依赖的 quoted_printable 使用 0BSD，已核对随包许可证并纳入许可证允许列表；未放宽依赖安全门禁。
