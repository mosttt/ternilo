# 原生账号安全

2026-10-03：本阶段按用户优先级 3 推进邮箱验证、密码找回与 MFA。自助修改密码先形成完整流程；这些能力与现有服务账号、本站 OIDC 会话统一管理分别记录。

## 自助修改密码

已登录的原生账号在用户设置验证当前密码后修改密码，不接受目标账号 ID。密码计算在数据库事务外完成，提交时比较原密码哈希并检查账号仍处于活动状态，避免并发改密覆盖。更新密码与撤销本站原生／OIDC 浏览器会话为同一事务，提交后通知 Live 重新认证；保留账号、角色、空间、电脑凭据和资源。审计只记录操作者及撤销数量，不记录密码或哈希。

SQLite 与受限 PostgreSQL 合同覆盖错误密码、伪造目标身份、禁用账号、旧登录凭据／刷新凭据、重置前已经验证但尚未签发的登录请求、其他账号及原资源保留。两种数据库均通过真实 Chromium 的界面提交、错误提示、手机布局、退出与重新登录验收；前端账号设置 6 项测试、TypeScript、i18n 和文档检查通过。

## 邮箱验证与找回

下一步：部署者配置 SMTP 和固定公网地址；仅向已验证的当前账号邮箱签发找回凭据。凭据采用随机、短时、一次性设计，数据库不保存明文。公开请求不泄露账号是否存在；找回后撤销本站浏览器会话。邮件链路使用 TLS，本地邮件投递代理可显式使用回环地址。开发验证只向临时 SMTP 接收器投递，不使用生产邮箱。

MFA 尚未实现，后续必须同时覆盖原生登录与已绑定的 OIDC 登录，并提供恢复码；不能以密码找回绕过第二因素。
