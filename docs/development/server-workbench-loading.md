# Server 工作台与电脑加载分离

2026-10-24：用户反馈，重新打开 Server 时，上一台电脑连接慢会让整个页面停在“正在连接 Ternilo 内核”。原流程有两处等待：`/state` 先同步在线电脑资源，前端取得列表后又等待当前执行目标的 `/catalog`、`/agent-presets`，然后才结束全屏加载。

浏览器现在先请求 `GET /api/v1/state?refresh_computers=false`，读取 Server 保存的资源索引，仍执行当前账号、空间、资源授权和在线范围过滤。原接口省略参数时继续同步电脑，既有调用方不改变读取语义。Live 连接负责后续电脑资源同步；它与当前会话历史和配置请求不再阻塞 Server 列表及导航。

全屏状态只用于 Server 自身初始化，并明确显示“正在加载 Server 工作台”。电脑的历史读取显示在会话区，提示可以切换电脑或打开设置；配置单独加载，失败提供局部重试，不升级成整页错误。已有可读历史继续显示。切换会话会取消旧配置请求，空间、账号及请求代次共同阻止迟到结果覆盖新选择。Local 的初始化流程保留。

工作台刷新同样先提交 Server 索引，不等待电脑配置；配置刷新独立启动。侧栏的电脑下拉框仍只筛选列表，不隐式切换会话。打开工作区沿用下拉电脑的改动见[电脑选择](sidebar-computer-picker.md)。

验证：前端工作台 47 项回归通过，涵盖慢配置不阻塞、切换目标、迟到结果、跨空间／退出登录、局部失败重试，以及原有 Local、权限和 Live 防回退流程。后端两个 SQLite HTTP 测试通过：已连接但不回复的电脑不会收到快照读取发起的 RPC，已有在线过滤／完整同步读取也保持通过。

真实 Chrome 验证已通过隔离 Server／双 Node 流程：暂停当前 Node 后重新打开页面，在它恢复前完成设置往返和切换另一台电脑；配置请求返回 503 时保留会话内容，就地重试成功。新工作区分别在指定电脑上实际创建，手动选择、跨空间、离线和退出后换账号均按预期处理。中英韩版本提示、真实离线原因和默认电脑入口同时验证，控制台与网络无意外错误。已检查手机深色版本行、更新弹窗和三语言工作区选择器的实际截图。

浏览器复测发现退出时全局 Provider 缓存失效会同步唤醒旧账号面板，导致在令牌撤销期间重新请求模型目录和凭据。账号／空间切换改为清空作用域缓存而不通知旧订阅者重新加载；迟到的旧作用域结果以中止结束，不重试到新作用域。原有同作用域配置变更仍发布失效并刷新。工作台、Provider 目录和模型选择器 89 项测试通过，包含退出不唤醒旧消费者和旧请求不重试回填的回归；修正后完整浏览器流程在 32.96 秒内通过，控制台、页面和 HTTP 无意外错误。Server 成品内嵌当前 Web 资源，相关 all-targets Clippy、TypeScript、i18n、文档检查及构建通过。

测试夹具修正了同名关闭按钮的定位及模拟版本请求的退出时序。一次运行发生 Chrome 页面进程崩溃，后续带进程日志的复测未再复现；最终验收使用上述完整通过结果。电脑管理既有浏览器流程另已通过，覆盖版本显示、详情编辑、暂停／恢复和保留历史的移除登记。

发行回归补齐：同一执行目标后台刷新期间保留已有目录／预设，避免插件表单短暂失去 schema。未编辑字段随迟到的 schema 恢复继承默认值，用户手动修改和清空的字段保持不变；具体回归见 [v0.2.24 验收](release-0.2.24-acceptance.md)。
