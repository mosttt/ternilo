# Work 资源与执行边界

状态：设计预留，未实现。现有 Node／executor 身份、版本化传输、工作区路由和模型授权是接入边界。当前没有独立 Work 程序、管理页面、数据库资源或 Docker 调度器。

## 资源模型

Work 表示用户的一台托管电脑，不是项目、工作区或一次 Harness 运行。设计默认每个用户最多一个 Work，可通过额度配置增加；停止的 Work 仍占数量额度。一个 Work 对应一个持久 Docker 容器，可容纳多个工作区、会话和 Harness 进程。工作区之间不自动获得独立隔离或文件副本。

Work ID 独立于 Docker container ID。创建时绑定执行节点，节点上的宿主管理进程负责 Docker 生命周期；Server 负责账号归属、准入和资源路由。工作区复用项目归属和 executor 路由，但 Work 不得冒充已登记 Node，凭据类型分别核验。

## 容器边界

Work 容器彼此同级，不在容器内启动 Docker daemon，不挂载宿主 Docker socket，不授予特权容器或宿主命名空间。此设计不提供容器内 Docker。

基础镜像提供初始工具环境，不限制所有用户软件必须预装。用户权限、软件安装策略以及软件持久化方式尚未定义。工作区数据卷、容器可写层与重建后的软件环境分别管理，不承诺重建后保留未持久化内容。

Work 是个人执行信任边界；同一容器内的工作区不构成多租户安全边界。

## 接口约束

执行链路保留真实操作者、资源所有者、授权来源、模型绑定与额度结算。客户端、Server、Node 和执行节点使用匹配的协议版本。

停止任务、确认真实进程退出、释放执行名额和删除持久存储是不同操作。租约到期不替代退出证明；重连不重放未知副作用；未知模型消耗不自动退款。

现有 `ternilo-worker` 按任务启动子进程及 Bubblewrap，是独立的可选托管执行器，不实现“一 Work 一 Docker”模型。它的部署与运行方式见[Worker 指南](../worker.md)。

## 未实现的能力

节点资源盘点、Work 容器生命周期、用户数量额度、镜像管理及存储恢复均未开放。这些能力需完成独立实现和对应平台验证，才能作为受支持的产品接口发布。
