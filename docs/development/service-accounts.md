# 服务账号实施记录

2026-10-02，按优先级 1 推进。电脑身份／名称恢复和本站登录会话统一管理已验收并提交本地 main（`afda0a9`），本阶段继续补服务账号。

使用独立 `ter_sa_` 身份，保存于现有 Control 用户与成员引用中，保留资源作者与用量关联的一致性。服务身份不建立人类浏览器登录或伪装创建者。当前支持当前空间 HTTP 认证、`resource.read` 与 `run.execute`，不把同一凭据直接接受到 Live、模型 Key、账号或配置管理接口。已有成员权限和资源权限仍生效；成员降级时收缩执行范围。

服务账号与访问凭据使用独立 `service_accounts` 组件；PostgreSQL 使用租户 RLS 和生产运行角色 CRUD 授权。凭据仅保存摘要，对外创建时返回完整随机值一次，之后列表只返回元信息。空间管理员可改名、启停，凭据可设置范围和有效期、逐项撤销。停用可逆，已撤销凭据不可恢复；均不删除历史和资源。

管理界面位于空间管理。凭据只在打开详情后加载，一次性展示保存在组件内存，关闭详情或切换空间即清除。中文／英文文案包含启停与撤销的实际区别。

已执行：SQLite 3 项、受限 PostgreSQL 1 项、Server 权限与真实路由 2 项通过，另有 2 项受影响旧 Server 测试通过；严格 Clippy、前端类型、256 文件国际化和 Web 构建通过。真实 Server／Chrome 流程通过创建、按需读取凭据、读取／执行凭据的实际接口隔离、独立工作区及空白会话、启停、关闭清除、逐项撤销、1440／390／320 布局及英文手机页面，控制台和网页请求无错误。Python 与 TypeScript SDK 使用现有 HTTP 入口对真实 Server 验证身份、历史、资源隔离与管理接口拒绝，通过；无需新增重复认证接口。

这是服务身份与基础管理的闭环，未代替模型任务验收。尚需推进：服务账号管理已有资源的明确授权操作、模型授权与真正模型任务闭环、带明确范围的 Live／SDK `watch/run`、后续设备模型转发及托管委托。当前 SDK 的 HTTP 方法已可使用服务凭据，`watch/run` 仍使用 Live；前者的通过不能作为后者的完成证据。电脑凭据轮换继续后移。CI 与发行在功能达到适合发布阶段后集中推进。
