# 保存的登录设置读取失败

2026-10-05：用户在生产实例观察到 `/auth/config` 500，服务端报错 `execution: stored authentication settings are invalid`。公开只读请求确认 500；没有读取生产密钥或执行生产重置。

用实际公开 v0.2.3 程序在独立目录创建管理员、保存单提供方格式，再保留原配置和数据库启动实际 v0.2.6，复现同一错误。运行 v0.2.6 的 `admin reset-authentication` 后，公开登录配置恢复 200，原账号 ID、密码登录和原生会话保持有效，`config.json` 字节完全相同；主密钥没有重新生成。临时服务与目录已清理。

按用户此前要求，不增加旧格式兼容或自动迁移。恢复使用既有运维命令；不自动丢弃保存的设置，也不绕过 Turnstile。该命令清除网页保存的 OIDC、Turnstile 和 SMTP，保留账号、密码、MFA、模型及资源。双语正式恢复文档补充 Docker UID 10001 命令与准确的清除范围，说明数据库端配置错误不能通过清 Cookie 修复，避免误重新生成主密钥或改动数据库目标。

随后公开 `/auth/config` 返回 200，识别到新的 LINUX DO 提供方；真实 Chrome 验证用户名／密码表单和具名 OIDC 按钮正常渲染，无页面异常或 5xx。没有填写凭据或尝试登录；用户随后确认已恢复。
