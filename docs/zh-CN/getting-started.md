# 本地快速开始

[English](../en/getting-started.md)

按下面五步在当前电脑完成第一个任务。本机使用只需要客户端；从其他设备访问时，再按[远程访问](remote-access.md)接入 Server。

## 1. 启动程序

从 [Releases](https://github.com/mosttt/ternilo/releases) 下载当前系统的桌面安装包或客户端归档。使用桌面版时打开应用；使用命令行时，将可执行程序所在目录加入 `PATH`。本文命令统一使用程序名。

```sh
ternilo serve --open-browser
```

程序在本地网页就绪后打开系统默认浏览器，通常访问 `http://127.0.0.1:3210`。不需要自动打开浏览器时使用 `ternilo serve`，手动打开终端显示的地址。`--open-browser` 只作用于本次启动；如果系统未能打开浏览器，服务仍会运行。

保持启动终端打开，Ctrl-C 会正常停止服务。关闭网页不会停止任务。桌面应用已启动服务时，可用 `ternilo status` 查看其地址并复用，无需启动第二个服务。

界面按浏览器首选语言显示中文、英文或韩文；在“设置 → 通用”手动选择后使用保存的语言。本机网页自动取得连接凭据，不需要注册账号。

运行现成程序不需要 Rust 或 Node.js。文件搜索需要 `ripgrep`（`rg`）；Linux 上的命令、终端和后台任务还需要 `bubblewrap`。Windows 保留 `ternilo-sandbox-windows.exe` 在主程序旁，详见[包内程序](binaries.md)。本地管理端口仅供当前电脑使用，其他设备通过 Server 访问。

## 2. 选择工作文件夹，开始会话

点击“选择工作文件夹”，或侧边栏工作区旁的文件夹按钮，选择项目目录并打开新会话。之后选择已有工作区，再点击“新会话”即可。

文件与终端操作以这个目录为工作范围，访问其他位置取决于任务权限。项目文件保留在原位置；移除工作区登记不会删除磁盘文件。普通浏览器由后台服务检查路径，桌面应用使用系统目录选择器。

多个会话操作同一个目录时会共享真实文件。需要同时修改不同版本时，使用不同目录或工作树。通过 Server 共享电脑的目录协调规则见[远程权限](remote-access.md#断线数据与权限)。

## 3. 配置 Provider、模型和 API Key

打开“设置 → 模型 → 添加 Provider”。Provider 保存模型服务的连接设置，通常添加一次就能重复使用。

| 要填写的内容 | 示例／选择方式 |
|---|---|
| Provider ID 与显示名称 | ID 如 `my-provider`；名称用于界面显示 |
| API 地址 | 服务提供的根地址，如 `https://api.example.com/v1` |
| 协议 | 选择服务实际使用的协议，不确定时查看厂商说明 |
| API Key | 粘贴该服务的 Key；不要求鉴权的服务可留空 |
| Model ID | 从服务获取模型列表，或填入一个真实模型 ID |

API 地址填写根路径，不填完整 `/chat/completions` 或 `/responses` 请求地址。保存 Provider 后，在输入框下方选择模型，即可发送任务。没有可用模型时，界面保留草稿并提示配置。

支持的协议、Claude／Gemini 地址、上下文窗口、输出限制和推理档位，见[模型配置](models.md)。这些细节可以在跑通第一次对话后继续调整。获取模型列表由后台服务完成，不会把已保存的 Key 返回浏览器；不支持目录接口的服务可以手动添加模型。

保存后 Key 输入框会清空，再次编辑时留空表示保留原 Key，填写新值表示替换。模型配置与会话导出不包含 Key 明文。

### “凭据与登录”页什么时候使用

模型 Key 在 Provider 中填写。独立插件或其他服务需要登录授权、命名凭据时，再使用“凭据与登录”页；Provider 自动生成的凭据引用只显示状态，无需重复配置。同名环境变量提供的凭据为只读。

## 4. 验证真实模型

发送一条简单任务，例如“列出这个项目的主要目录，并说明从哪里开始阅读”。对话页会逐步显示模型输出与工具执行；需要详细排查时打开调用轨迹，查看请求、耗时和用量。

在输入框中选择所需权限。只查看内容时用只读权限，修改项目文件时用工作区写入；需要确认的操作会进入审批。目标不会自动启用，只有你在界面设置目标或使用 `/goal` 后才会持续推进目标。

| 遇到的问题 | 先检查 |
|---|---|
| `401`／`403` | Key、账号和模型权限 |
| `404` | API 根地址及服务要求的路径 |
| `model not found` | Model ID 是否准确 |
| 超时或重试耗尽 | 网络、代理、服务状态，再调整超时 |
| 工具无法执行 | `rg`、Linux `bubblewrap` 或 Windows 沙箱辅助程序是否可用 |
| 请求格式不兼容 | Provider 协议是否与端点一致 |

日常会话、队列、附件、审批和历史操作见[用户指南](user-guide.md)，联网问题见[联网工具排查](web-access.md)。

## 5. 数据与备份

应用数据与项目文件分开保存。默认应用目录为 `$XDG_DATA_HOME/ternilo`，未设置 XDG 时使用 `~/.local/share/ternilo`；自定义位置由 `--data-dir` 指定。目录内保存总配置、工作区登记、会话、模型和插件配置、凭据、附件及定时任务，分类见[配置与数据目录](data-layout.md)。

备份时同时保存完整应用目录和实际项目目录。先用 `ternilo stop` 正常停止服务，其他使用同一目录的 RPC／ACP 程序也应结束，再复制数据。外部 Profile、服务配置与环境凭据需要一并保存。备份含私密数据，应限制访问。

恢复时，停止目标目录的所有使用者，恢复整份应用数据与对应项目文件，再使用匹配版本启动。自定义目录示例：

```sh
ternilo serve --data-dir /path/to/restored-ternilo-data
```

检查工作区、历史和模型是否可用。异常退出的任务不会自动重做外部操作；恢复历史后先检查实际文件，再决定是否重新提交。连接 Server 的电脑还需恢复原登记和凭据，确认重新在线；Server 数据的备份见[部署与运维](deployment.md)。

## 查看、停止和重新启动

另开终端运行：

```sh
ternilo status
ternilo stop
```

自定义应用目录时，两条命令都加同一个 `--data-dir`。`status` 显示实际地址，`stop` 成功后才安全释放目录，供备份或重新启动。停止失败时查看原服务日志。

## 按需调整启动参数

默认值通常已经够用。需要调整端口、应用目录或执行配置时使用以下参数；优先级为命令行 > 环境变量 > 总配置 > 默认值。

| 参数 | 环境变量 | 用途 |
|---|---|---|
| `--listen` | `TERNILO_LOCAL_LISTEN` | 回环监听地址，默认 `127.0.0.1:3210` |
| `--data-dir` | `TERNILO_LOCAL_DATA_DIR` | 完整应用目录，查询和停止也使用它 |
| `--profile` | `TERNILO_LOCAL_PROFILES` | 额外 Profile；多个环境变量路径用逗号分隔 |
| `--max-steps` | `TERNILO_LOCAL_MAX_STEPS` | 额外执行步数上限，默认 `0` 表示未额外限制 |

```sh
ternilo serve --listen 127.0.0.1:3211
```

需要多个独立实例时，为每个实例指定不同端口和数据目录。一个目录由一个服务持有，网页与桌面可以共用它；远程接入也复用原目录，见[远程访问](remote-access.md)。
