# 用户指南

本指南介绍如何用 Ternilo 完成任务、管理会话和配置能力。网页、桌面和手机远程访问使用同一套工作台；可用功能取决于当前工作区的执行位置、权限和插件。

还没启动程序时，先按[本地快速开始](getting-started.md)操作。需要从另一台设备访问电脑，见[远程访问](remote-access.md)；安装和管理桌面应用，见[桌面应用](desktop.md)。

只在当前电脑工作，启动 `ternilo` 即可。想从一个网页管理自己的多台电脑或 VPS，再接入 Server；想让别人共同使用，再由实例所有者开启多用户模式并授权共享。部署者另外启用的 Worker 用于托管任务，自己的 VPS 并不需要因此改用 Worker。

## 完成第一个任务

1. 在侧边栏选择工作文件夹，确认后会直接打开新会话。这个文件夹就是本次任务的工作区。
2. 本地网页或桌面打开“设置 → 模型”；Server 网页打开侧栏“我的模型”。添加 Provider、模型和所需 API Key，或选择已经获得的平台模型授权，再在输入框下方选择模型。Server 用户设置不再提供模型栏目；本地设置保留该入口。没有可用模型时，工作台会提示配置并保留草稿。
3. 选择权限。只想分析代码时用“只读”；需要修改项目时用“工作区写入”。
4. 输入明确的任务，例如“阅读这个项目，说明启动步骤，并修复导致启动失败的问题”。可以同时附上文件、图片或工作区引用。
5. 运行中查看过程；遇到问题卡或审批卡时，按卡片说明回答。需要补充要求时，可排队发送或“停止并发送全部”；仅需中止时点击“停止”。
6. 阅读最终答案，查看文件变更和交付物。要了解具体调用，切换到“调用轨迹”；要带走完整记录，使用会话“更多 → 导出”。

本地浏览器和桌面可以连接同一个后台服务。关闭窗口后服务仍会运行；要停止整个本地服务，使用 `ternilo stop`，自定义数据目录时加 `--data-dir`。等待命令成功返回后，服务才完成收尾并释放数据目录。运行超过 30 秒仍未收尾时会明确报错；诊断步骤见[桌面应用](desktop.md)。

## 空间、项目、工作区和工作目录

Server 中的组织层级是：**个人／团队空间 → 项目 → 工作区 → 会话**。工作目录是工作区绑定的实际文件夹，不是会话的上级组织层，也不是 Ternilo 保存凭据和会话日志的数据目录。

| 名称 | 用途 | 例子 |
|---|---|---|
| 空间 | 区分个人与团队的资源、成员和管理范围 | 我的个人空间、产品团队 |
| 项目 | 在同一空间里组织相关工作区 | Ternilo 开发 |
| 工作区（Workspace） | 确定一处具体工作位置，绑定执行电脑或托管环境及文件存储 | 笔记本上的代码、VPS 上的测试代码 |
| 工作目录 | Agent 在执行机器上实际读写的项目文件夹 | `~/projects/ternilo` |
| 会话 | 在一个工作区内进行的对话、任务和执行记录 | 修复部署问题、调整侧栏 |

新建窗口里的 `Workspace` 指工作区，不应与个人／团队“空间”混称为工作空间。“新建项目”按钮只创建 Server 中的项目记录，不会创建同名文件夹。创建本机工作区时，选择运行电脑和该电脑上的目录，再给这个工作位置命名；创建托管工作区时，由平台准备对应的持久存储。

例如，“Ternilo 开发”项目可以包含笔记本和 VPS 上的两个工作区，分别绑定两台机器上的目录。项目名称相同不会使文件自动同步。同一工作区中的多个会话使用同一工作位置，打开新会话不会自动复制目录。单机 Ternilo 的常用流程直接选择文件夹并打开会话，不要求先操作 Server 的空间和项目。

团队权限组用于批量授予工作区／会话的具体协作权限；当前创建项目或加入团队并不自动开放全部工作文件。模型使用权仍来自个人获得的模型授权或共享会话允许使用的模型配置；创建空间、项目或工作区不会自动获得平台模型额度。

## 工作区与会话

工作区（Workspace）决定 Agent 从哪个文件夹开始读写。在侧边栏可以登记已有文件夹、创建工作区和会话、调整名称，并按工作区查看历史。移除工作区登记不会删除电脑上的项目文件；选择一个目录也不会自动获得目录之外的访问权限。

在本地 Ternilo 点击其他文件夹后，顶部“新会话”会在所选文件夹中创建。文件夹旁的“＋”始终在对应文件夹中创建会话。在空白会话里选择另一个工作文件夹，也会打开该文件夹的新会话，原来的会话不会被移动。

鼠标停在侧栏工作区上可查看位置；手机上打开工作区菜单，选择“查看位置”。点击路径即可复制完整目录，主目录在页面中缩写为 `~`。Server 中会单独标明执行电脑，真实目录只在电脑在线且你拥有该电脑时可查；离线时会提示无法读取。来自多台电脑的工作区会带有简短的来源标签。

在 Server 中打开工作区时，先选要使用的电脑或 VPS，再浏览那台机器上的文件夹。选择后返回确认页，工作区名称会按文件夹预填，可以修改；这里的名称只改变列表显示，不会重命名磁盘目录。页面同时显示归属、项目、电脑和完整路径。

选择已有项目，点击“打开并开始会话”；需要新项目时，在项目下拉框选择“新建项目”，检查项目名称后点击“创建项目并开始会话”。只想建立项目记录，可以点击“仅创建项目”，不会创建工作区或会话。一个项目可以包含多台电脑上的工作区。切换电脑会清除之前选的目录，避免把另一台电脑的路径带入任务。

尚未接入机器时，直接从提示中的“接入电脑”进入“我的机器”。托管环境选项仅在部署者启用托管执行时出现：

| 执行位置 | 任务在哪里运行 | 文件在哪里 |
|---|---|---|
| 托管环境 | Server 安排的 Worker 隔离进程 | 空间绑定的持久工作区存储 |
| 我的电脑或 VPS | 所选机器上的 `ternilo` | 那台机器上的所选文件夹 |

本地直连网页和桌面直接使用当前电脑，不需要登录 Server。会话创建后不会自动换到另一种执行位置。电脑离线时，Server 仍可显示已缓存的工作区、标题和可用历史，搜索也会保留云端及其他在线电脑的结果；必须访问离线电脑的操作会提示不可用。

云端工作区也有固定存储位置。Worker 离线时，Server 保留会话记录，但不会把任务自动迁到另一台机器的空目录。需要原文件的操作等待相应存储恢复；恢复或迁移由部署者处理。

侧边栏搜索可以匹配会话标题、消息、推理过程和工具记录。会话“更多”菜单提供重命名、分叉、归档和导出：

- 分叉从当前会话建立一条独立对话，继承模型、权限、模式、Agent 预设快照及会话插件设置，并建立自己的 Agent Team。
- 归档用于整理会话列表。侧栏工作区区域的“归档会话”入口可查看当前有权访问的归档记录；点击“查看历史”可在恢复前只读查看对话、思考、工具详情或原始事件，不切换当前聊天，也不执行任何任务。附件列出名称，文件内容在文件页查看；页面每次渲染 50 项。恢复保留原会话 ID、历史、模型及作者，不复制文件，也不自动启动任务、目标或队列。Server 上离线电脑只显示已经同步的记录，尚未同步的历史和恢复操作需要电脑在线。共享查看权限可以预览，但不能恢复他人的会话；已删除的会话不能靠此入口找回。
- 导出下载以会话标题命名的 JSON，保留完整会话记录。配置中的 Provider API Key、登录 token 和 Node 凭据不会随导出加入文件；自己写进消息或工具结果的敏感内容仍需检查。本地导出保留工作区路径，Server 中的“此电脑”导出会隐藏宿主绝对路径。

每个会话保存自己的工作区、模型、权限、预设、消息和任务状态。刷新页面或远程重连会恢复已有记录；浏览器窗口不是记录的唯一副本。较早的内容仍可通过搜索和导出取得。

多机器搜索会合并 Server 已知的标题、托管会话和在线机器返回的内容。某台机器离线、超时或暂时无法读取时，其他结果仍可显示，但结果可能不完整；没有搜到不代表那台机器没有相关记录，恢复连接后可以再次搜索。

## 权限与危险操作

在输入框下方选择当前会话权限；新会话的默认权限可以在设置中调整。

| 权限 | 读取工作区 | 修改工作区 | 工作区外访问 |
|---|---|---|---|
| 只读 `ReadOnly` | 允许 | 拒绝 | 拒绝 |
| 工作区写入 `WorkspaceWrite` | 允许 | 在沙箱范围内允许 | 需要本次明确审批 |
| 完整访问 `FullAccess` | 允许 | 允许 | 允许普通宿主操作 |

云端只提供只读和工作区写入。完整访问适用于本地电脑，不会被云端会话接受。

有些操作仍需单次审批，包括被标记为危险的 MCP/LSP 调用、定时任务、外部子代理、Workflow 和运行时扩展变更。即使使用完整访问，审批要求也仍生效。卡片会显示工具名、原因和本次参数；“允许一次”只批准这一项调用，不会批准以后的同名操作。拒绝、取消或没有有效回答时不会执行。

Plan 模式保持只读，审批不能让它绕过模式限制。点击“停止”可以取消当前模型生成、工具运行和等待中的问题；已经发生的文件修改或外部操作不会自动回滚。具体隔离机制见[安全模型](security.md)。

## 运行中追加消息

每条已发送的用户消息旁都提供编辑与“重新生成”，同批次的第二条及后续消息也不例外。模型返回失败后可以重试，成功后也可以再次生成；编辑保存后从该消息位置重新发送。保留前面的输入，替换所选消息及后续消息、回答，同时更新实际模型上下文，不在末尾追加副本。例如同批次为“1、12、3”，编辑“12”会保留“1”，重新发送修改后的“12”，移除当前对话中的“3”及之后内容。原始事件与用量记录仍保留，已经发生的文件修改不会回滚。原附件、引用和输入框草稿保留，使用当前会话的模型与权限。运行中或有待处理消息时先停止并清理队列；只读访问不提供该操作。

Agent 正在运行时，输入框提供两种发送方式：

| 方式 | 用途 |
|---|---|
| 排队发送 | 当前整轮（含工具调用）结束后，将当时等待的普通消息一起交给下一轮处理 |
| 停止并发送全部 | 取消当前执行，确认停止后，将所有待处理普通消息一起交给新一轮处理 |

默认按 Enter 排队，按 Ctrl/⌘ + Enter 停止并发送全部。可以在“设置 → 通用 → 繁忙时 Enter 键行为”中交换两者；输入框提示会显示当前规则。

Shift + Enter 换行，中文输入法正在选字时 Enter 不会提交。运行中输入新内容后使用停止并发送快捷键，会将新消息加入现有队列后一并发送；草稿、附件和引用为空时，只发送已经排队的消息。

输入框上方只显示待处理消息，不重复显示当前正在执行的内容；没有待处理消息时隐藏队列。各条消息可以编辑或删除，整个队列只有一个“停止并发送全部”按钮；空闲时显示“发送全部”。刷新或远程重连会恢复已有队列，不需要重复提交。

例如 A 正在执行时同一作者提交 B、C，A 结束后下一轮请求包含两条独立的 `user` 消息 B、C，不把文本拼接为一条；聊天记录也分别显示，作者、附件和引用各自保留。不同作者的连续输入分批运行，不能越过其他作者的消息合并后面的输入；身份不明确或自动任务无法证明共同作者时也独立运行。处理 B、C 期间新增的 D 留到下一批。普通停止与停止并发送都会保留 A 已产生的内容及文件效果，不自动重做 A，也不回滚文件。

“停止”只中止当前任务并暂停队列。之后点击“发送全部”或提交新消息可恢复处理，仍保持原顺序。相同文本的两次提交保留为两条独立用户消息，不去重。直接命令、技能与重新生成是独立执行边界，不与普通补充消息混成一轮；托管执行遇到不同模型、权限或预算配置时也会分批处理。

停止或失败后，已输出的思考内容仍可查看，但动效与计时会停在终止事件；刷新页面不会继续累计已结束轮次的思考时长。

问题卡是 Agent 主动请求的信息，与普通追加消息不同。请在卡片中选择或填写答案后提交；权限审批也应使用对应审批卡。在共享会话中，卡片是否可回答还取决于这项操作所需的共享权限，见[与其他人共享工作](collaboration.md#与其他人共享工作)。

## 会话指令与高级运行指令

输入 `/` 或点击输入框左下角的 `+`，打开会话指令菜单。模型与权限项打开现有选择器；`/plan` 在执行和计划模式间切换，`/export` 导出当前会话 JSON，`/feedback` 记录反馈，目标与压缩项使用当前会话实际提供的能力。前端选择动作不会作为普通对话发送给模型，也不会清空通过 `+` 打开菜单前的草稿或待发送附件与引用。

手机发送消息后不自动重新聚焦输入框，点击 `+` 打开菜单也不主动唤起键盘。需要继续输入时直接点输入框；选中需要填写内容的指令后仍可编辑参数。桌面保留发送后继续输入的快捷体验。

输入 `.` 打开高级运行指令，例如 `.agents`、`.agent-stop`、`.read` 和 `.skill`。带参数的指令选中后先填入输入框，补齐内容后再发送；无参数的运行指令选中后也先保留在输入框，再次提交才执行。菜单仍来自实际会话的同一份命令目录，执行使用既有权限检查。旧 `/agents` 等直接输入仍可解析，但高级项不再混入 `/` 菜单。

上下方向键循环选择，当前选项保持可见并显示确认提示；Enter 或 Tab 选择，Escape 或 Shift + Tab 关闭菜单。左右方向键仍移动光标，不会误选。中文输入法选字不触发菜单选择或发送。`.` 只在输入开头匹配指令，`./`、`../` 与未匹配的 `.env` 等不作为运行指令执行。`@` 文件与会话引用、附件按钮仍保留。

共享会话只显示当前权限可用的前端操作；后端仍独立检查权限。只有配置权限、没有发送权限的成员可继续从会话更多菜单切换计划模式，而不需要获得发送权限。

## 阅读过程与调整界面

欢迎页在桌面、网页和手机网页统一显示“让想法，动起来”。各可滚动区域共用主题滚动条，初始与闲置时隐藏，鼠标移动、滚轮、触摸或滚动按键操作时显示；恢复历史位置不会主动显示滚动条，也不会因此禁止滚动。系统强制高对比度模式保留可见滚动条。

桌面和移动端都在标题下显示“对话／轨迹”标签，保留标题下的工作路径。点击标签切换视图，使用键盘聚焦标签时可按左右方向键切换。

在工作台与文件、设置等页面间切换时，已有会话连接继续接收后续消息，返回工作台不因切页重新加载整段历史。换账号、换空间及登录权限变化仍会清理原目标；页面切换并不关闭安全校验或正常的数据更新。

对话正文独立滚动，顶部会话栏和底部输入框保持可用。发送消息后页面回到最新位置；模型尚未输出时不会主动滚动，任务结束后也不会因窗口高度变化重新跟随。新增输出会在你停留底部时自动跟随，一开始向上翻阅就暂停，即使只移动很小的距离也不会被拉回。主动滑回底部或点击“回到底部”后，可以继续跟随新内容。

“紧凑”视图会收起已完成轮次中最终答案前的过程消息、推理和工具调用，可逐轮展开；设置中可以改为完整显示。宽屏在对话区域最右侧固定显示已加载轮次的短横线导航，当前阅读轮次更亮、更长，悬停可预览、点击可跳转；标记过多时在导航内滚动，不随正文离开屏幕。窄屏隐藏辅助导航但保留内容。折叠不会删除记录。

“轨迹”用于检查模型请求和执行过程，可查看工具参数、结果、推理、系统提示、文件差异、耗时与用量，并使用搜索、筛选和时间线定位某次调用。输入框附近的统计显示上下文和 token 使用情况；不同 Provider 返回的详细用量可能不同。

展开“执行命令”后，可以阅读自动换行的完整命令，点击复制图标会复制原始命令，保留引号和换行。手机上复制按钮单独排列，命令不会被省略号截断。

每轮回答的用时、首 token 等待时间和输出速度集中显示在回答底部。消息操作旁只显示发送时间，悬停可查看完整日期；不会再次列出性能数据。点击“本轮用量”可展开该轮的模型、输入、缓存和输出明细。

手机上，反馈备注单独占一行，性能数据按完整项目换行。“本轮用量”也可以直接点开；横屏空间不足时，向上滚动即可使用回答操作。

设置中还可以切换中文或英文、浅色或深色主题、跟随系统，以及对话正文字号。这些外观设置不改变会话内容或插件能力。

将网页安装为 PWA 后，出现“刷新应用”提示时可以刷新到新界面；刷新页面不会停止后台已开始的任务。完全离线时只能打开公开界面，不能离线执行任务或从安装缓存读取会话历史。网络恢复后点击“重试连接”，页面会重新连接服务并读取记录。

## 遥测、导出与隐私

会话遥测默认关闭。设置中的模式决定是否向部署者配置的接收端发送记录：

| 模式 | 行为 |
|---|---|
| `disabled` | 不发送新记录 |
| `feedback_only` | 提交反馈时，发送从上次反馈释放位置到本次反馈的记录；没有反馈时不发送 |
| `full` | 持续发送经结构化敏感字段遮蔽的会话事件 |

输入 `/feedback <内容>` 记录会话反馈，不会把反馈交给模型；该命令不接受附件或上下文引用。反馈是否触发遥测取决于上述模式。

发送的记录可能包含提问、工具参数、执行结果和模型回答。结构化字段遮蔽不会保证自动识别正文中的所有敏感信息，启用前应了解接收方及其保存策略。手动导出会话与遥测是两个独立动作，关闭遥测不影响导出。

云端改为关闭后，尚未开始发送的批次会丢弃；已经发送中的一个批次可能完成，失败后不会继续重试。网络中断重试可能产生可识别的重复记录。凭据处理、事件存储及部署者配置见[安全模型](security.md#会话遥测)。

## 历史加载

历史中的流式文字片段、工具和状态都属于底层事件，数量不等于可见消息数。普通历史自动加载完整；超过 10,000 条底层事件时先加载最近 5,000 条，再提供“加载更早”，每次追加最多 5,000 条。单个接口请求最多 1,000 条，界面自动合并连续页面。新事件的实时游标独立推进，不会因加载旧记录而重复订阅已有历史。

同一账号、同一项目中的工作区显示名称应当唯一。不同电脑打开同名目录时，界面自动加入电脑标识，例如 `Pictures (d)`；这不会修改磁盘目录，也不会删除离线电脑的工作区和历史。手动填写重名会显示明确提示。打开工作区弹窗时加载项目和电脑列表，之后使用“刷新”更新，不进行持续轮询。
