# 工具与多 Agent 协作

Ternilo 可以调用文件、命令和外部工具，也可以用子 Agent、后台任务与工作流处理较长的工作。本页说明如何使用；安装和开发插件见[扩展系统](extensions.md)。

## Code Mode 脚本

Code Mode 的 Rhai 脚本通常由模型编写。手动编写时，保留字不能用作变量名；对象字段可以加引号，例如 `#{"path": "notes.txt", "old": "before", "new": "after"}`，也可以使用 `args["new"] = "after"`。普通函数参数按值传递，函数修改集合后应返回新值，由调用处重新赋值。希望某次工具失败后继续其他操作，可以用 `try { ... } catch (error) { print(error); }`。

运行过程中报错会保留此前的 `print` 日志和已经完成的工具操作。语法错误发生在执行前，整段脚本都不会运行，因此没有本次日志，也不会产生本次工具操作；错误提示会注明这一点。

## Skills

Skill 是一份可复用的任务说明。输入 `/skills` 查看当前目录，输入 `/skill review-code <任务>` 显式使用某个 Skill。模型先看到摘要，需要时再加载正文；Skill 不会额外获得文件、网络或执行权限。

要为项目添加 Skill，可创建 `.ternilo/skills/review-code/SKILL.md`：

```markdown
---
name: review-code
description: Review a code change
when-to-use: Use before merging a risky refactor
disable-model-invocation: false
user-invocable: true
---

# Review code

Inspect correctness, tests, security boundaries, and maintainability.
```

同名 Skill 按以下顺序选择：

| 优先级 | 位置 |
|---:|---|
| 1 | `<project>/.ternilo/skills` |
| 2 | `<project>/.agents/skills` |
| 3 | Profile 配置的自定义绝对目录 |
| 4 | `$TERNILO_HOME/skills` 或 `~/.ternilo/skills` |
| 5 | `$TERNILO_AGENTS_HOME/skills` 或 `~/.agents/skills` |

项目根取从工作区向上找到的最近 `.git` 目录，没有时使用工作区本身。每个 Skill 根也接受直接放置的 `*.md`。文件修改后目录会更新；符号链接不能越过已登记的根。安装扩展也可以提供 Skill，来源会在目录中标明，详见[扩展系统](extension-packages.md#静态-skill)。

## Plan、todo 与 goal

需要先讨论方案时，输入 `/plan` 或 `/plan <任务>`。Agent 可以读取上下文、维护计划、todo 和 goal，但不能修改项目，也不能通过 shell、终端、Workflow、子代理或扩展绕过只读限制。

计划准备好后，页面显示审阅卡。批准且本轮成功完成后，会话切换到执行模式，下一轮开始实现；拒绝、继续规划、失败或取消不会因此自动切换。也可以主动输入 `/plan off` 退出。计划和审阅决定会保存在会话中，刷新后仍可查看。共享会话的计划审阅需要“调整会话设置”权限；它与“发送任务”权限分别授予。

计划用于列出当前步骤，todo 用于维护待办。目标默认关闭，必须由用户通过 `/goal` 或目标界面明确设置；普通对话不会自动创建目标。未启用时模型工具目录与 Code Mode 不公开 `update_goal`，执行端也拒绝直接调用。完成或阻塞后，模型不能自行重新开启目标。`/goal <目标>` 会保存目标并立即开始执行；模型一轮回答后，如果目标仍未完成，会在同一运行中自动继续，直到模型记录已验证的完成、报告真正的阻塞，或用户停止。仅回复“稍后继续”不会结束目标推进，设置成功也不等于目标已经完成。

点击“停止运行”终止本次推进，未完成的目标仍保留；点击“继续目标”或发送 `/goal resume <目标>` 可明确恢复。刷新不会重新启动已停止的目标，会话重启或分叉也不会擅自恢复。浏览器刷新不影响仍在执行端运行的任务。要编辑或手动管理正在执行的目标，应先停止运行。

`/goal edit <目标>`、`/goal complete <目标>`、`/goal blocked <目标>` 只管理目标，不额外调用模型；启动和恢复需要可用模型。目标状态与自动轮次进入模型上下文，但不冒充额外的人类输入，也不改变原始任务的操作者或权限。

模型请求失败、输出截断或达到执行限制时会停止自动推进并显示问题，不会伪报完成。每次明确启动或恢复默认最多推进 256 个目标轮次，可通过 `agent-loop` 的 `max_goal_rounds` 配置，0 表示不加此项上限；宿主步骤、工具与模型授权限制仍然生效。真实模型可维护计划与 todo，并在用户明确启用的目标范围内更新目标状态。

## 子代理、后台任务与终端

复杂任务可以拆给子代理。默认内置子代理可在后台工作；还可以通过配置接入实现 ACP v1 的外部程序。外部程序需要自行安装和配置，详见[外部 ACP 子代理](extensions.md#外部-acp-子代理)。

常用命令如下；真实模型也会调用相同能力：

```text
/agent <任务>
/agent-on <provider> <任务>
/agent-bg-on <provider> <任务>
/agents
/agent-send <id> <后续任务>
/agent-wait <id>
/agent-stop <id>
```

在会话的“Agent Team”面板可查看状态、打开子代理对话或停止运行。支持续发、且处于等待或失败状态的子代理会显示后续任务输入；无需等待主会话结束就能直接操作子代理。

向云端内置子代理补充任务时，如果它已经在运行，补充内容会进入该子会话的队列，当前任务结束后再执行。提交成功的后续任务会保留原提交者；子代理刚好在此时变为忙碌，也不会丢弃这条任务。

内置子代理保留独立对话和父子关系，可以继续对话并创建更下一层子代理。刷新、重连或服务重启后，已有记录仍保留；运行是否继续取决于执行端状态。外部 ACP 一次性进程只记录实际生命周期，其对话只读，不提供继续输入。云端同样保存子代理历史与谱系。

后台命令适合需要持续运行的 shell 任务。输入 `/job <命令>` 启动，使用 `/jobs`、`/job-output <id>` 和 `/job-kill <id>` 查看或停止；页面会自动更新任务状态。需要连续使用同一个终端环境时，使用 `/terminal-open`、`/terminal-send`、`/terminal-read` 和 `/terminal-close`。这些操作仍遵守当前沙箱、超时、输出上限和停止规则。

开发服务器等长期运行的程序应使用后台任务或持久终端。普通 Shell 命令属于有界执行；在 Linux/macOS 上，命令结束、超时或被取消时会回收其管理的进程组。终端的一次读取等待超时不会关闭终端，关闭终端才会清理它管理的进程。需要继续工作的程序使用这些受管理的入口，便于查看状态和停止。

定时任务支持延迟、指定时刻和周期执行。可以要求模型创建，也可用 `/schedule-after <秒> <任务>` 创建延迟任务，用 `/schedules` 查看、`/schedule-delete <id>` 删除。创建定时任务需要明确审批；任务记录会保存，实际触发需要对应执行服务运行。周期任务的间隔受插件设置约束。

接入 Server 的电脑使用账号或平台模型时，任务始终追溯原创建者并重新检查当前授权，采用触发时该会话明确选择的模型。Node 重启后，尚未派发的此类任务在网关连接就绪后恢复。停止当前执行不删除周期定时器；取消后续执行应删除定时器。已经持久化派发的一次性任务不会因重启而自动重试，避免重复产生文件或外部操作。

## 工具定义按需加载

在“设置 → 插件 → tool-registry”中开启“按需加载工具定义”，可以减少发送给模型的工具说明。常用工具保持可用，Agent 通过 `search_tools` 按名称或关键词加载其他工具的当前定义。默认保留 32 个附加定义，可设置 1–128；达到上限后，较早加载的定义会被移出，需要时可再次查找。

该开关默认关闭。启用后，工具权限、审批及 Code Mode 限制继续由宿主执行，显式用户命令仍可使用已启用的工具。工具定义缓存属于当前会话运行环境，不写入项目文件。

## Agent Team

在“设置 → 插件”中展开 `subagents`，可选择协作模式并配置调查、实现、复核三个角色。统筹始终使用当前会话的主模型；修改角色模型不会修改主模型或账号默认模型。

| 模式 | 默认同时运行的子代理数 | 工作方式 |
|---|---:|---|
| 独行 | 0 | 当前 Agent 完成任务，关闭子代理派生与续发 |
| 协行 | 4 | 统筹推进主任务，按需委派范围明确的辅助工作 |
| 并进 | 8 | 主动拆分独立任务，相互依赖的工作仍按顺序执行 |

协行和并进都可自定义 1–32 的并发上限，统筹不占该名额。未自定义时采用对应模式的默认值；已设置的上限在模式切换时保留。实际并发还受插件的子代理总数、执行资源及模型额度限制。Workflow 读取相同的并发上限，按批执行超出上限的任务，并保留原有结果顺序与取消行为。

每个角色可以继承统筹模型，或选择已保存的模型连接及其支持的推理强度，并填写补充说明。调查和复核默认只读，实现默认继承会话权限；角色设置不能扩大父会话的权限。只读限制由执行宿主落实。角色子会话默认独行，避免继续自动扩张团队。已经创建的子会话保留自己的模型和配置，父会话之后修改角色设置不会改写它们。

Server 会验证角色模型的当前授权；客户端提交的内部模型快照不能授予访问权。接入电脑与现有 Worker 执行沿用各自的模型转发、额度、取消和持久化机制。角色设置适用于内置持久子代理；外部 ACP Agent 的模型仍由其 Provider 配置。

从会话或子代理关系视图打开“Agent Team”，使用三个页面管理协作：

| 页面 | 可以做什么 |
|---|---|
| 成员 | 查看负责人和各层子代理、任务分配、状态及对话；向支持续发的子代理补充任务，或停止运行中的子代理 |
| 任务 | 新建或编辑共享任务，指定状态、负责人和依赖关系 |
| 邮箱 | 给指定成员发送消息，查看未读和已读状态 |

多个页面或 Agent 同时修改任务时，较晚提交的一方会收到冲突提示；页面读取最新版本后，由你决定是否重新提交。被其他任务依赖的任务不能直接删除。

同一会话树的负责人、子代理和更下一层子代理共用任务板和邮箱，各成员以自己的身份收信。只有收件人能标记已读，发送者也能看到状态变化。普通会话分叉会建立独立 Team，不复制原 Team 的任务和消息。

邮箱用于传递协作信息，不会自动启动收件 Agent。需要立刻继续工作时，使用成员页的后续任务输入。面板打开时会定期同步，也可手动刷新；启用 `ternilo.tools.agent_team` 后，模型维护的是同一份任务板和邮箱。

同一电脑的本地网页、桌面和远程网页共用 Team 数据。云端 Team 数据由 Server 保存，Worker 重启不会删除已有成员关系、任务和邮件。

## Workflow

Workflow 适合明确需要多阶段或并行协作的任务。例如先让多个子代理分别检查模块，再汇总结果。运行前需要一次性审批，页面会显示阶段和日志；取消、超时或脚本失败时，会停止仍在工作的子代理并记录结果。

高级用户可以用隔离的 Rhai 脚本编排：

| 函数 | 用途 |
|---|---|
| `agent(prompt, options?)` | 启动并等待一个子代理 |
| `task(...)` / `stage(...)` | 定义任务或阶段 |
| `parallel(tasks)` | 并行执行一组任务 |
| `pipeline(items, stages)` | 让每个输入依次经过多个阶段 |
| `phase(title)` | 更新可见阶段 |
| `log(message)` | 写入过程日志 |

直接命令示例：

```text
/workflow {"meta":{"name":"review","description":"review inputs","phases":[{"title":"scan"}]},"script":"phase(\"scan\"); parallel([task(\"alpha\"), task(\"beta\")])","args":{}}
```

默认限制为总时长 120 秒、最多 128 个子代理、8 个并发、1 MiB 结果，以及每次 `parallel`/`pipeline` 最多 512 个输入。脚本还有运算与结构深度上限；它不能直接访问文件、网络、进程、环境变量或凭据，也不提供 `eval`、`import`。实际文件或工具任务由受原有权限约束的子代理执行。

## 扩展与集成

插件页中的设置有三个作用范围：

| 范围 | 影响什么 |
|---|---|
| 执行目标的扩展库存 | 当前电脑或空间云端已安装、信任和启用的扩展 |
| Agent 预设 | 新会话或显式应用该预设时的插件基线 |
| 当前会话配置 | 只覆盖本会话的启停和字段设置 |

日常调整时，先确认配置目标，再修改当前会话插件。点“恢复默认”会移除该插件的会话覆盖，重新继承预设；关闭继承的扩展只影响当前会话，不会改写预设。扩展要求的必填设置需先补齐，保存时才会完成配置和挂载。

同一会话切换 Agent 预设时，已经保存的会话覆盖会保留。希望后续新会话也采用某项设置，请编辑自定义 Agent 预设；只在插件页保存不会更新预设。

扩展包目前可以提供工具、提示词片段、Skill、Hook、命令和 Provider 模板。使用 Provider 模板创建的模型连接会成为普通 Provider，之后卸载来源扩展不会删除它。每个包只采用 Rhai 或 WASM Component 中的一种运行时；静态提示词和 Skill 的读取不会执行扩展代码。

信任发布者、安装或卸载包、授予包能力由用户或管理员操作，模型不能自行完成。卸载后可重新安装完全相同的签名包和授权；同一版本不能替换代码、签名或授权，有变化需要新版本。完整安装步骤、配置例子与权限说明见[扩展系统](extensions.md)。

MCP、LSP、HTTP fetch、SearXNG／Brave／Tavily 搜索、Hooks、Code Mode 和外部 ACP 子代理也通过插件配置。需要从其他程序使用 Ternilo 时，可以使用 CLI、JSON-RPC、ACP 或 Python/TypeScript SDK，见[自动化与 ACP](automation.md)。

`web_fetch` 不需要单独的网页 API Key。透明代理的 Fake-IP DNS 导致网页读取失败时，可以配置可信的 HTTPS DNS JSON 服务，见[网页访问与代理 DNS](web-access.md)。

## 查看和控制后台服务

在会话顶部的“更多 → 后台服务”中，可以查看已配置的 MCP 和语言服务。仅查看状态不会启动外部程序；任务执行时才按配置准备服务。服务可能在回答完成后继续运行并占用工作目录。本机和接入电脑允许同一可信用户的其他会话并行，其他用户的重叠目录任务仍会等待；托管 Worker 继续遵循执行家族与实际退出的占用规则。可以回到原会话停止不再需要的服务，保留原来的插件配置。

启动、停止和查看分别沿用任务提交、任务停止和内容查看权限。启动过程中也可以停止；正在处理实际工具请求时，先停止当前任务。连接失败后可以重新启动或停止该服务；已经发现过工具的服务失败时，仍可使用其他工具，不会自动重试失败的请求。首次连接失败时会提示原因，处理后再继续任务。手动停止会抑制当前运行实例中的自动启动；重启程序或更改模型、权限、预设导致运行实例重建时，仍按现有配置准备服务。需要长期禁用时，在相应预设或会话配置中关闭插件。

托管 Worker 的后台服务属于当前任务的执行环境，只能在该环境仍运行时查看和控制；任务结束后服务一起退出。空闲会话的查询不会为了显示列表而另外启动一台执行环境。这里的目录协调保护会话声明的工作目录，不等于限制任意外部程序对其他目录的写入。

## 上下文交接摘要

自动压缩较长会话时，默认按目标、约束、决策、已完成工作、待办、文件、验证结果和风险整理摘要。可在上下文压缩插件设置中关闭结构化摘要。聊天中展开对应轮次的过程，再展开压缩记录即可查看。后续模型继续收到约束和待办，原始会话历史仍保留；重启后也可继续使用摘要。旧纯文本摘要继续可用。手动 `/compact` 使用确定性压缩，保留原摘要方式。

## 团队用量与估算金额

打开 Agent Team 的“用量”页可查看主代理、子代理及已读取成员的合计。统计按响应中实际记录的 Provider／模型分组，包含重新生成之前的响应，排除回放响应。缓存读取与写入属于输入 Token，推理属于输出 Token，不重复相加。记录不可读取或响应未报告用量时会标明未知；合计只覆盖可读取的成员。

“配置估算单价”按每百万 Token 输入单价，支持 USD、CNY、KRW，各币种独立保存。单价只保存在当前浏览器，不修改模型连接或团队配置。需要计价的类别留空时不显示金额；明确填写 0 才表示该类别免费。缓存写入使用一个适用单价，不推断供应商的缓存时长档位。估算范围为已记录的会话响应，不包含标题、压缩等辅助调用及未记录的失败请求，不等于供应商账单。刷新 Team 可重新读取用量，运行状态变化及当前会话新响应也会触发更新。

输入框的上下文指示器显示最近一次已报告响应的输入、输出、缓存读取和推理 Token，并使用当前绑定模型的上下文窗口。后续请求和压缩会改变实际占用，该指示器不是下一次请求的精确预测。

## 工具输出预算与文件读取缓存

会话日志插件中的“历史工具输出预算”默认 48000 字符，限制发送给模型的工具结果总内容，优先保留最近结果。0 可取消此总量限制，单条工具输出限制仍生效。缩短结果会带说明，调用及结果仍配对；完整持久历史和大输出附件不变。

本地文件插件的“文件读取缓存”以字节设置每个会话可复用的文件内容，默认关闭；例如 8388608 表示 8 MiB。开启后仍检查工作区路径、权限、文件类型与版本，工具写入或检测到外部文件变化时失效。缓存不跨会话共享，不缓存目录、搜索、命令或失败结果。版本检查使用文件元数据；外部程序若刻意保留全部可见元数据，需关闭缓存再读取。

## AST 代码图谱

`code_map` 读取指定文件的 AST，适合先了解代码结构，再定点阅读和修改。支持 Rust、TypeScript／TSX、JavaScript／JSX、Python、Go，返回符号位置、嵌套所属关系、导入及语法调用目标，不执行项目代码。例如参数 `{"paths":["src/lib.rs","web/src/app.tsx"]}`。

代码图谱插件默认最多分析 16 个文件、每文件 256 KiB；超限或语法错误会标记，不能将部分结果视为完整依赖图。动态调用不做类型推断，需要结合源码或语言服务确认。Local 默认提供该插件；托管 Worker 中先在插件配置启用 `code-map`，并确保管理员的 Worker 策略允许 `ternilo.tools.code_map`。配置界面支持中英韩文。

## 提示缓存与推理强度观察

Agent loop 插件提供两个默认关闭的选项。“提示前缀缓存”对 Anthropic Messages 的稳定系统指令增加缓存标记，会话身份和动态工具信息位于后续内容。其他协议使用原有上游缓存行为；命中情况以响应用量为准，不保证每次请求都节省费用。

“自动推理强度：观察模式”在聊天过程里记录每一步的建议和依据，仅用于评估，不切换模型或修改实际推理强度。建议基于本轮输入长度、工具调用及错误数量；这是确定性规则，也不会检查目标模型是否提供该强度档位。需要调整实际强度时，仍通过主模型或角色模型选择器操作。
