# 设置、预设与执行上限

设置前先看页面顶部的配置目标。它说明这次修改作用于哪台电脑或哪个账号环境；新会话默认值和当前会话设置分别保存。

## 下拉选择与主题

设置页、模型表单以及相关的电脑、项目、成员和文件筛选使用统一的主题下拉。当前选项有勾选与底色，支持键盘方向键、Enter 确认、Escape 关闭和触摸选择；长菜单可滚动，窄屏不会超出视口。语言、主题、字号等通用设置在手机上使用整行控件，浅色和深色界面采用各自的主题颜色。

## 设置目标与数据归属

数据库连接、监听地址、数据目录等启动设置由部署者配置。日常选择模型、管理插件、连接机器、邀请用户和共享工作在软件中完成；不需要为了日常配置反复修改部署文件。

Server 提供模型授权时，可以从“我的模型”领取自己的接入密钥，再把平台地址和 Key 填入本机 Provider。模型请求经过 Server，工具和文件操作仍在本机运行，无需登记 Worker 或连接电脑中继，具体步骤见[模型接入指南](model-service.md)。

Server 的“用户设置”在独立页面打开，不再包含模型栏目。Provider、模型目录、接入 Key 和模型授权设备统一位于“我的模型”；平台账号、平台模型服务和托管 Worker 从管理员专用的“平台管理”进入。团队管理位于空间切换区域旁。管理员也使用普通工作台，不在用户设置中操作平台事务；本地 Ternilo 保留包含模型配置的设置弹窗。

打开用户设置时，先看顶部“当前配置目标”。它决定插件、预设及非模型凭据修改的是哪台电脑或哪个云端环境；模型中心使用独立的显式来源选择，不跟随以下聊天目标：

1. 已选择会话时，配置该会话的执行位置。
2. 尚无会话、但已选择工作区时，配置该工作区的执行位置。
3. 两者都未选择时，启用了托管执行的 Server 使用当前空间和用户的云端配置；未启用时先选择自己的电脑。本地网页和桌面仍使用当前电脑。

电脑上的 Provider、API 凭据、模型目录、Agent 预设和扩展库存由那台电脑保存。Server 只转发对应操作，不复制这些配置或 Key。电脑离线时，相关设置会提示不可用，不会把修改悄悄保存到云端。

Server 的账号 Provider 与 API Key 由账号统一管理，模型中心不提供旧空间配置入口；设备 Provider 则保存到明确选定的电脑。Agent 预设仍属于目标空间中的当前用户，云端扩展库存属于空间。会话列表和可用历史不会因某个离线目标的设置加载失败而一起消失。三类模型来源见[模型配置指南](models.md#server-的三类来源)。

| 你要保存的内容 | 实际保存位置 |
|---|---|
| 自己电脑或 VPS 的项目文件 | 该机器上选择的目录 |
| 该机器的会话、模型、插件、凭据和附件 | 该机器的 Ternilo 数据目录 |
| Server 账号、资源共享和托管会话 | Server 数据库 |
| 托管任务的项目文件 | Worker 使用的持久工作区存储 |

关闭网页不会删除这些数据，也不会自动停止任务。完整备份需要覆盖对应位置；只备份 Server，不能恢复电脑上的项目文件。

“凭据与登录”用于插件所需的独立服务凭据和授权流程。普通模型 Key 直接在 Provider 卡片填写即可；它自动生成的凭据引用只显示状态。具体操作见[凭据与登录说明](getting-started.md#凭据与登录页什么时候使用)。

Server 的“用户设置 → 通用 → 账号”提供浏览器登录会话列表，显示设备／浏览器描述、首次和最近来源 IP、登录／最后活动／到期时间及当前会话标记，可以逐项撤销或撤销其他会话。撤销当前会话会要求确认并返回登录页；已连接网页需要重新认证。展开详情可查看浏览器 User-Agent 和公开会话 ID，不返回登录令牌或令牌摘要。列表不包含模型授权设备或 Node。

普通浏览器不能取得真实电脑主机名，界面会明确说明，不用 Server 主机名代替。设备描述来自浏览器 User-Agent，不作为可信身份。IP 是 Server 看到的来源地址，可能属于代理、VPN 或 NAT；不推断地理位置或内网地址。最后活动记录已认证 HTTP 请求，通常每分钟落盘一次，来源 IP 改变时立即更新；仅阅读页面或保持空闲 WebSocket 不等于新的 HTTP 活动。旧会话缺少资料时显示“尚未记录”。

反向代理 IP 只有在 `--trusted-proxy-ips`／`TERNILO_SERVER_TRUSTED_PROXY_IPS` 或 JSON 配置 `trusted_proxy_ips` 明确指定后，才允许提供 `X-Forwarded-For`。配置代理的实际连接地址，不要填任意客户端范围；未信任的转发头会被忽略。通过 OIDC 登录时，只能管理本站签发的原生登录会话，外部组织会话仍由身份提供方管理。

## 空间与项目

空间是个人或团队资源的范围；项目是该空间内工作区的分组，不是磁盘文件夹。工作区另行绑定某台电脑的实际目录或托管执行环境，创建项目不会创建文件夹，也不会启动会话。

空间所有者和管理员可从空间切换旁的管理入口进入“项目”，查看项目及当前有权访问的工作区，创建、改名或删除空项目。点击工作区可返回工作台；列表数量只统计当前可见工作区，不表示整个项目的全部资源。项目分组本身不会授予文件、会话或电脑权限。

“打开工作区”中的项目选择器支持键盘上下移动、Enter 确认和 Esc 关闭，选中项有勾选标记；旁边的“管理项目”进入同一管理页面。会话标题下在权限允许时显示项目归属。改名不更改磁盘目录；删除不会连带删除工作区、会话或文件。个人默认项目、空间最后一个项目及仍有关联资源或历史的项目不可删除，详见[空间与项目管理](platform-management.md#个人空间与团队)。

## Agent 预设

Agent 预设保存一组能力和插件配置，适合给不同类型的任务设置起点。内置预设只读，可以复制后修改：

| 预设 | 适合的用法 |
|---|---|
| `standard` | 使用完整的标准能力 |
| `ptc` | 保留标准能力，由模型通过 Rhai Code Mode 统一调用 |
| `minimal` | 只保留工作区文件和 shell 等精简能力 |
| `creative` | 保留标准能力，并提供预设、插件和运行时实验指导 |

在“设置 → Agent 预设”中复制一个预设，修改显示信息和插件字段，再保存或设为新会话默认值。已有插件使用字段表单编辑；需要新增插件行或调整组合结构时，再展开完整 Profile JSON。草稿需要统一保存，保存时会检查配置和依赖。

创建会话会保存所选预设的快照。之后编辑或删除预设不会改动旧会话。只有尚未接受任务的空白会话可以切换预设；首次任务被接受后，即使仍在队列中、已经停止或移除队列项，也不能再切换。刷新、重启和保留历史的分叉不会解锁；要使用另一份预设，请创建新会话。这一限制由后端同时执行，不仅是按钮禁用。模型、执行权限和计划模式仍按各自规则调整。

分叉继承当前预设快照。复制出来的名称和说明属于你的自定义内容，不会因切换界面语言而被覆盖。

预设保存位置跟随当前配置目标。在某台电脑上创建的预设不会自动变成云端预设。

## 单轮执行限制

工具调用次数默认每轮最多 512 次，填写 `0` 表示 Agent 不按次数截断。`wait_agent` 每调用一次也计一次，等待时长不会增加次数。达到上限后，已完成的操作和结果仍保留，未执行的调用会注明原因；发送后续消息即可继续，不需要新建会话。

调整当前会话：进入“设置 → 插件 → 插件配置”，展开 `agent-loop`，修改“每轮工具调用上限”后保存。会话空闲时保存，下一轮即可生效，无需重启服务或新建会话。“恢复默认”会移除会话覆盖，重新继承预设。

调整以后新会话：在“设置 → Agent 预设”中复制内置预设，或编辑已有自定义预设中的同一字段；将修改应用到草稿，保存预设，再设为默认。已有会话保留自己的配置。

同一个插件还有“每轮执行步数上限”。一步是一次模型决策，可以包含多次工具调用，不等于 token 数或消息数。此项默认 `0`，表示不按固定步数截断；正整数表示每轮最多执行的步数。

部署者可以额外设置上限。本地 `ternilo serve --max-tool-calls 128` 或环境变量 `TERNILO_LOCAL_MAX_TOOL_CALLS=128` 会将实际次数限制在 128 以内；`run`、`rpc`、`acp` 使用相同参数，命令行优先于环境变量。本地默认宿主值为 `0`，表示不额外限制网页里的 Agent 配置，因此普通会话仍默认 512 次。修改启动参数需要重启相应进程；使用同一数据目录重启后，已有会话的后续任务会使用新上限。

云端由 Server WorkerPolicy 的 `maximum_limits.max_tool_calls` 设置最高次数，官方默认和示例保持 512。插件页会说明当前实际生效的限制：两层都设置正数时取较小值，一层为 `0` 时使用另一层，两层都为 `0` 才不限制。

| 会话插件值 | 本机或平台上限 | 实际上限 |
|---:|---:|---|
| `0` | `0` | 不按这项计数截断 |
| `128` | `0` | `128` |
| `0` | `512` | `512` |
| `128` | `512` | `128` |

修改平台策略后需要重启 Server 和 Worker，Worker 会重新取得策略。新提交的托管任务保存新配置，已经接受的任务和队列保留提交时的配置与上限。显式自定义值不会被默认值覆盖。

步数也遵循相同规则：本地通过 `--max-steps` 设置宿主上限，云端通过 WorkerPolicy 的 `maximum_limits.max_steps` 设置，默认均为 `0`。没有独立会话宿主的内置回退子代理，还使用 `ternilo.subagents.in_process` 中的同名限制。工具次数、步数、上下文、超时和部署配额分别生效，任何次数或步数设置下都可以手动停止任务。宿主策略详见[托管执行说明](server-reference.md#workerpolicy-与模型-broker)。
