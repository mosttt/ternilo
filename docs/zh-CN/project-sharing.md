# 项目共享继承

[English](../en/project-sharing.md)

项目共享用于把同一套成员或权限组规则应用到多个工作区。它需要工作区所有者主动开启继承；创建项目规则不会公开现有资源。个人空间不提供协作共享，操作需要在多用户模式下的团队中进行。

空间管理员在“空间管理 → 项目 → 项目共享规则”中选择团队成员或权限组，设置查看、发送、停止和调整会话设置权限。团队成员可以查看项目规则；只有空间拥有者和管理员可以编辑。项目管理权限本身不授予他人的工作区内容访问权。

工作区所有者在侧栏该工作区的“更多 → 共享…”中，先通过“查看项目规则”了解授权范围，再打开“继承项目共享规则”。开启后，项目现有及后续规则会作用于该工作区、其中的会话、归档和同位置分叉。新工作区及升级前的工作区默认关闭继承。团队只读角色仍只允许查看，不会因规则包含更多操作而提权。

| 身份 | 项目规则 | 工作区继承开关 | 工作区与会话内容 |
|---|---|---|---|
| 空间拥有者／管理员 | 可管理 | 仅能修改自己拥有且可配置的工作区 | 仍需要资源所有权或有效授权 |
| 工作区所有者 | 可查看；管理仍取决于团队角色 | 可开启或关闭，需可写团队角色 | 沿用所有者权限 |
| 被授权的团队成员 | 可查看 | 不能修改 | 取得已开启继承工作区的有效授权 |

权限按直接授权、工作区授权、权限组和项目规则取合集，再应用团队角色限制。“查看权限…”会显示项目名称及具体来源。关闭继承、撤销项目授权或移除组成员后，对应来源失效；其他独立授权继续有效。项目规则不转化为分叉上的永久个人授权，同工作区分叉始终使用当前规则，因此重新加入项目权限组时也会按当前工作区规则重新获得访问。

继承不会授予删除资源、管理资源直接共享、修改继承开关、机器管理、Provider 凭据或额外模型预算。项目管理员可以管理规则，但工作区当前管理者保留是否加入的决定。共享不会移动目录、切换资源管理者或创建独立工作副本。[资源管理权交接](resource-management.md)是独立操作，不改写项目继承开关；跨项目迁移尚未提供。

失去全部查看权限后，列表、实时内容、文件及归档访问会被撤销。已经接受的任务沿用原来的队列和停止规则，不会单纯因为共享撤销而自动取消；由仍有停止权限的人处理。

Control schema 为 `14`，独立的 `project_sharing` schema 为 `1`，保存项目用户／组授权和工作区加入状态。身份、存储绑定和直接共享分别保存。PostgreSQL 由 schema 所有者初始化组件，运行账号使用租户 RLS，访问视图采用调用者权限。执行器协议为 `48`。

API 见 [Server 参考](server-reference.md)，共享目录及文件权限见[协作指南](collaboration.md#与其他人共享工作)。
