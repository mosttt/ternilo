# 多 Server 的 Node 路由

[English](../en/server-cluster.md)

当前源码提供跨 Server 的 Node 调用转发、实时变化补读及电脑模型流式转发，已通过受限 PostgreSQL 的真实双实例浏览器流程。使用包含这些功能的同版本程序部署；共享 PostgreSQL 和调用转发并不构成完整存储故障转移。

参与的 Server 必须使用相同版本、同一数据库和同一 `secret_master_key`，并各自设置可由其他实例访问的 `cluster_url`。它是当前实例的地址，不是负载均衡地址，也不代替浏览器登录使用的 `public_url`。每台实例的地址必须唯一并直接指向该实例。

配置示例：

```json
{
  "cluster_url": "https://server-a.internal.example:8443"
}
```

把这一字段加入完整的私有 Server 配置；也可使用 `ternilo-server serve --cluster-url https://server-a.internal.example:8443` 或 `TERNILO_SERVER_CLUSTER_URL`。其他实例填写自身地址。跨主机使用验证证书的 HTTPS，反向代理将 `/api/v1/internal/node/call` 转发到对应实例，避免记录请求正文或认证签名。HTTP 仅接受 `127.0.0.1` 或 `::1` 等字面量回环地址，用于同机进程。

Node 保持一条到 Server 的认证 WebSocket。浏览器或 API 请求落在其他实例时，Server 根据有效连接租约找到持有者，通过认证在线通道请求，再返回原结果。接收实例重新检查租约、原 Node 凭据及执行器能力；提交任务保留实际作者和账号授权，返回内容继续遵守原资源权限。转发通道不授予用户新的电脑或资源访问权。

实例时钟应保持同步，请求签名只接受 30 秒内的时间偏差。输入同时保留入口时的账号授权版本，停用再恢复不能让旧输入获得新授权。

凭据值、目录和文件内容等临时调用不写入共享命令日志。网络中断不能证明任务没有执行；未取得可核验结果时不会自动重发。检查会话、队列和实际文件状态后再决定后续操作。

每台 Node 的变化版本在共享数据库合并保存，其他实例按版本补读权限允许的历史和当前状态。网页保持原实时订阅；同一事务回滚不会产生已提交变化提示。节点离线或租约失效后，已同步历史仍可读，需要抵达电脑的操作返回不可用。

这项功能只协调 Node 连接及调用，不搬迁工作目录、Server 或 Worker 的文件存储，不接管脱离监督的外部程序，也不实现 Work 容器调度。配额、受限 PostgreSQL、备份及持久卷要求仍见[部署指南](deployment.md)；功能边界见[架构](architecture.md#node-路由与事件)。

跨电脑模型使用独立的 `/api/v1/internal/node/model` WebSocket 通道。反向代理还需允许此路径的 WebSocket 升级。通道核对签名、时效、来源所有者、当前连接租约与执行器能力；流式输出、每次尝试的报告、取消和新的重试许可沿同一连接传递。请求不进入持久重放队列，来源连接变化会结束在途调用。
