# 账号密码、邮箱与多因素认证

[English](../en/account-recovery.md) · 简体中文

已登录的原生账号可以从“用户设置 → 通用 → 账号 → 修改密码”输入当前密码、新密码和确认密码。成功后包括当前页面在内的本站原生／OIDC 浏览器登录全部失效，需重新登录。密码更新与会话撤销在同一事务中完成；错误密码或并发改密不会覆盖当前密码。仅有 OIDC 登录的账号不显示此入口。

接口为 `POST /api/v1/auth/password`，使用当前账号的浏览器认证，JSON 字段为 `current_password` 和 `new_password`，不接受目标账号参数。响应不包含密码；该操作不退出外部身份提供方的登录，不撤销电脑凭据、模型 Key 或服务账号凭据。

能够读取 Server 私有配置的运维人员可以重置已有原生账号的密码。账号 ID、角色、个人空间、工作区、会话、电脑与模型授权保持原有归属。此命令不增加账号，也不为仅有 OIDC 登录的账号创建密码。

在运行 Server 的机器上执行：

```bash
ternilo-server admin reset-password \
  --config-dir /path/to \
  --username owner
```

终端会隐藏输入新密码，并要求重复确认。新密码沿用注册规则：8～1024 字节，空格属于密码。成功后可用原用户名和新密码登录，不需要重建数据库或重启 Server。

自动化场景使用 `--password-stdin`，例如从受保护的临时文件读取：

```bash
ternilo-server admin reset-password \
  --config-dir /path/to \
  --username owner \
  --password-stdin < /path/to/protected-password-file
```

标准输入会去掉一处末尾 LF／CRLF，其余字符保留；没有终端且未指定该选项时，命令明确拒绝。密码不作为命令参数接收，也不会写入输出和审计。私有配置与密码文件仍应只对运维人员可读。

密码更新与旧的本站原生／OIDC 浏览器会话撤销在同一事务中完成。旧密码在重置前已验证、但尚未签发会话的登录也会被拒绝。旧会话对后续请求失效，网页的在线连接在复核后要求重新登录；已接受的任务不会因此自动中断。

电脑凭据和模型 Key 不随密码重置撤销，OIDC 绑定关系保持；外部 IdP 的凭据与组织会话由 IdP 管理。被封禁或待审核的账号仍保持原状态，已移除账号不能恢复。需要调整访问状态时使用[账号管理](platform-management.md)。

已登录账号可自助改密；忘记密码时可使用已验证邮箱或上述运维恢复。已启用的 MFA 在密码修改或找回后仍然有效。若错误的 OIDC／Turnstile 设置阻止登录，参照[登录设置恢复](server-authentication.md)，它与密码重置是两个不同的维护操作。

## 邮箱验证与邮件找回

实例所有者在“平台管理 → 实例设置 → 登录与人机验证”启用“账号邮件服务”，配置 SMTP 主机、端口、加密方式、发件邮箱和可选认证凭据。默认使用端口 587 的 STARTTLS，也支持端口 465 的直接 TLS。两种方式均验证服务器证书；STARTTLS 失败不会降级发送。“本机邮件代理”只接受回环主机地址，用于受信任的本机投递代理。

SMTP 密码加密保存，不在读取设置时回显；未修改连接参数时留空保留原密码，更改主机、端口、加密方式或用户名后需重新输入。邮件链接使用配置的 Server 公网根地址，不使用请求 Host；生产部署使用 HTTPS。关闭账号邮件服务会停止签发邮件和通过邮件重置密码，不影响普通登录。

账号登录后在“用户设置 → 通用 → 账号”发送验证邮件。打开链接后需登录对应账号并点击验证；仅知道邮箱或外部身份提供方返回相同邮箱不能取得“已验证”状态。邮箱验证不作为现有账号登录的强制条件。当前邮箱改变后必须重新验证，新邮箱不能直接用于恢复。

登录页的“忘记密码”向已验证的原生账号邮箱发送找回链接。不存在、未验证、仅 OIDC 登录或非活动账号返回相同公开结果；已有 Turnstile 配置也应用于找回请求。用户重复填写新密码后完成恢复，不会自动登录；本站原生／OIDC 浏览器会话全部撤销，原账号身份和资源保持。邮件找回不改变外部 IdP 的密码或会话。

链接 15 分钟后失效，成功使用一次即失效；重新签发会使同类旧链接失效，任何密码更新都会清除旧找回链接。数据库只保存随机凭据的 SHA-256 哈希。凭据位于链接片段中，页面读取后从地址栏移除，不随初始 HTTP 请求发送；OIDC 登录期间待验证邮箱凭据仅在当前标签页短时保存。

同一账号的同类邮件至少间隔一分钟。各 Server 共享每来源 IP 每分钟 5 次、全站每分钟 100 次的邮件相关请求限制；原生改密接口不使用此邮件额度。代理部署应正确设置受信任代理地址。单实例最多同时投递 8 封邮件，发送超时不超过 20 秒；投递失败时检查 SMTP 设置并稍后重试。它们是账号邮件保护，不代表通用模型／账号分层额度已经实现。

接口为 `GET /api/v1/auth/email`、`POST /api/v1/auth/email/send`、`POST /api/v1/auth/email/verify`、`POST /api/v1/auth/password-recovery` 和 `POST /api/v1/auth/password-reset`。验证需要本站登录；找回请求使用 `email` 和可选 `turnstile_token`，重置使用 `token`、`password`，邮箱确认使用 `token`。这些接口不返回邮件凭据。


## 验证器与恢复码

原生账号可以在“用户设置 → 通用 → 账号 → 多因素认证”输入当前密码，使用验证码应用扫描二维码（或手动输入密钥）。保存页面一次性展示的 8 个恢复码，勾选已保存，再输入验证器当前的六位验证码启用。配置在 10 分钟后失效；退出配置页面后重新设置会替换未启用的密钥。恢复码不能用于确认启用。

启用后，密码登录以及已绑定的 OIDC 登录都需要验证码或一个未使用的恢复码；启用和停用都会撤销已有本站浏览器登录。OIDC 登录通过身份提供方后会回到第二因素页面，通过验证前不会获得本站访问凭据。启用本站 MFA 的账号不能直接使用外部 OIDC 访问令牌调用本站接口。仅有 OIDC 身份、未设置原生密码的账号使用身份提供方的多因素认证策略，本站不显示验证器设置入口。

验证码使用 TOTP（SHA-1、六位、30 秒），接受相邻一个时间步；同一个时间步的验证码只能成功使用一次，包括启用时使用的验证码。请保持设备时间准确，已用过时等待下一次更新。连续五次错误会暂停验证码验证五分钟，未使用的恢复码仍可用于恢复访问。每个恢复码也只能使用一次；页面显示剩余数量，不能再次查看原文。需要更换验证器或补充恢复码时，先以当前密码和验证码／恢复码停用，再重新设置。

密码修改、运维改密和邮件找回不会关闭 MFA。电脑凭据、模型 Key 和服务账号凭据继续使用独立的授权与撤销规则。通行密钥（Passkey）尚未提供。

验证器密钥加密保存在 Server 数据库，恢复码仅保存摘要；请求不缓存。丢失验证器和全部恢复码时，具有 Server 私有配置及主密钥访问权的运维人员可以执行：

```bash
ternilo-server admin reset-mfa \
  --config-dir /path/to \
  --username owner
```

此命令清除该原生账号的 MFA 并撤销本站浏览器登录，保留密码、身份、资源和 OIDC 绑定；不会解封账号，也不能恢复已移除账号。下一次登录后应重新设置验证器。操作写入审计，不存在公开跳过 MFA 的恢复接口。

状态与配置接口为 `GET /api/v1/auth/mfa`、`POST /api/v1/auth/mfa/setup`、`POST /api/v1/auth/mfa/enable` 和 `POST /api/v1/auth/mfa/disable`。配置接受 `current_password`，启用另需 `generation` 和 `code`，停用另需 `code`。原生登录的第二因素字段为 `mfa_code`；OIDC 回调产生短时 `mfa_challenge`，由 `POST /auth/mfa` 接收 `challenge` 和 `code` 完成验证。待验证凭据不能用于访问资源。
