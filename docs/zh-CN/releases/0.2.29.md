# Ternilo v0.2.29

本版将网页搜索和读取统一到 Provider 配置，账号保存一次，任务电脑按所选 Provider 执行。中英韩界面同步更新。

- 在“我的模型 → 账号自有 → 编辑 → 自定义设置 → 网页访问”选择搜索与读取方式。独立使用 Ternilo 时，从“设置 → 模型”进入。新会话沿用已有默认模型，不需要另设搜索默认值。
- 电脑搜索可选 DeepSeek、Brave、Tavily 或 SearXNG；网页读取可直接抓取或使用 DeepSeek Markdown 服务。独立网页 API Key 可在同一编辑页保存，DeepSeek 搜索与读取可以共用这份网页凭据；不会自动使用模型 Key。
- 账号或其他电脑提供模型时，独立网页工具仍在任务电脑执行。网页凭据仅按需交给所有者已授权的电脑，不保存到执行电脑的凭据库或会话历史。
- DeepSeek Responses 的 `deepseek-v4-pro` 可启用供应商内置搜索；Claude 可启用内置搜索与读取。内置工具由供应商执行，与电脑执行模式分开选择。
- 保留“使用会话插件”和“关闭”。明确禁用的能力及宿主权限仍然生效；停用的替代插件不会误禁当前启用的同类能力。集中与单插件配置均显示 Provider 管理的生效值。
- 新对话读取更新后的配置，切换 Provider 同步切换网页工具。配置变更、凭据缺失和余额不足分别提示；已失效的远端来源在入队前返回错误，避免 SDK 等待未开始的任务；本机非网页命令不因模型来源离线而无法使用。
- 更新 Markdown 解析依赖，修复 RUSTSEC-2026-0414。

配置方法与支持边界见[网页访问](https://github.com/mosttt/ternilo/blob/v0.2.29/docs/zh-CN/web-access.md)。平台 Provider 不导出电脑网页凭据；托管 Worker 继续使用独立插件或供应商内置工具。

## 升级

**本版 Executor 协议由 49 升为 50，Server 和接入电脑需统一升级。** 等现有任务结束后，停止相关服务，保留原实例数据，更新完整客户端包，并拉取 `ghcr.io/mosttt/ternilo-server:0.2.29` 后重建 Server 容器，再按原方式启动。不能通过新版 Server 的远程更新入口直接升级仍使用协议 49 的旧电脑。

签名更新清单的最低客户端版本为 0.2.29，Server 范围为 `>=0.2.29, <0.3.0`；完成首次统一升级后，同协议、同数据代次的后续版本可继续远程更新。数据代次仍为 1。Windows 保留完整包中同版本的 `ternilo-sandbox-windows.exe`。

已有 Worker 部署需同步更新 Server／Worker，并将私有 Worker policy 的 `catalog_revision` 改为 `ternilo-cloud-v5`。不使用 Worker 的部署无需此步骤。桌面安装器仍未进行发行者签名／公证，桌面自动更新未启用。
