# Ternilo v0.2.33

## 归档与删除

归档主会话会同时归档真正的子 Agent 后代、停止相关任务并暂停队列；普通分叉会话保持独立。恢复会重新显示这条委派分支，不自动重跑任务或恢复队列。

归档列表支持所有者永久删除单条记录，提供中英韩确认和失败重试。删除保留其他会话及工作目录文件；云端父记录删除后，直接子会话解除该父子关联，执行目录隔离关系不变。

## 内存与执行路径

启动时流式读取历史并写入搜索索引，队列恢复只保留输入消费凭据和调度事实，避免把所有历史正文集中放入内存。

运行时增加已提交会话事实与轮次索引。轮次检查、作者溯源、目录准入、结果提取及队列收尾按需读取，不再为这些操作复制整份会话历史。事件同步落盘、输入持久化、权限检查和调度来源校验保持不变。

会话配置查询不再依赖模型授权或网络连接。平台模型授权被撤销后，已有历史仍可查看，切换到可用模型后可以继续发送；新任务仍按当前授权执行。

## 文件下载与留存

工作目录中的 ZIP、不支持预览的文件和大文件均可完整下载，下载与 2 MiB 预览限制分离。回答中的工作区文件链接可打开文件标签。原文件与历史文件使用分块传输，历史版本保留完整性校验。

“设置 → 插件”的会话日志插件新增“单个生成文件留存上限（MiB）”，默认 64，集中配置与详情同步。调低不删除已有文件，不影响它们的下载和恢复；上传限制保持独立。

## 子 Agent 连续追问

修复同一父轮次多次给子 Agent 发消息时复用运行 ID、导致 `already exists in this session` 的错误，并刷新失败后的活动状态。独立子轮次仍沿已验证的来源链使用原任务授权。Agent Team 的“共享任务”空状态明确区分对话执行计划，不自动把计划转为共享任务。

## 插件配置保存

集中配置、插件详情和协作设置共享写入状态。保存期间切换入口不会让旧回调覆盖新草稿；已接受的配置与迟到的页面刷新分别处理，后续编辑不会被旧投影清除；恢复继承和放弃修改使用已接受配置。

## 核心插件接口变化

自定义核心插件使用的 Sessions 接口升级为 `ternilo/sessions@2`，需要适配后重新编译。执行协议从 51 升为 52，Server、Node 和 Worker 需要配套升级；独立维护通道仍可为旧执行端发起更新。子 Agent 新日志记录 `source.kind=subagent` 及父轮次，旧版程序不能安全读取包含这些记录的历史；降级前应保留升级前备份。新版仍能读取既有历史，数据库无需迁移。

## 升级

更新 Server 镜像为 `ghcr.io/mosttt/ternilo-server:0.2.33`，并更新电脑端完整客户端包。已启用维护通道的 v0.2.30 及更新客户端可从 Server 发起升级；更早版本仍需手动安装。保留数据、电脑登记和原服务配置，无需迁移数据库。

详见[客户端更新](https://github.com/mosttt/ternilo/blob/v0.2.33/docs/zh-CN/client-updates.md)和[核心架构](https://github.com/mosttt/ternilo/blob/v0.2.33/docs/zh-CN/architecture.md)。Desktop 安装器仍未签名，自动更新保持关闭。
