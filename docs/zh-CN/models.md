# 配置和使用模型

本机在“设置 → 模型”保存连接；Server 统一使用侧栏“我的模型”，用户设置不再提供重复的模型栏目。配置完成后，在会话输入框下方选择模型。服务商、协议和执行电脑是不同的选择；使用 Server 分配的模型额度，见[平台模型接入](model-service.md)。

模型中心按功能组织：桌面左侧选择“模型／授权与接入／用量”，手机使用顶部导航。模型页再按账号自有、设备本地、平台授权切换来源；授权与接入集中管理接入密钥和模型授权设备，不与远程控制的电脑登记混淆。用量页按来源筛选 Server 模型服务的请求及统计；选择“设备本地”可查看自己已登记电脑直接调用 Provider 的已同步尝试，包含重试、未知计数和原提交者。设备报告与 Server 预算分开，详见[设备用量](device-provider-usage.md)。

## Server 的三类来源

“账号自有”管理当前账号的私有 Provider，固定归当前账号，不随聊天中选择的电脑或团队切换，也没有旧空间配置选择入口。账号模型的上游 Key 由 Server 保管，不因查看或切换团队而复制、合并或共享。

“设备本地”按所选空间内的电脑列出卡片，同一电脑只显示一次，无需选择工作区。点击“查看模型”展开该电脑的目录，已接入的自有电脑即使还没有工作区也可配置。Provider 在同一设备的工作区间共用，不因选择不同工作区而复制。只有拥有相应设备配置权限时才显示修改入口；共享者只能读取获准展示的目录。设备离线时不能同步或修改，但不影响独立管理账号来源。目录读取权限本身不授予模型调用权；跨电脑调用按会话绑定单独校验，合成的 Server 模型连接不能充当跨电脑来源。

“平台授权”展示平台实际授予当前账号的模型与预算。相同模型来自多份授权时分别保留，不因名称相同而合并用量来源。平台上游仍由管理员维护；个人中心另有接入密钥、模型授权设备和用量入口。

模型中心的配置目标与当前聊天独立：保存 Provider 不会替你更换另一段对话的模型。当前会话仍从输入框选择；账号页的默认值只作用于个人空间的托管新会话，不改接入电脑的本地默认值。旧 `/settings/models` 地址进入同一个模型中心，不再打开第二套编辑器。

会话选择器统一从“模型”进入，按账号自有、设备本地和平台授权分组显示当前可用来源，平台模型不再另开弹窗。平台分组保留每份预算的名称，支持搜索模型／预算和分页；同名模型的不同预算不会合并。个人空间的新会话默认值也使用这套交互，这只是选择默认模型，不是配置新的授权。所有模型条目统一显示名称和模型 ID 两行；未另设名称时也显示 ID。手机在同一弹层内逐层进入并返回，不横向叠加子菜单。

目录按来源、Provider／预算、模型三级视觉层次排列，已选模型用底色和勾选标记区分，保留不可用说明与推理强度。Server 的会话选择器不再提供“配置账号自有模型”按钮，管理连接统一从侧栏“我的模型”进入；进入其他页面时关闭原菜单，返回聊天不会自动重新弹出。

平台模型与账号、设备模型共用“推理强度”入口。选择档位后保存到当前模型绑定，后续请求使用该档位，同时保持原账号或平台预算不变。若模型未声明可选推理档位，会显示说明而不是猜测支持的等级；平台管理员需要在“平台管理 → 模型服务 → 上游接入”配置对应 Provider／模型的推理能力。这里的能力声明应与真实上游接口一致。

更新推理能力后，重新打开会话的模型菜单即可读取当前可选档位，不必先切换到其他模型。Server 接入电脑的会话将“目前可选的档位”和“会话已经选定的执行参数”分开：修改 Provider 不会偷偷改写已保存的任务参数，明确选择新档位或“模型默认”后才应用当前配置。删除原档位时，旧选择会显示不可用，但仍可直接改选新配置允许的档位；撤销整个模型授权则不能继续选择或调用。

独立客户端的选择器区分“设备本地”“账号自有 · 已连接 Server”和“平台授权 · 已连接 Server”，连接项显示 Server 地址和原授权来源。私有模型须经浏览器明确授权，不会自动包含在已有平台模型连接中。Server 远程控制接入电脑时，也可在同一模型目录的“平台授权”分组中，将当前账号获授的模型和指定额度用于此会话。它与独立客户端的设备授权连接是不同场景，不要求给 Node 再配置平台 API Key，也不修改电脑默认模型。

给接入电脑分配新模型需要会话配置权限，所选授权仍绑定原持有人；其他协作者需要提交权限，且平台授权允许共享。平台预算在 Server 端预留、计量和撤销，每次重试重新检查额度，不因上游模型与设备本地模型同名而回退。子任务沿原运行追溯输入作者，使用该子会话自己的模型快照；父会话后来收到新消息不会替换正在运行的子任务身份。

定时任务使用触发时该会话明确选择的模型，调用身份始终追溯到创建定时器的原始输入，不改用会话最新消息的作者。Server 每次调用及执行期间继续核验原作者的提交权限、模型持有人的配置权限和模型授权；权限失效时停止，不切换来源。Node 重启后待执行的账号模型定时器在网关就绪后恢复。手动停止只结束当前执行，取消后续提醒应删除定时器；已经记录派发的一次性任务不会因为重启而再次执行。

团队的托管会话可以直接选择会话所有者在“我的模型”配置的账号模型，无需把 Provider 或 Key 复制到团队空间。只有会话所有者可以首次指定或改选另一份私有模型；协作者只能查看当前已授权模型的目录并在提交权限范围内使用，不能凭配置权限枚举或改用所有者的其他私有 Provider。目录不返回私有服务地址或密钥，也不返回无关的个人凭据。

模型配置位置与执行位置分别校验：模型仍归账号个人空间，文件、执行租约及任务额度仍归实际团队工作区。删除账号模型或所需 Key 后，不会自动切换到团队中的同名 Provider 或另一份平台预算；需要所有者明确选择仍可用的模型。已有任务的模型绑定不会因目录调整被重新解释为另一个同名来源。

## 远程会话使用另一台电脑的模型

在 Server 中打开执行电脑 A 的会话，进入输入框的“模型 → 其他电脑的模型”，选择同一空间内自己登记的来源电脑 B，再选择 B 的 Provider／模型。电脑列表只读取基本信息，展开 B 后才加载其模型目录。来源电脑使用名称展示，绑定保存系统生成的固定 ID，改名和正常重连不会换成另一台电脑。

Agent、文件及工具运行在 A；模型请求由 A 经 Server 转到 B，B 使用自己的配置和 Key 调用上游，流式结果原路返回 A。Key 不复制到 A，也不用于在 Server 直接调用上游。这个入口只存在于 Server 管理的远程电脑会话，不能保存为独立客户端或托管工作区的默认模型。

首次指定来源时，需要拥有 B 并具有此会话的配置权限。其他获准提交的协作者或服务账号可以使用已经绑定的模型，来源所有者仍需保有会话配置权限。每次请求、重试和执行期间继续复核授权。来源离线、暂停、凭据撤销或 Provider／Key 更改会使调用不可用或中止；不会自动换用 A 上的同名 Provider，也不会在断线后重放在途模型请求。两台电脑连接不同 Server 时使用[集群通道](server-cluster.md)。

“我的模型 → 用量 → 设备本地 → 跨电脑模型调用”按需加载调用记录，区分执行电脑、来源电脑、提交者和模型所有者。计数来自来源电脑报告，与平台预算分开；丢失的计数保持未报告，详见[设备用量](device-provider-usage.md)。

## 模型 Provider

Provider 是一组可以复用的模型连接设置。添加一次后，多个会话可以选择其中的模型。

1. 本机打开“设置 → 模型”，Server 打开“我的模型”并明确选择账号或设备来源，点击“添加 Provider”，填写标识、显示名称、服务地址和协议。
2. 服务需要鉴权时，直接在同一卡片填写 API Key。保存后输入框会清空；再次编辑时留空表示保留原 Key，填写新值表示替换。
3. 手动加入模型，或使用“获取可用模型”。模型发现由执行端发起，浏览器不会取得已保存的 Key。
4. 设置上下文窗口、最大输出 token，以及该模型支持的推理强度。
5. 保存后，在输入框下方或“当前会话模型”中选择 Provider、模型和推理强度。

完整字段示例见[首次配置 Provider](getting-started.md#3-配置-provider模型和-api-key)。托管会话的模型选择器同时提供获准的平台模型和会话所有者已授权的账号 Provider；个人 API Key 继续按账号隔离，不因统一入口扩大可见范围。

使用 DeepSeek 官方 Responses 接口时，在 Provider 的“API 协议”中选择 **DeepSeek Responses**。该选项会接收服务返回的完整思考正文，并在工具调用后的请求中带回所需历史；OpenAI Responses 保持标准推理摘要行为。协议按接口实际实现选择，不会根据服务地址自动更换。

模型返回的思考内容可以在对话中点击“思考”展开或收起；紧凑显示下，先展开本轮过程。只显示实际返回并保存的内容，切换协议不会补出旧记录中缺失的思考正文。

OpenAI Responses 在配置了非 `none` 的实际推理强度时，同时请求 `reasoning.summary: "auto"`，用于显示模型支持的推理摘要；未配置实际强度或明确关闭时不额外请求摘要。摘要与推理 token 用量是两回事：有推理用量但没有摘要文本时，不生成虚假的“思考”内容。上游是否支持并返回摘要仍以其实际响应为准，旧会话不会补出未返回的摘要。参见 [OpenAI 推理摘要说明](https://developers.openai.com/api/docs/guides/reasoning#reasoning-summaries)。

模型的上下文窗口、最大输出 token 和推理配置分别取值，优先级为：**手动指定 → 上游明确提供 → Provider 默认值**。账号模型、平台上游和客户端一致。手动添加时没有上游数据，默认使用 Provider；获取模型时保留上游容量，不会因为返回容量就把没有返回的推理配置清空。编辑器逐项显示“自动 · 上游提供”“自动 · Provider 默认”或“自定义”，每一项可单独恢复自动。

上游目录中的 `reasoning: false` 表示明确关闭；缺失、`null` 或只有 `true` 而没有档位映射时，不假定具体档位，继续使用 Provider 配置。识别到包含 `default_effort` 和 `efforts` 的完整推理配置时使用上游配置。用户也可单独选择“未启用”关闭该模型的推理配置，这与自动继承不同。

再次“获取可用模型”可勾选已有条目更新其上游信息；现有名称和手动值不变，只有保存 Provider 后生效。取消编辑不改持久配置。已有完整覆盖项的原值保留为手动设置，不猜测它来自手动输入还是旧版自动发现；若旧覆盖项没有推理配置，在该模型中将推理来源切到“自动”即可继承，无需改动独立容量。若服务采用自己的档位名称，可把统一档位映射到端点值，例如将 `high` 映射为 `ultra`。超时和重试仍在 Provider 中设置。

模型发现弹窗可按名称或模型 ID 搜索，忽略大小写和首尾空格。筛选不会清除其他结果的勾选，“全选结果／取消结果选择”只影响当前结果；“已选”数量包含隐藏的勾选项，应用时采用全部已选模型。搜索只筛选本次取得的目录，不重复请求上游。客户端、账号自有和平台 Provider 共用此交互。

在电脑上新增或修改 Provider 后，可以在 Server“设备本地”点击上方刷新，同时重新读取电脑和已展开的模型目录；收起的电脑下次展开时也会读取新配置。Provider 区域的“刷新 Provider”只刷新当前来源，普通刷新保留未保存的编辑，不更换聊天模型。这里读取的是已保存的 Provider 配置，不等于再次向供应商“获取可用模型”。本机“Server 模型连接”卡的授权数量只计算 Server 授予的模型，不包含下方本机自有 Provider。

配置使用 `settings.mode: "automatic"` 分开保存 `upstream` 与 `overrides`；未指定的覆盖字段参与自动取值，推理的 `{ "mode": "disabled" }` 明确关闭，`{ "mode": "enabled", "configuration": { ... } }` 保存具体档位。已有 `inherit`／`override` 配置的原含义不变，编辑保存时转为等价逐项设置。当前执行器协议为 47，连接的 Server、Node 与 Worker 需要同步更新。

上下文窗口决定占用比例和自动压缩时机。默认达到估算窗口的 80% 时自动压缩；模型没有声明窗口时，不会使用一个猜测的固定阈值，仍可输入 `/compact` 手动压缩。最大输出 token 和推理设置会用于实际模型请求。

新会话可以使用默认模型；修改新会话默认值不会更换已有会话的选择。会话也可以使用 Agent 预设中的 `profile_default` 模型。临时 OpenAI-compatible 路由及通过环境变量引用 Key 适合单次调试，长期使用建议保存为命名 Provider。

正在被会话引用的 Provider 或模型不能直接删除。允许保存的连接设置更新，会在相关会话下一轮生效。设备本地 Provider 由所在电脑或 VPS 的 `ternilo` 直连上游；接入电脑选择账号自有或平台授权模型时，由 Server 代为请求上游，文件和工具仍在所选电脑执行，不把上游 Key 下发给 Node。托管任务也由 Server 请求模型，Worker 不取得模型 API Key。配置究竟保存在哪里，见[设置目标与数据归属](settings.md#设置目标与数据归属)。

托管会话的“更多会话操作 → 任务用量上限”设置每次新任务可使用的 token 总量，包括输入、输出和多次模型调用。默认上限为 32,768 tokens；图片、较大输出或较长任务可能需要提高。提交前若预留不足，页面会提示所需最低额度并保留草稿和附件；提高上限后可以重新提交。这个最低值是提交前估算，历史上下文、工具结果和重试仍可能需要更多额度。

任务提交时预留额度，结束后释放未使用部分；用量未确认的部分保留待核对。修改会话上限只影响后续提交，已经排队或运行的任务保持原上限。个人模型授权和空间额度仍然生效，提高任务上限不会增加可用余额。这个设置仅用于托管任务，本机和自己的电脑不受它控制。

## Gemini 与 Claude 原生协议

添加 Provider 时可以选择 `Google Gemini` 或 `Claude · Anthropic Messages`。账号、平台和本地共用这个入口；不是 OpenAI 兼容模式。Gemini 默认基础地址为 `https://generativelanguage.googleapis.com/v1beta`，Claude 为 `https://api.anthropic.com/v1`，填写相应服务的 API Key 后即可获取模型。切换协议会更新未自定义的默认地址，已填写的中转地址不会被覆盖。

两种协议支持文本、图像输入、流式回答、函数工具和思考历史。Gemini 使用原生 `generateContent` / `streamGenerateContent`；Claude 使用 Anthropic Messages。工具循环和刷新后的下一轮请求保留原始思考签名，不把签名当作可见回答。Gemini 附件由 Ternilo 解析为 base64 图像；原生模式不提供 Vertex AI/OAuth、Bedrock、实时语音、图像生成或服务商内置搜索工具。

推理强度依实际模型能力配置，不要将所有统一档位全部勾选。Gemini 的实际值可以是 `minimal`、`low`、`medium`、`high`，或思考 token 预算（`-1` 自动，`0` 关闭）。Claude 新模型使用 `low`、`medium`、`high`、`xhigh`、`max` 等自适应强度；旧模型使用不少于 `1024` 且低于最大输出 token 的预算值；`none` 关闭。空映射只是不发送参数，不会关闭服务商默认思考。发现接口没有明确提供的档位继续继承手动 Provider 配置，不按模型名称猜测。

Server 接入密钥也可用于这两种原生协议：Claude 使用 `/v1/messages` 与 `x-api-key`；Gemini 使用 `/v1/models/{公开模型ID}:generateContent` 或 `:streamGenerateContent?alt=sse` 与 `x-goog-api-key`。基础地址仍填 Server 的 `/v1`，预算、授权撤销及设备范围保持有效，不在 URL 中传递密钥。

当前执行器协议为 **47**，包含原生模型签名历史、队列编辑版本条件与归档恢复。Server、Node 和 Worker 需要同步更新，旧协议会在握手阶段被明确拒绝；不要仅升级网页而保留旧客户端。

## 长时间思考与复制

Provider 的“请求与重试 → 单次请求总时限（ms）”包含等待、思考和输出，不只是等待首个字的时间。新建 Provider 默认 600000 ms（10 分钟）；已有 Provider 保留自己设置的值。模型仍在输出时达到时限也会结束该次请求。长任务可以调大数值，或设为 `0` 关闭 Ternilo 这一侧的总时限；仍可随时点击停止。这个设置不会取消模型服务端或中间代理自身的限制。

Ternilo 没有单独的思考时钟。选中命名 Provider（例如 `ds`）时，以该 Provider 的请求设置为准；只有使用 Agent 预设中直接配置的远程模型时，才使用模型插件自身的 `timeout_ms`。两处都支持 `0`，不要将工具执行超时或子代理等待时限与模型请求混淆。页面保存影响后续请求；直接修改数据目录下的 `providers.json` 则需重启。

发生超时后，已经收到的消息和思考仍保留。程序不会自动重跑已经开始输出的请求；检查已有结果后，可以发送后续消息继续。停止或超时也不会撤销已经执行的文件修改。

消息、代码、命令、路径和账号 ID 共用复制行为。浏览器不提供剪贴板 API 或拒绝该 API 时，页面会尝试通过选中文本复制；仍被浏览器限制时保留失败提示和可选择的原文。

“连接 Server”可使用平台授权及明确授权的账号自有模型，包含 OpenAI Chat、OpenAI Responses、DeepSeek Responses、Gemini 和 Anthropic Messages。来源按授权与协议独立保留，Server 凭据不会下发上游 API Key；此连接仅授权模型访问，无需登记远程控制电脑。

### Claude 官方模型目录

使用 Anthropic 官方 API 时，协议选择 `anthropic-messages`，API 地址填 `https://api.anthropic.com/v1`。模型发现请求为 `GET /v1/models`，使用 `x-api-key` 和 `anthropic-version: 2023-06-01`，不使用 Chat Completions 的 Bearer 鉴权。API 地址是版本入口，不是 `/messages` 或 `/models` 的完整路径。

程序使用 `has_more`、`last_id` 与 `after_id` 读取后续页，读取 `display_name`、`max_input_tokens`、`max_tokens` 和实际返回的能力声明。未返回的推理档位继续沿用明确配置，不猜测支持范围。接口依据：[Anthropic 官方 Models API](https://platform.claude.com/docs/en/api/models/list)。
