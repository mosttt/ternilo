# 产品与能力边界

Ternilo 面向需要 AI 实际操作文件和工具的用户，支持个人多台电脑／VPS、多人协作和模型授权。托管执行为可选组件；跨 Server 故障转移和经过完整压力测试的平台容量尚不在可承诺范围。

## 单用户和多用户

区别是“谁可以使用和协作”，不取决于机器在家中还是云端。

| 能力 | 单用户模式 | 多用户模式 |
|---|---|---|
| 使用本地电脑、家用服务器和 VPS | 支持多台 | 支持多台，按归属和授权访问 |
| 账号 | 实例所有者自己使用 | 独立账号和个人空间，可加入团队 |
| 工作区与会话共享 | 自己跨设备继续工作 | 按成员或团队权限组授权 |
| 平台模型与托管 Worker | 按需要启用 | 按需要启用并分配使用权限 |
| 数据库 | SQLite 或 PostgreSQL | SQLite 或 PostgreSQL |

访问模式在软件中切换，数据库、监听和密钥在部署时配置。切换模式不会更换数据库、删除账号或搬动文件。单用户模式不要求创建团队，单机使用 `ternilo` 也不需要 Server。

## 资源分别是什么

| 名称 | 作用 |
|---|---|
| 账号 | 以用户名和系统 ID 识别用户，邮箱用于账号信息；自动取得个人空间 |
| 个人／团队空间 | 组织资源、成员和管理范围；个人空间不添加团队成员 |
| 项目 | 归类同一空间中的相关工作区，不自动创建或同步目录 |
| 工作区 | 绑定执行机器和实际工作目录，或者平台托管存储 |
| 会话 | 在工作区中的对话、任务、历史和配置 |
| 工作目录 | Agent 实际读写的文件夹，与保存配置、凭据和日志的数据目录分开 |

一个项目可以包含笔记本和 VPS 上的不同工作区。新会话或历史分叉不会自动复制文件。本机／Node 按可信输入作者协调目录，同一用户可以并行，不同用户的重叠目录仍互斥；托管 Worker 继续使用执行家族和退出证明。同用户并行不会自动解决同时编辑同一文件的冲突。空间、项目和会话组织信息不会自动授予模型额度。

## 共享分三个维度

| 分享什么 | 得到什么 | 当前边界 |
|---|---|---|
| 模型访问权 | 在自己的执行环境中调用获准模型，使用指定额度 | 账号／设备／平台模型、受限 Key、独立客户端模型授权和可信 Node 协作已实现；设备间转发本地模型及更广泛的托管协作者委托尚未实现 |
| 已配置的执行环境 | 在指定机器上使用已有工具、文件和允许使用的模型 | 已有工作区／会话共享和 Worker 隔离执行；通用环境目录、执行池与完整组合授权仍需完善 |
| 项目和工作成果 | 查看或协作已有内容，按权限提交、停止、配置或分叉 | 工作区／会话授权、当前管理者主动启用的项目继承和同团队管理权交接已实现；文件／执行身份迁移尚未提供 |

前两种分别提供“模型能力”和“模型加机器算力”，都保留。第三种解决共同处理已有工作的问题。它们可以组合，但一份权限不会自动变成另一份：加入团队不自动获得模型额度，能使用执行环境不自动得到独立模型 Key，分享一个会话也不会开放整个项目。

平台模型组用来批量分配模型授权；团队权限组用来批量分配团队资源权限。两者的成员范围和用途不同。资源所有者、实际提交者和模型预算来源分别记录，不能因为共享而把操作都算成机器所有者发起。

## 页面怎么分工

用户的主要入口是工作台：选工作位置、交代任务、查看结果。机器、模型、预设和权限在相关位置清楚显示，不以隐藏选择来减少功能。

“用户设置”管理自己的偏好、连接和配置；“我的模型”管理本人得到的模型授权与接入方式。“团队管理”处理成员和协作权限。“平台管理”处理账号、平台模型、Worker、平台策略和审计。管理员也通过普通工作台做任务，管理权限不自动授予私人资源或模型密钥的读取权。

多人共享会话时，各自保留输入框与草稿，提交进入会话队列。自己的消息显示“你”，其他人显示用户名，点击身份栏查看 ID。输出通过会话事件同步，输入框不按人独占；文件写入由执行层协调。执行范围内的父子 Agent 仍须分工，目录协调不会自动解决它们之间的内容冲突。

## 三个部署程序

- `ternilo` 在自己的机器上运行任务，保存本机配置、会话和附件。网页及管理接口只监听回环，远程使用时主动连接 Server。
- `ternilo-server` 提供远程入口、账号、资源权限、机器路由、模型服务和账本。它可以独立提供模型访问，无需 Worker。
- `ternilo-worker` 是可选的托管执行服务，为任务启动隔离环境；不连接数据库，不持有 Server 主密钥或上游模型 Key。

桌面应用连接本地服务，Node 是 `ternilo` 接入 Server 后的角色。模块拆分不意味着必须部署更多进程。部署选择见[部署指南](deployment.md)，数据归属见[设置说明](settings.md)。

## 能力边界

下表区分现有功能与能力限制，不代表后续版本的交付承诺。

| 范围 | 当前可用 | 当前限制 |
|---|---|---|
| 多机器工作 | 本机、Server 接入、多机器目录选择、文件任务和离线缓存历史 | 历史与归档按事件游标分页；离线历史仅包含已同步记录，Cloud 派生统计仍需回放事件 |
| 模型来源 | 统一模型中心；账号／设备／平台来源并列选择；独立客户端授权；子任务／Workflow／调度保留原操作者 | 设备间本地模型转发、协作者在他人托管会话中新增自己的模型委托 |
| 模型协议 | OpenAI Chat、标准 OpenAI Responses、独立 DeepSeek Responses、原生 Gemini／Claude Messages | 供应商云端搜索与其他托管工具、Vertex AI／Bedrock |
| 账号 | 用户名、邮箱、系统 ID、开放／审核／邀请注册策略、封禁与解封、移除；实例设置中的 OAuth 2.0／OIDC 与 Turnstile；原生登录会话管理与本机运维密码恢复 | OIDC 不等于任意 OAuth 服务商适配；尚无邮箱验证、自助密码找回、原生多因素认证和服务账号 |
| 协作 | 团队、权限组、工作区／会话共享、当前管理者主动启用的项目继承、同团队管理权交接、项目改名与空项目删除、真实提交者、独立草稿、队列编辑版本冲突提示 | 文件／执行身份迁移和远程协作者设备模型授权尚未提供 |
| 用量 | 逐次请求账本、授权预算、受限 Key、模型授权设备的独立月额度／并发／有效期／每分钟请求限制、可信迟到用量结算、管理员未知用量核对、自有电脑 Provider 尝试报告 | 账号／平台分层速率与额度、设备报告持久汇总与导出 |
| 执行 | 本机目录协调、后台服务、Worker 容量与同机故障恢复基础 | Work／Worker 的执行池、每工作区存储、跨主机交接及完整隔离恢复仍为预留范围 |
| 扩展 | 签名 Rhai／WASM、能力与资源上限、Rhai／WASM 工具运行中取消 | 宿主同步 I/O 与 Hook 的取消边界仍受各自生命周期限制，不承诺立即中断或副作用回滚 |
| 部署规模 | 一个 Server 的 SQLite／PostgreSQL 业务流程；跨实例权限通知；Node 转发与事件补读通过实际 TCP 和受限 PostgreSQL 合同 | 跨实例真实浏览器联调、文件存储故障转移与正式容量结论 |

持续目标支持设置后立即执行、未完成自动续轮、阻塞退出与手动停止／显式继续。持久历史和中断收尾不等于崩溃后自动重做已执行过的任务。归档列表、恢复和恢复前只读历史预览已提供，恢复不会自动启动任务；[日志尾行离线修复](session-log-repair.md)已提供；MCP 支持工具变化通知和可选的有界重连，失败调用不重放。额外搜索服务和更广泛的外部代理适配仍需单独实现。CLI／RPC／ACP／SDK 的现有接口与限制见[自动化说明](automation.md)。

PWA 可安装并缓存应用外壳，离线时不能执行远程任务。Linux、macOS 和 Windows 各有隔离实现；Windows 不承诺完整读取隔离。源码中存在实现不代表对应系统安装包、签名和实机验收已经完成，详见[安全模型](security.md)。

`ternilo` 与 `ternilo-server` 不依赖 Worker 即可完成本机和远程电脑上的任务。现有 Worker 的使用及恢复边界见[托管 Worker](worker.md)；预留设计不等于完整托管执行产品已经交付。
